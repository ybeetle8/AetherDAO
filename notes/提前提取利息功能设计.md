# 质押与解质押流程分析及提前提取利息功能设计

## 一、当前质押流程分析

### 1.1 质押流程 (stake)

**入口函数**: `stake(uint160 _amount, uint8 _stakeIndex)`

**流程步骤**:

1. **参数验证** (`_validateStakeParameters`)
   - 检查金额 >= 100 USDT (MIN_STAKE_AMOUNT)
   - 检查金额 <= 当前最大质押限额 (动态计算)
   - 检查质押索引 <= 4 (0=7天, 1=30天, 2=90天, 3=180天, 4=365天)
   - 检查用户总质押额 + 新质押额 <= 10,000 USDT (MAX_USER_TOTAL_STAKE)

2. **7天质押限制检查**
   - 如果是7天质押 (stakeIndex == 0), 检查用户是否已使用过
   - 每个用户只能使用一次7天质押

3. **资金处理** (`_swapAndAddLiquidity`)
   - 从用户转入 USDT 到合约
   - 将 50% USDT 兑换成 AE 代币
   - 将剩余 50% USDT + 兑换得到的 AE 添加到流动性池
   - 流动性 LP 代币销毁 (发送到 address(0))

4. **创建质押记录** (`_mintStakeRecord`)
   - 检查用户是否已绑定推荐人 (必须先绑定)
   - 记录网络总供应量快照 (t_supply)
   - 创建用户质押记录:
     - stakeTime: 质押时间戳
     - amount: 质押本金
     - status: false (未提取)
     - stakeIndex: 质押期限索引
   - 更新推荐链上所有上级的团队业绩 (teamTotalInvestValue)
   - 铸造 sAE 代币 (记账代币,不可转账)

### 1.2 利息计算机制

**计算函数**: `_calculateStakeReward(Record storage stakeRecord)`

**计算公式**: 复利计算
```
最终金额 = 本金 × (1 + 日利率)^天数
```

**利率配置** (主网):
- 7天: 0.6% 日利率 (1.006)
- 30天: 0.9% 日利率 (1.009)
- 90天: 1.1% 日利率 (1.011)
- 180天: 1.5% 日利率 (1.015)
- 365天: 2.0% 日利率 (1.020)

**计算逻辑**:
1. 计算已质押天数 = min(当前时间 - 质押时间, 质押期限)
2. 计算复利期数 = 已质押天数 / 1天
3. 最终金额 = 本金 × (日利率)^复利期数

**重要**: 利息计算有上限,最多计算到质押期限结束,不会超额计算。

## 二、当前解质押流程分析

### 2.1 解质押流程 (unstake)

**入口函数**: `unstake(uint256 stakeIndex)`

**流程步骤**:

1. **销毁质押记录** (`_burn`)
   - 检查质押期限是否已到期
   - 检查是否已经提取过
   - 计算总奖励 (本金 + 利息)
   - 标记质押记录为已提取 (status = true)
   - 销毁 sAE 代币

2. **兑换 AE 为 USDT** (`_swapAEForReward`)
   - 使用合约持有的 AE 代币兑换成 USDT
   - 目标兑换金额 = 计算出的总奖励
   - 实际获得的 USDT 可能与计算值有偏差 (取决于池子价格)

3. **计算利息**
   ```
   利息 = 实际获得的 USDT - 本金
   ```

4. **分配奖励**

   **4.1 好友奖励** (`_distributeFriendReward`)
   - 计算: 利息 × 5%
   - 接收方: **教育基金地址** (educationFundAddress)
   - 注: 原来是给直推人,现已改为教育基金

   **4.2 团队奖励** (`_distributeTeamReward`)
   - 总池: 利息 × 35%
   - 分配规则: **严格差额分配制**

   **团队奖励详细规则**:

   用户等级由两个条件共同决定 (取较低者):
   - 团队业绩 (Team KPI): 直推和间推所有下级的质押总额
   - 个人质押额 (Personal Stake): 用户自己的当前质押价值

   **等级阈值**:

   | 等级 | 团队业绩要求 | 个人质押要求 | 奖励比例 |
   |------|-------------|-------------|---------|
   | V1   | 3,000 USDT  | 100 USDT    | 3%      |
   | V2   | 10,000      | 300         | 7%      |
   | V3   | 30,000      | 600         | 11%     |
   | V4   | 100,000     | 1,000       | 15%     |
   | V5   | 300,000     | 3,000       | 19%     |
   | V6   | 1,000,000   | 6,000       | 23%     |
   | V7   | 3,000,000   | 10,000      | 27%     |
   | V8   | 10,000,000  | 15,000      | 31%     |
   | V9   | 30,000,000  | 20,000      | 35%     |

   **差额分配示例**:
   - 用户A解质押,利息1000 USDT
   - 推荐链: A -> B(V2) -> C(V5) -> D(V3) -> E(V1)
   - 分配:
     - E(V1): 1000 × 3% = 30 USDT
     - D(V3): 1000 × (11% - 3%) = 80 USDT (差额)
     - C(V5): 1000 × (19% - 11%) = 80 USDT (差额)
     - B(V2): 0 USDT (V2=7% < V5=19%,已被上级占用)
   - 总分配: 190 USDT
   - 剩余: 1000 × 35% - 190 = 160 USDT -> 发送到 rootAddress

   **4.3 赎回手续费** (1%)
   - 计算: 用户应得金额 × 1%
   - 接收方: feeRecipient
   - 从 AE 池中额外兑换 USDT 支付

5. **更新团队业绩**
   - 从推荐链上所有上级的 teamTotalInvestValue 中减去本金

6. **转账给用户**
   ```
   用户实得 = 实际获得的 USDT - 好友奖励(5%) - 团队奖励(35%) - 赎回手续费(1%)
   ```

7. **回收 AE 代币**
   - 将使用的 AE 代币发送到 AE 合约的 recycle 函数

8. **记录提取历史**
   - 保存完整的提取记录到 `_userWithdrawalHistory`

## 三、提前提取利息功能设计

### 3.1 功能需求

**核心需求**:
- 允许用户在质押期限到期前提取已产生的利息
- 只提取利息,不提取本金
- 可以多次提取
- 提取规则与到期解质押相同 (扣除好友奖励、团队奖励、手续费)

### 3.2 设计方案

#### 3.2.1 新增状态变量

```solidity
// 记录每个质押记录已提取的利息总额
mapping(address => mapping(uint256 => uint256)) public withdrawnInterest;
```

#### 3.2.2 新增函数

```solidity
/**
 * @notice 提前提取质押利息 (不提取本金)
 * @param stakeIndex 质押记录索引
 * @return interestWithdrawn 实际提取的利息金额 (扣除各项费用前)
 */
function withdrawInterest(uint256 stakeIndex) external onlyEOA returns (uint256 interestWithdrawn);
```

#### 3.2.3 提取流程

1. **验证条件**
   - 检查质押记录是否存在
   - 检查质押记录是否已完全提取 (status == false)
   - 计算当前可提取利息

2. **计算可提取利息**
   ```
   当前总价值 = _calculateStakeReward(stakeRecord)
   已产生利息 = 当前总价值 - 本金
   已提取利息 = withdrawnInterest[user][stakeIndex]
   可提取利息 = 已产生利息 - 已提取利息
   ```

3. **检查可提取金额**
   - 如果可提取利息 <= 0, 则 revert

4. **兑换 AE 为 USDT**
   - 与 unstake 相同,使用 `_swapAEForReward`
   - 目标金额 = 可提取利息

5. **分配奖励** (与 unstake 相同)
   - 好友奖励: 5% -> 教育基金
   - 团队奖励: 35% -> 推荐链差额分配
   - 赎回手续费: 1% -> feeRecipient

6. **更新状态**
   - 更新 `withdrawnInterest[user][stakeIndex] += 可提取利息`
   - **不修改** 质押记录的 status
   - **不销毁** sAE 代币
   - **不更新** 团队业绩 (因为本金还在)

7. **转账给用户**
   ```
   用户实得 = 实际获得的 USDT - 好友奖励(5%) - 团队奖励(35%) - 赎回手续费(1%)
   ```

8. **记录提取历史**
   - 新增事件: `InterestWithdrawn`
   - 可选: 在 WithdrawalRecord 中添加类型标识 (全额提取 vs 利息提取)

#### 3.2.4 新增事件

```solidity
/**
 * @notice 提前提取利息事件
 * @param user 用户地址
 * @param stakeIndex 质押记录索引
 * @param interestAmount 提取的利息金额 (扣费前)
 * @param usdtReceived 实际兑换得到的 USDT
 * @param aeTokensUsed 使用的 AE 代币数量
 * @param referralFee 好友奖励
 * @param teamFee 团队奖励
 * @param userPayout 用户实得
 * @param timestamp 提取时间
 */
event InterestWithdrawn(
    address indexed user,
    uint256 indexed stakeIndex,
    uint256 interestAmount,
    uint256 usdtReceived,
    uint256 aeTokensUsed,
    uint256 referralFee,
    uint256 teamFee,
    uint256 userPayout,
    uint40 timestamp
);
```

#### 3.2.5 新增查询函数

```solidity
/**
 * @notice 查询指定质押记录的可提取利息
 * @param user 用户地址
 * @param stakeIndex 质押记录索引
 * @return availableInterest 可提取利息金额
 */
function getAvailableInterest(address user, uint256 stakeIndex)
    external
    view
    returns (uint256 availableInterest);

/**
 * @notice 查询指定质押记录已提取的利息
 * @param user 用户地址
 * @param stakeIndex 质押记录索引
 * @return withdrawn 已提取利息金额
 */
function getWithdrawnInterest(address user, uint256 stakeIndex)
    external
    view
    returns (uint256 withdrawn);
```

## 四、关键差异对比

| 项目 | unstake (到期解质押) | withdrawInterest (提前提取利息) |
|------|---------------------|-------------------------------|
| 提取内容 | 本金 + 全部利息 | 仅利息 (可多次) |
| 期限要求 | 必须到期 | 无要求,随时可提 |
| 质押记录状态 | 标记为已提取 (status=true) | 保持未提取 (status=false) |
| sAE 代币 | 销毁 | 保留 |
| 团队业绩 | 减少 (扣除本金) | 不变 |
| 好友奖励 | 5% -> 教育基金 | 5% -> 教育基金 |
| 团队奖励 | 35% 差额分配 | 35% 差额分配 |
| 赎回手续费 | 1% | 1% |
| 可重复操作 | 否 (一次性) | 是 (多次) |

## 五、实现注意事项

### 5.1 安全考虑

1. **重入攻击防护**
   - 使用 Checks-Effects-Interactions 模式
   - 先更新状态 (withdrawnInterest),再转账

2. **精度问题**
   - 使用 UD60x18 库进行高精度计算
   - 注意 USDT 和 AE 的精度差异

3. **最小提取金额**
   - 建议设置最小提取金额 (如 1 USDT)
   - 避免频繁小额提取导致的 gas 浪费

### 5.2 经济模型影响

1. **流动性影响**
   - 提前提取会增加 AE 代币的卖出压力
   - 需要确保 AE 池有足够流动性

2. **用户行为**
   - 用户可能频繁提取利息,减少复利效果
   - 但本金仍在质押,团队业绩不受影响

3. **手续费收入**
   - 每次提取都收取 1% 手续费
   - 多次提取会增加协议收入

### 5.3 Gas 优化

1. **批量提取**
   - 可考虑添加批量提取多个质押记录的利息
   - 减少用户 gas 成本

2. **存储优化**
   - withdrawnInterest 使用嵌套 mapping
   - 考虑是否需要记录每次提取的详细历史

## 八、总结

提前提取利息功能是对现有质押系统的增强,主要特点:

**优点**:
- 提高资金灵活性,用户可以随时提取收益
- 本金仍在质押,维持团队业绩和等级
- 增加协议手续费收入 (多次提取)
- 不影响现有 unstake 逻辑

**风险**:
- 增加 AE 代币卖压
- 用户可能频繁提取,增加合约调用次数
- 需要确保 AE 池流动性充足

**建议**:
- 设置最小提取金额 (如 10 USDT)
- 考虑添加提取冷却时间 (如 24 小时)
- 监控 AE 池流动性,必要时调整参数
