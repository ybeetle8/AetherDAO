# 已领取质押收益与复利计算机制分析

## 一、核心结论

**已领取的质押收益不会参与复利计算。** 复利仅基于初始质押本金（`stakeRecord.amount`）进行计算，已提取的利息通过 `withdrawnInterest` 映射进行追踪和扣除，防止重复领取。系统中不存在自动复投或手动复投机制。

---

## 二、复利计算公式

**代码位置：** `contracts/AE-Staking/src/abstract/StakingBase.sol:1555-1584`

```solidity
function _calculateStakeReward(
    IStaking.Record storage stakeRecord
) private view returns (uint256 currentReward) {
    UD60x18 principalAmount = ud(stakeRecord.amount);       // 始终使用初始本金
    uint40 stakeStartTime = stakeRecord.stakeTime;
    uint40 stakingDuration;

    unchecked {
        stakingDuration = uint40(block.timestamp) - stakeStartTime;
    }

    stakingDuration = _min40(
        stakingDuration,
        uint40(getStakePeriod(stakeRecord.stakeIndex))
    );

    if (stakingDuration == 0) {
        currentReward = UD60x18.unwrap(principalAmount);
    } else {
        UD60x18 baseInterestRate = ud(rates[stakeRecord.stakeIndex]);
        uint256 compoundPeriods = stakingDuration / getCompoundTimeUnit();

        UD60x18 compoundedAmount = principalAmount.mul(
            baseInterestRate.powu(compoundPeriods)       // 复利：本金 × 日利率^天数
        );
        currentReward = UD60x18.unwrap(compoundedAmount);
    }
}
```

**数学公式：**

```
currentReward = principal × (dailyRate) ^ compoundPeriods
```

关键点：
- `principal` = `stakeRecord.amount`，即质押时写入的初始金额，**永远不会变更**
- `dailyRate` = 各档位对应的日利率（见下表）
- `compoundPeriods` = 质押时长（秒）/ 86400（一天的秒数）
- 使用 PRBMath 库的 `powu()` 实现高精度定点数幂运算

**各档位日利率（主网）：** `contracts/AE-Staking/src/mainnet/Staking.sol:28-46`

| 档位 | 日利率 | 周期 | 理论总收益率 |
|------|--------|------|-------------|
| 7天  | 1.006 (0.6%/天) | 7天  | ≈ 4.28% |
| 30天 | 1.009 (0.9%/天) | 30天 | ≈ 30.89% |
| 90天 | 1.011 (1.1%/天) | 90天 | ≈ 167.2% |
| 180天| 1.015 (1.5%/天) | 180天| ≈ 1,371% |
| 365天| 1.020 (2.0%/天) | 365天| ≈ 137,641% |

**复利计时单位：** `Staking.sol:112-114`，主网为 `1 days`（86400 秒）。

## 三、已领取收益的追踪机制

### 3.1 存储结构

**代码位置：** `StakingBase.sol:164-166`

```solidity
// Maps user address => stake index => total interest withdrawn
mapping(address => mapping(uint256 => uint256)) public withdrawnInterest;
```

每个用户的每笔质押记录，都独立追踪已提取的利息总额。

### 3.2 提取利息流程（withdrawInterest）

**代码位置：** `StakingBase.sol:385-480`

```
用户调用 withdrawInterest(stakeIndex)
    │
    ▼
1. 校验：质押记录存在且未赎回
    │
    ▼
2. 计算总当前价值：totalCurrentValue = _calculateStakeReward(stakeRecord)
   （使用复利公式，基于初始本金计算）
    │
    ▼
3. 计算总利息：totalInterest = totalCurrentValue - principalAmount
    │
    ▼
4. 计算可提取利息：availableInterest = totalInterest - alreadyWithdrawn
   （扣除已经提取过的利息）
    │
    ▼
5. 更新已提取记录：withdrawnInterest[user][stakeIndex] += availableInterest
    │
    ▼
6. 将 AE 兑换为 USDX：_swapAEForReward(availableInterest)
    │
    ▼
7. 扣除费用（教育基金5% + 团队奖励 + 赎回手续费5%）
    │
    ▼
8. 将 USDX 转给用户
```

**核心代码：** `StakingBase.sol:396-412`

```solidity
// 计算总当前价值和利息
uint256 totalCurrentValue = _calculateStakeReward(stakeRecord);
uint256 principalAmount = stakeRecord.amount;

// 可提取利息 = 总利息 - 已提取
uint256 totalInterest = totalCurrentValue > principalAmount
    ? totalCurrentValue - principalAmount
    : 0;
uint256 alreadyWithdrawn = withdrawnInterest[user][stakeIndex];
uint256 availableInterest = totalInterest > alreadyWithdrawn
    ? totalInterest - alreadyWithdrawn
    : 0;

require(availableInterest > 0, "No interest available to withdraw");

// 更新已提取记录（先更新状态，再做外部调用 — CEI 模式）
withdrawnInterest[user][stakeIndex] = alreadyWithdrawn + availableInterest;
```

## 四、赎回时的防重复领取机制

**代码位置：** `StakingBase.sol:1272-1294`（`_burn` 函数）

当用户在质押到期后调用 `unstake()` 赎回时，合约会自动扣除之前已通过 `withdrawInterest` 提取的利息：

```solidity
function _burn(uint256 index) private returns (uint256 reward, uint256 amount) {
    // ...
    amount = user_record.amount;
    reward = _calculateStakeReward(user_record);    // 计算总收益（本金+复利）

    // [修复 C-02] 扣除已通过 withdrawInterest 提取的利息
    uint256 alreadyWithdrawn = withdrawnInterest[sender][index];
    if (alreadyWithdrawn > 0) {
        require(reward > alreadyWithdrawn, "Reward calculation error");
        reward -= alreadyWithdrawn;      // 总收益 - 已领取利息 = 剩余可领取
    }
    // ...
}
```

**执行逻辑：**

```
假设用户质押 1000 USDX，30天档位
│
├── 第15天调用 withdrawInterest
│   ├── totalCurrentValue = 1000 × 1.009^15 = 1143.96
│   ├── totalInterest = 1143.96 - 1000 = 143.96
│   ├── alreadyWithdrawn = 0
│   ├── availableInterest = 143.96
│   └── withdrawnInterest[user][idx] = 143.96
│
├── 第30天调用 unstake
│   ├── reward = _calculateStakeReward() = 1000 × 1.009^30 = 1308.65
│   ├── alreadyWithdrawn = 143.96
│   └── reward = 1308.65 - 143.96 = 1164.69（用于兑换 USDX）
│
└── 用户总共获得 = 143.96(第15天) + 1164.69(第30天) = 1308.65（等于完整复利）
```

## 五、为什么已领取收益不参与复利

### 5.1 本金不可变

`stakeRecord.amount` 在 `_mintStakeRecord` 时写入后**永远不会被修改**。没有任何函数会增加这个值。复利公式始终基于这个不变的初始本金计算。

### 5.2 没有复投/再质押机制

合约中不存在以下任何功能：
- `compound()` — 自动将利息加入本金
- `reinvest()` — 将收益重新质押
- `restake()` — 追加本金到已有质押

### 5.3 用户想要"复利效果"的唯一方式

用户必须手动操作：
1. 调用 `withdrawInterest()` 领取已有利息（获得 USDX）
2. 用获得的 USDX 调用 `stake()` 创建一条**全新的质押记录**
3. 新质押记录独立计算复利，与原质押记录无关

这意味着每条质押记录的复利计算是**完全独立**的，不存在跨记录的复利累积。

## 六、累计收益统计变量

**代码位置：** `StakingBase.sol:188-202`

这些变量仅做统计用途，**不参与任何复利计算**：

```solidity
// 用户累计质押收益 (unstake / withdrawInterest 的 userPayout 之和)
mapping(address => uint256) public totalClaimedStakingReward;

// 用户累计社区收益 (作为推荐人获得的团队奖励之和)
mapping(address => uint256) public totalClaimedCommunityReward;

// 用户累计已退还本金 (unstake 时退还的本金之和)
mapping(address => uint256) public totalPrincipalReturned;

// 用户累计已领取的净利息 (扣除教育基金+团队奖励+赎回手续费后的纯利息到账金额)
mapping(address => uint256) public totalClaimedNetInterest;
```

这些变量在 `unstake()` 和 `withdrawInterest()` 执行时被累加更新，但仅用于前端展示和统计查询。

## 七、总结

| 问题 | 答案 |
|------|------|
| 复利的计算基数是什么？ | 始终是 `stakeRecord.amount`（初始质押本金） |
| 已领取利息会增加计算基数吗？ | 不会，本金永远不变 |
| 已领取利息如何防止重复领取？ | 通过 `withdrawnInterest` 映射追踪，赎回时从总收益中扣除 |
| 有自动复投功能吗？ | 没有 |
| 用户如何实现"复利效果"？ | 手动领取利息后，用领取到的 USDX 创建新的质押记录 |
| 复利计算精度如何保证？ | 使用 PRBMath UD60x18 定点数库的 `powu()` 函数 |
| 各质押记录之间有关联吗？ | 完全独立，互不影响 |
