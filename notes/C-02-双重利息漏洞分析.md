# C-02: withdrawInterest + unstake 双重利息获取 — 详细分析与修复方案

## 1. 问题概述

| 项目 | 详情 |
|------|------|
| **严重等级** | Critical (严重) |
| **漏洞类型** | 经济逻辑漏洞 — 双重支付 |
| **影响范围** | 所有使用 `withdrawInterest` 后再 `unstake` 的用户 |
| **涉及函数** | `unstake()`, `withdrawInterest()`, `_burn()`, `_calculateStakeReward()` |
| **涉及文件** | `StakingBase.sol` |
| **关联问题** | H-02 (费用基数膨胀) 是本漏洞的附带问题 |

---

## 2. 根因分析

### 2.1 核心问题

`_burn()` 函数 (L1245-1275) 在计算 unstake 奖励时, 调用 `_calculateStakeReward()` 获得的是**从质押开始到当前时刻的全部复利总额**, 但**完全没有扣除用户已经通过 `withdrawInterest` 提取的利息部分**。

### 2.2 两个函数的利息计算对比

**`withdrawInterest()` (L368-459) — 正确的利息追踪:**

```solidity
uint256 totalCurrentValue = _calculateStakeReward(stakeRecord);  // 全部复利
uint256 totalInterest = totalCurrentValue - principalAmount;      // 总利息
uint256 alreadyWithdrawn = withdrawnInterest[user][stakeIndex];   // 已提取利息
uint256 availableInterest = totalInterest - alreadyWithdrawn;     // 可用利息 = 总利息 - 已提取

// 更新已提取记录
withdrawnInterest[user][stakeIndex] = alreadyWithdrawn + availableInterest;
```

这个函数正确维护了 `withdrawnInterest` 映射, 只发放**增量利息**。

**`_burn()` (L1245-1275) — 缺失扣除逻辑:**

```solidity
amount = user_record.amount;
reward = _calculateStakeReward(user_record);  // 全部复利总额, 包含本金!
// ↑ 这里没有任何代码读取或扣除 withdrawnInterest
user_record.status = true;
```

**`unstake()` (L286-357) — 基于未扣除的 reward 进行后续操作:**

```solidity
(uint256 calculatedReward, uint256 principalAmount) = _burn(stakeIndex);
// calculatedReward 包含了本金 + 全部利息 (含已提取部分)

(uint256 usdxReceived, uint256 aeTokensUsed) = _swapAEForReward(calculatedReward);
// ↑ 按全额 swap, 多 swap 出了已提取利息对应的 USDX

uint256 interestEarned = usdxReceived - principalAmount;
// ↑ 利息计算基数包含已提取部分, 导致 H-02 费用膨胀问题
```

### 2.3 数据流图

```
withdrawInterest (第89天):
┌─────────────────────────────────────────────────────┐
│ _calculateStakeReward() = 2677 USDX (本金+利息)      │
│ totalInterest = 2677 - 1000 = 1677 USDX             │
│ alreadyWithdrawn = 0                                 │
│ availableInterest = 1677 USDX  ← 发放给用户           │
│ withdrawnInterest[user][idx] = 1677                  │
└─────────────────────────────────────────────────────┘
                        ↓
unstake (第90天):
┌─────────────────────────────────────────────────────┐
│ _burn():                                             │
│   _calculateStakeReward() = 2697 USDX               │
│   reward = 2697  ← 未扣除 withdrawnInterest=1677!    │
│                                                      │
│ _swapAEForReward(2697):                              │
│   swap 出约 2697 USDX                                │
│                                                      │
│ interestEarned = 2697 - 1000 = 1697 USDX            │
│ 用户实际获得: 本金 + 1697 利息 (扣费前)                  │
└─────────────────────────────────────────────────────┘

用户总获利: 1677 + 1697 = 3374 USDX 利息
正常应得:          ~1697 USDX 利息
多获取:           ~1677 USDX (约 2 倍利息)
```

## 3. 数值模拟

### 3.1 90 天档位 (1.1% 日复利, 本金 1000 USDX)

复利公式: `reward = principal × (1.011)^days`

| 天数 | `_calculateStakeReward()` 返回值 | 总利息 |
|------|----------------------------------|--------|
| 第 1 天 | 1000 × 1.011¹ = 1011.00 | 11.00 |
| 第 30 天 | 1000 × 1.011³⁰ = 1388.07 | 388.07 |
| 第 60 天 | 1000 × 1.011⁶⁰ = 1926.75 | 926.75 |
| 第 89 天 | 1000 × 1.011⁸⁹ = 2660.05 | 1660.05 |
| 第 90 天 (到期) | 1000 × 1.011⁹⁰ = 2687.87 | 1687.87 |

**正常流程 (仅 unstake):**

```
第90天 unstake:
  用户获得: 2687.87 USDX (扣费前) = 本金 1000 + 利息 1687.87
```

**攻击流程 (withdrawInterest + unstake):**

```
第89天 withdrawInterest:
  totalInterest = 2660.05 - 1000 = 1660.05
  alreadyWithdrawn = 0
  availableInterest = 1660.05 USDX  → 发放给用户

第90天 unstake:
  _burn() 中 reward = 2687.87 (未扣除 1660.05!)
  _swapAEForReward(2687.87) → usdxReceived ≈ 2687.87
  interestEarned = 2687.87 - 1000 = 1687.87
  用户再获得: 2687.87 USDX (扣费前) = 本金 1000 + 利息 1687.87
```

| | 正常流程 | 攻击流程 | 多获取 |
|--|---------|---------|--------|
| withdrawInterest | 0 | 1660.05 | - |
| unstake (利息部分) | 1687.87 | 1687.87 | - |
| **利息合计** | **1687.87** | **3347.92** | **+1660.05 (+98.3%)** |

### 3.2 365 天档位 (2.0% 日复利, 本金 1000 USDX)

```
第364天: reward = 1000 × 1.02^364 = 1,377,408 USDX  (利息: 1,376,408)
第365天: reward = 1000 × 1.02^365 = 1,404,956 USDX  (利息: 1,403,956)
```

| | 正常流程 | 攻击流程 | 多获取 |
|--|---------|---------|--------|
| withdrawInterest | 0 | 1,376,408 | - |
| unstake (利息部分) | 1,403,956 | 1,403,956 | - |
| **利息合计** | **1,403,956** | **2,780,364** | **+1,376,408 (+98.0%)** |

### 3.3 多次 withdrawInterest 的情况

用户可以在质押期内**多次**调用 `withdrawInterest`, 每次提取增量利息。`withdrawInterest` 内部正确追踪了 `withdrawnInterest`, 所以多次调用 `withdrawInterest` 之间不会重复发放。但最终 `unstake` 时仍然会按全额重复发放一次。

```
第30天 withdrawInterest: 提取 388.07
第60天 withdrawInterest: 提取 926.75 - 388.07 = 538.68
第89天 withdrawInterest: 提取 1660.05 - 926.75 = 733.30
第90天 unstake: 仍然按 2687.87 全额 swap, 用户再获得利息 1687.87

总利息: 388.07 + 538.68 + 733.30 + 1687.87 = 3347.92 (同单次 withdrawInterest 结果)
```

无论分几次提取, **多获取的总额固定等于 unstake 前最后一次 `withdrawnInterest` 的累计值**。

## 4. 连锁影响

### 4.1 合约 AE 代币耗尽

每次双重利息发放, 合约需要额外 swap AE → USDX。这会:

1. 消耗合约中的 AE 余额
2. 对 AE/USDX 交易对造成卖压, 降低 AE 价格
3. AE 价格下跌后, 后续 unstake 需要更多 AE 才能 swap 出同等 USDX
4. 最终触发 H-01 (maxInput 50% 限制), 导致后续用户 unstake 失败

### 4.2 H-02 费用基数膨胀

`unstake` 中的 `interestEarned` 按全额计算:

```solidity
uint256 interestEarned = usdxReceived > principalAmount
    ? usdxReceived - principalAmount
    : 0;

uint256 educationFund = _distributeEducationFund(interestEarned);  // 5%
uint256 teamFee = _distributeTeamReward(referralChain, interestEarned);  // 35%
```

如果用户已通过 `withdrawInterest` 提取了 1660 利息 (且该次已扣过 5%+35% 费用), 在 `unstake` 时 `interestEarned` 仍为 1688, 导致费用在已提取利息上**被重复收取**。

用户在 `unstake` 阶段虽然获得了双重利息, 但也被多收了一次费用。不过由于利息远大于费用, 用户仍然净获利。

### 4.3 系统性风险

- 知情攻击者会在每次 `unstake` 前先调用 `withdrawInterest`, 形成套利策略
- 合约 AE 余额消耗速度是设计预期的约 2 倍
- 系统 APY 实际为设计值的约 2 倍, 可能导致庞氏崩溃

## 5. 修复方案

### 方案 A: 在 `_burn()` 中扣除已提取利息 (推荐)

**原理:** 在 `_burn()` 返回的 reward 中减去 `withdrawnInterest`, 使 `unstake` 只 swap 尚未发放的部分。

**修改位置:** `StakingBase.sol` — `_burn()` 函数

**当前代码 (L1245-1275):**

```solidity
function _burn(
    uint256 index
) private returns (uint256 reward, uint256 amount) {
    address sender = msg.sender;
    IStaking.Record[] storage cord = userStakeRecord[sender];
    IStaking.Record storage user_record = cord[index];

    uint256 stakeTime = user_record.stakeTime;

    if (
        block.timestamp - stakeTime < getStakePeriod(user_record.stakeIndex)
    ) revert StakingPeriodNotMet();
    if (user_record.status) revert AlreadyWithdrawn();

    amount = user_record.amount;
    reward = _calculateStakeReward(user_record);
    user_record.status = true;

    _update(sender, address(0), amount);

    // ... 后续逻辑
}
```

**修复后代码:**

```solidity
function _burn(
    uint256 index
) private returns (uint256 reward, uint256 amount) {
    address sender = msg.sender;
    IStaking.Record[] storage cord = userStakeRecord[sender];
    IStaking.Record storage user_record = cord[index];

    uint256 stakeTime = user_record.stakeTime;

    if (
        block.timestamp - stakeTime < getStakePeriod(user_record.stakeIndex)
    ) revert StakingPeriodNotMet();
    if (user_record.status) revert AlreadyWithdrawn();

    amount = user_record.amount;
    reward = _calculateStakeReward(user_record);

    // [修复 C-02] 扣除已通过 withdrawInterest 提取的利息
    uint256 alreadyWithdrawn = withdrawnInterest[sender][index];
    if (alreadyWithdrawn > 0) {
        require(reward > alreadyWithdrawn, "Reward calculation error");
        reward -= alreadyWithdrawn;
    }

    user_record.status = true;

    _update(sender, address(0), amount);

    // ... 后续逻辑
}
```

**对 `unstake()` 的影响:**

修复后, `_burn()` 返回的 `reward` 已经是扣除已提取利息后的净值:
- `_swapAEForReward(calculatedReward)` — swap 金额正确, 不会多 swap
- `interestEarned = usdxReceived - principalAmount` — 利息基数正确, 费用不会重复收取
- 同时自动修复了 H-02 (费用基数膨胀) 问题

**修复后数据流:**

```
第89天 withdrawInterest:
  availableInterest = 1660.05 → 发放给用户
  withdrawnInterest[user][idx] = 1660.05

第90天 unstake:
  _burn():
    fullReward = _calculateStakeReward() = 2687.87
    alreadyWithdrawn = 1660.05
    reward = 2687.87 - 1660.05 = 1027.82  ← 仅剩余部分

  _swapAEForReward(1027.82):
    swap 出约 1027.82 USDX (= 本金 1000 + 剩余利息 27.82)

  interestEarned = 1027.82 - 1000 = 27.82
  用户获得: 1027.82 USDX (扣费前)

总利息: 1660.05 + 27.82 = 1687.87 ✓ (等于正常应得)
```

### 方案 B: 在 `unstake()` 中调整 interestEarned (替代方案)

不改 `_burn()`, 而是在 `unstake()` 中做调整。

**修改位置:** `StakingBase.sol` — `unstake()` 函数

```solidity
function unstake(
    uint256 stakeIndex
) external onlyEOA returns (uint256 totalReward) {
    // 在 _burn 之前读取已提取利息
    uint256 alreadyWithdrawnInterest = withdrawnInterest[msg.sender][stakeIndex];

    (uint256 calculatedReward, uint256 principalAmount) = _burn(stakeIndex);

    // 扣除已提取利息后再 swap
    uint256 adjustedReward = calculatedReward - alreadyWithdrawnInterest;
    (uint256 usdxReceived, uint256 aeTokensUsed) = _swapAEForReward(adjustedReward);

    uint256 interestEarned = usdxReceived > principalAmount
        ? usdxReceived - principalAmount
        : 0;

    // ... 后续费用分配和转账逻辑不变
}
```

### 方案对比

| | 方案 A (推荐) | 方案 B |
|--|--------------|--------|
| 修改范围 | `_burn()` 一处 | `unstake()` 一处 |
| 封装性 | 好 — `_burn` 返回的 reward 含义统一 | 差 — 调用者需知道 reward 含已提取部分 |
| H-02 修复 | 自动修复 | 自动修复 |
| 兼容性 | 如果 `_burn` 被其他地方调用, 行为一致 | 只修复 `unstake` 的调用路径 |
| 风险 | `reward - alreadyWithdrawn` 需确保不下溢 | 同样需要确保不下溢 |

**推荐方案 A**, 因为它从源头修复问题, 使 `_burn()` 返回的语义更准确。

## 6. 测试验证要点

修复后应验证以下场景:

### 6.1 基本场景

1. **仅 unstake (无 withdrawInterest):** 行为不变, reward 中 `alreadyWithdrawn = 0`, 无影响
2. **单次 withdrawInterest 后 unstake:** 总利息 = withdrawInterest 利息 + unstake 利息 = 全额利息
3. **多次 withdrawInterest 后 unstake:** 总利息 = 各次 withdrawInterest 利息之和 + unstake 剩余利息 = 全额利息

### 6.2 边界场景

4. **到期后 withdrawInterest 再 unstake:** withdrawInterest 提取全部利息, unstake 的 reward 应等于本金
5. **withdrawInterest 提取全部利息后立即 unstake:** reward = principalAmount, interestEarned = 0, 用户只拿回本金
6. **从未 withdrawInterest 的用户 unstake:** `alreadyWithdrawn = 0`, 行为完全不变

### 6.3 数值验证

7. 90 天档, 1000 USDX 本金:
   - 第89天 withdrawInterest: 应得 ~1660 USDX 利息
   - 第90天 unstake: 应得 ~1028 USDX (本金 1000 + 剩余利息 ~28)
   - 总利息: ~1688 USDX (等于直接 unstake 的全额利息)

---

## 7. 总结

这是一个典型的**状态不一致漏洞**: `withdrawInterest()` 维护了 `withdrawnInterest` 状态, 但 `_burn()`/`unstake()` 在计算奖励时完全忽略了这个状态。修复方法是在 `_burn()` 中读取并扣除 `withdrawnInterest`, 使两个提取路径的利息计算保持一致。

修复此漏洞同时可以消除 H-02 (费用基数膨胀) 问题, 因为 `unstake` 中的 `interestEarned` 将只包含尚未提取的利息部分, 费用只在新利息上收取。
