# 赎回质押收益记录包含本金问题诊断

## 问题描述

赎回质押（unstake）时，推送的"质押收益记录"中的值包含了本金，不是纯利息。

## 涉及的代码位置

| 文件 | 行号 | 说明 |
|------|------|------|
| `contracts/AE-Staking/src/abstract/StakingBase.sol` | 360-361 | `totalClaimedStakingReward` 累加和事件推送 |
| `contracts/AE-Staking/src/abstract/StakingBase.sol` | 292-375 | `unstake()` 函数完整流程 |
| `contracts/AE-Staking/src/abstract/StakingBase.sol` | 1777-1822 | `_recordWithdrawal()` 记录和事件推送 |

| `contracts/AE-Staking/src/interfaces/IStaking.sol` | 174-179 | `RewardPaid` 事件定义 |
| `contracts/AE-Staking/src/interfaces/IStaking.sol` | 195-207 | `WithdrawalCompleted` 事件定义 |
| `contracts/AE-Staking/src/interfaces/IStaking.sol` | 347 | `UserStakingRewardUpdated` 事件定义 |

## 根因分析

### 问题 1：`totalClaimedStakingReward` 累加的是 `userPayout`（含本金）

**位置：** `StakingBase.sol:360-361`

```solidity
// 累计用户质押收益
totalClaimedStakingReward[msg.sender] += userPayout;
emit UserStakingRewardUpdated(msg.sender, userPayout, totalClaimedStakingReward[msg.sender]);
```

`userPayout` 的计算方式（`StakingBase.sol:312`）：

```solidity
uint256 userPayout = usdxReceived - educationFund - teamFee;
```

**问题核心：** `usdxReceived` 是 AE 换回的 USDX 总金额，它**包含了本金 + 利息**。`userPayout` 只是从中扣除了教育基金和团队费用，但**本金仍然在其中**。

所以 `totalClaimedStakingReward` 实际累加的是「本金 + 扣费后的利息」，而不是纯利息收益。

### 问题 2：`RewardPaid` 事件推送的是 `calculatedReward`（含本金）

**位置：** `StakingBase.sol:1807`

```solidity
emit RewardPaid(user, calculatedReward, withdrawalTime, stakeIndex);
```

`calculatedReward` 来自 `_burn()` 函数（`StakingBase.sol:1287`）：

```solidity
reward = _calculateStakeReward(user_record);
```

而 `_calculateStakeReward()`（`StakingBase.sol:1555-1584`）计算的是**复利后的总金额**：

```solidity
UD60x18 compoundedAmount = principalAmount.mul(
    baseInterestRate.powu(compoundPeriods)
);
currentReward = UD60x18.unwrap(compoundedAmount);
```

这是 `本金 × 利率^期数`，即**本金 + 利息的总和**，不是纯利息。

### 问题 3：`WithdrawalRecord.calculatedReward` 字段命名误导

**位置：** `IStaking.sol:100, 112`

```solidity
/// @param calculatedReward Total calculated reward (principal + interest)
uint256 calculatedReward;
```

注释写的 "Total calculated reward (principal + interest)"，说明设计者本身知道这个值包含本金。但字段名叫 `calculatedReward`（计算的**奖励**），容易让前端/测试误以为这是纯利息。

## 数据流追踪

以一笔质押 100 USDX、到期利息为 10 USDX 为例：

```
_burn() 返回：
  calculatedReward = 110  (本金100 + 利息10)
  principalAmount  = 100

_swapAEForReward(110) 返回：
  usdxReceived = ~110  (实际换回的USDX，可能有滑点)
  假设 usdxReceived = 109

interestEarned = 109 - 100 = 9  ✅ 纯利息（已正确计算）

educationFund = 9 * 5%  = 0.45
teamFee       = 9 * 35% = 3.15

userPayout = 109 - 0.45 - 3.15 = 105.4  ❌ 包含本金100

// 推送的记录：
totalClaimedStakingReward += 105.4  ❌ 累加了本金
emit UserStakingRewardUpdated(user, 105.4, ...)  ❌ 事件值含本金
emit RewardPaid(user, 110, ...)  ❌ 事件值含本金
```

## 各字段/事件的实际含义 vs 语义期望

| 字段/事件 | 名称含义（语义期望） | 实际值 | 是否含本金 |
|-----------|---------------------|--------|-----------|
| `calculatedReward` | "计算的奖励" | 本金 + 利息 | ❌ **含本金** |
| `RewardPaid.reward` | "支付的奖励" | 本金 + 利息 | ❌ **含本金** |
| `totalClaimedStakingReward` | "累计质押收益" | 累加 userPayout (本金+扣费后利息) | ❌ **含本金** |
| `UserStakingRewardUpdated.amount` | "质押收益更新金额" | userPayout (本金+扣费后利息) | ❌ **含本金** |
| `interestEarned` | "赚取的利息" | usdxReceived - principalAmount | ✅ 纯利息 |
| `totalClaimedNetInterest` | "累计净利息" | 扣费后的纯利息 | ✅ 纯利息 |
| `totalPrincipalReturned` | "累计退还本金" | 本金 | ✅ 纯本金 |

## 已有的正确字段

合约中其实**已经有正确的纯利息追踪**：

1. **`totalClaimedNetInterest`**（`StakingBase.sol:202, 369`）—— 追踪纯净利息
2. **`totalPrincipalReturned`**（`StakingBase.sol:199, 364`）—— 追踪纯本金
3. **`WithdrawalRecord.interestEarned`**（`IStaking.sol:117`）—— 单笔纯利息

这三个字段的计算是正确的，不包含混淆。

## 问题总结

存在**两类问题**：

### 类型 A：语义混淆（前端/测试易误读）

- `totalClaimedStakingReward` 名称暗示"质押收益"，实际是"用户到账总额（含本金）"
- `RewardPaid` 事件的 `reward` 参数是"本金+利息"，不是"纯奖励"
- `calculatedReward` 字段是"本金+利息"，不是"计算的奖励"

### 类型 B：数值正确性（取决于设计意图）

如果 `totalClaimedStakingReward` 的设计意图就是追踪"用户到账总额"，那数值是正确的，只是命名不准确。

如果设计意图是追踪"纯收益/利息"，那么 `unstake()` 中的累加逻辑需要修改。

## 修复建议（仅供参考，不改代码）

### 方案 1：修改累加逻辑（如果语义应该是"纯收益"）

`StakingBase.sol:359-361` 处，将 `userPayout` 替换为净利息值：

```
// 当前（含本金）：
totalClaimedStakingReward[msg.sender] += userPayout;

// 修改为（纯收益）：
// 使用已有的 interestAfterEduTeam - interestRedemptionFee，
// 即与 totalClaimedNetInterest 的累加值保持一致
```

### 方案 2：重命名字段（如果语义应该是"到账总额"）

- `totalClaimedStakingReward` → `totalClaimedStakingPayout` 或 `totalUserPayoutFromStaking`
- `UserStakingRewardUpdated` → `UserStakingPayoutUpdated`
- 前端/测试按"到账总额"理解，不当作"纯收益"使用

### 方案 3：前端侧适配（不改合约）

前端在展示"质押收益"时，不读 `totalClaimedStakingReward`，而是读 `totalClaimedNetInterest`，后者才是纯利息收益。

## 与 `withdrawInterest()` 的对比

`withdrawInterest()`（`StakingBase.sol:385-480`）中同样有：

```solidity
// Line 457
totalClaimedStakingReward[user] += userPayout;
emit UserStakingRewardUpdated(user, userPayout, totalClaimedStakingReward[user]);
```

但 `withdrawInterest` 的 `userPayout` **不含本金**（因为它只提取利息，不退本金），所以在 `withdrawInterest` 场景下 `totalClaimedStakingReward` 的累加是正确的。

**问题仅出现在 `unstake()` 场景**，因为 unstake 的 `userPayout` 包含了退还的本金。
