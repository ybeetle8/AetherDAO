# 7天质押限制方案设计

## 需求
7天质押方案（方案0）每个用户只能使用一次，需要在合约中添加限制机制。

## 方案对比

### 方案1：简单布尔标记（推荐）⭐

#### 实现方式
```solidity
// 在 StakingBase.sol 中添加
mapping(address => bool) public hasUsed7DayStake;

// 在 stake() 函数中检查
if (_stakeIndex == 0) {
    require(!hasUsed7DayStake[msg.sender], "7-day stake already used");
    hasUsed7DayStake[msg.sender] = true;
}
```

#### 优点
- ✅ 实现简单，代码清晰
- ✅ Gas 消耗最低（只需一次 SSTORE）
- ✅ 查询效率高（O(1)）
- ✅ 易于理解和维护

#### 缺点
- ❌ 无法重置（除非添加 owner 函数）
- ❌ 无法查询使用时间

#### Gas 成本
- 首次标记：~20,000 gas（SSTORE from 0 to 1）
- 查询：~2,100 gas（SLOAD）

---

### 方案2：记录使用次数

#### 实现方式
```solidity
// 在 StakingBase.sol 中添加
mapping(address => uint8) public stake7DayCount;
uint8 public constant MAX_7DAY_STAKES = 1;

// 在 stake() 函数中检查
if (_stakeIndex == 0) {
    require(stake7DayCount[msg.sender] < MAX_7DAY_STAKES, "7-day stake limit reached");
    stake7DayCount[msg.sender]++;
}
```

#### 优点
- ✅ 灵活性高，可以轻松调整限制次数
- ✅ 可以查询已使用次数
- ✅ 未来可扩展为允许多次使用

#### 缺点
- ❌ 比方案1稍复杂
- ❌ Gas 消耗略高（需要读取和递增）

#### Gas 成本
- 首次使用：~20,000 gas
- 后续查询：~2,100 gas

#### 适用场景
如果未来可能调整为"允许使用2次"或"允许使用3次"，这个方案更合适。

---

### 方案3：记录使用时间戳

#### 实现方式
```solidity
// 在 StakingBase.sol 中添加
mapping(address => uint256) public first7DayStakeTime;

// 在 stake() 函数中检查
if (_stakeIndex == 0) {
    require(first7DayStakeTime[msg.sender] == 0, "7-day stake already used");
    first7DayStakeTime[msg.sender] = block.timestamp;
}
```

#### 优点
- ✅ 可以查询用户首次使用时间
- ✅ 便于数据分析和统计
- ✅ 可以基于时间实现更复杂的逻辑（如"每年可用一次"）

#### 缺点
- ❌ 存储 uint256 比 bool 消耗更多空间
- ❌ 如果不需要时间信息，则浪费存储

#### Gas 成本
- 首次使用：~20,000 gas
- 查询：~2,100 gas

#### 适用场景
如果需要追踪用户行为、做数据分析，或未来可能基于时间实现"冷却期"功能。

---

### 方案4：基于质押记录检查（无需额外存储）

#### 实现方式
```solidity
// 在 stake() 函数中检查
if (_stakeIndex == 0) {
    // 遍历用户的质押记录
    IStaking.Record[] storage records = userStakeRecord[msg.sender];
    for (uint256 i = 0; i < records.length; i++) {
        require(records[i].stakeIndex != 0, "7-day stake already used");
    }
}
```

#### 优点
- ✅ 无需额外存储空间
- ✅ 利用现有数据结构

#### 缺点
- ❌ Gas 消耗随用户质押次数线性增长（O(n)）
- ❌ 如果用户有很多质押记录，Gas 费用会非常高
- ❌ 性能差，不推荐

#### Gas 成本
- 首次使用：~5,000 gas（遍历0条记录）
- 第10次质押时检查：~50,000 gas（遍历10条记录）
- 第100次质押时检查：~500,000 gas（可能超出区块 gas 限制）

#### 适用场景
**不推荐使用**，除非用户质押次数非常少（<5次）。

---

### 方案5：时间冷却期（允许重复使用）

#### 实现方式
```solidity
// 在 StakingBase.sol 中添加
mapping(address => uint256) public last7DayStakeTime;
uint256 public constant COOLDOWN_7DAY = 365 days; // 一年冷却期

// 在 stake() 函数中检查
if (_stakeIndex == 0) {
    require(
        block.timestamp >= last7DayStakeTime[msg.sender] + COOLDOWN_7DAY,
        "7-day stake cooldown not met"
    );
    last7DayStakeTime[msg.sender] = block.timestamp;
}
```

#### 优点
- ✅ 允许用户在冷却期后再次使用
- ✅ 更灵活的限制机制
- ✅ 可以调整冷却期长度

#### 缺点
- ❌ 如果需求是"永久只能用一次"，则不适用
- ❌ 需要额外的时间计算逻辑

#### Gas 成本
- 每次使用：~20,000 gas
- 查询：~2,100 gas

#### 适用场景
如果希望用户可以定期使用7天质押（如每年一次），这个方案很合适。

---

## 推荐方案

### 🏆 最佳方案：方案1（简单布尔标记）

**理由：**
1. **需求匹配**：题目要求"每个用户只能使用一次"，布尔标记完美满足
2. **Gas 效率**：最低的 Gas 消耗
3. **代码简洁**：实现简单，易于审计和维护
4. **安全性高**：逻辑简单，不易出错

### 实现细节

#### 1. 状态变量
```solidity
// 在 StakingBase.sol 的状态变量区域添加
mapping(address => bool) public hasUsed7DayStake;
```

#### 2. 修改 stake() 函数
```solidity
function stake(uint256 _amount, uint8 _stakeIndex) external {
    // ... 现有的检查逻辑 ...

    // 添加7天质押限制检查
    if (_stakeIndex == 0) {
        require(!hasUsed7DayStake[msg.sender], "7-day stake can only be used once");
        hasUsed7DayStake[msg.sender] = true;
    }

    // ... 后续的质押逻辑 ...
}
```

#### 3. 添加查询函数（可选）
```solidity
/**
 * @notice 查询用户是否已使用7天质押
 * @param user 用户地址
 * @return 是否已使用
 */
function has7DayStakeBeenUsed(address user) external view returns (bool) {
    return hasUsed7DayStake[user];
}
```

#### 4. 添加事件（可选）
```solidity
event FirstTime7DayStakeUsed(address indexed user, uint256 timestamp);

// 在标记时触发
if (_stakeIndex == 0 && !hasUsed7DayStake[msg.sender]) {
    hasUsed7DayStake[msg.sender] = true;
    emit FirstTime7DayStakeUsed(msg.sender, block.timestamp);
}
```

## 扩展考虑

### 1. 是否需要 Owner 重置功能？

如果需要管理员能够重置某个用户的7天质押使用状态：

```solidity
/**
 * @notice Owner 可以重置用户的7天质押使用状态
 * @param user 用户地址
 */
function reset7DayStakeUsage(address user) external onlyOwner {
    hasUsed7DayStake[user] = false;
    emit StakeUsageReset(user, 0); // 0 表示7天质押
}
```

### 2. 批量重置功能

```solidity
/**
 * @notice 批量重置多个用户的7天质押使用状态
 * @param users 用户地址数组
 */
function batchReset7DayStakeUsage(address[] calldata users) external onlyOwner {
    for (uint256 i = 0; i < users.length; i++) {
        hasUsed7DayStake[users[i]] = false;
    }
    emit BatchStakeUsageReset(users, 0);
}
```

### 3. 全局开关

如果希望能够临时关闭这个限制：

```solidity
bool public enforce7DayStakeLimit = true;

function setEnforce7DayStakeLimit(bool _enforce) external onlyOwner {
    enforce7DayStakeLimit = _enforce;
}

// 在 stake() 中检查
if (_stakeIndex == 0 && enforce7DayStakeLimit) {
    require(!hasUsed7DayStake[msg.sender], "7-day stake can only be used once");
    hasUsed7DayStake[msg.sender] = true;
}
```

## 安全考虑

### 1. 重入攻击
- ✅ 使用 `hasUsed7DayStake[msg.sender] = true` 在调用外部合约前设置
- ✅ 遵循 Checks-Effects-Interactions 模式

### 2. 前端显示
建议在前端调用 `hasUsed7DayStake(user)` 或 `has7DayStakeBeenUsed(user)` 来：
- 禁用7天质押按钮
- 显示"已使用"提示
- 引导用户选择其他方案

### 3. 测试用例
需要添加的测试：
- ✅ 用户首次使用7天质押成功
- ✅ 用户第二次使用7天质押失败
- ✅ 用户可以正常使用其他质押方案（1/2/3/4）
- ✅ 不同用户的限制互不影响

---

## 总结

**推荐使用方案1（简单布尔标记）**，因为：
1. 完美匹配需求
2. Gas 效率最高
3. 代码最简洁
4. 安全性最高

如果未来需求变化（如允许多次使用、添加冷却期等），可以轻松迁移到其他方案。
