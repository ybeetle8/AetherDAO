# AetherDAO 合约代码说明 - 第3部分：推荐人系统与项目总结

## 四、推荐人合约（Aether-Referral）

### 4.1 AetherReferral.sol

**文件**: `contracts/Aether-Referral/AetherReferral.sol`（约520行）

独立的推荐关系管理合约，不依赖 AE 或 Staking 合约。

#### 状态变量

```solidity
address public rootAddress;                        // 根推荐人
address public operator;                           // 操作员地址

mapping(address => address) internal _referrals;    // 用户 → 推荐人
mapping(address => address[]) internal _children;   // 推荐人 → 下级列表
mapping(address => bool) internal _hasLockedReferral; // 推荐绑定状态

mapping(address => address) internal _friends;      // 用户 → 好友（5%奖励）
mapping(address => bool) internal _hasLockedFriend;  // 好友绑定状态

uint256 constant MAX_REFERRAL_DEPTH = 30;           // 最大推荐链深度
```

#### 核心函数

##### 用户操作

| 函数 | 说明 |
|------|------|
| `lockReferral(referrer)` | 绑定推荐人（一次性，不可更改） |
| `lockFriend(friend)` | 绑定好友（5%奖励接收者，一次性） |

##### 绑定规则

```
lockReferral(referrer):
├── 不能重复绑定
├── 不能自我推荐
├── 推荐人必须已绑定（或是 rootAddress）
├── 不能形成循环引用
└── 触发 ReferralBound 事件

lockFriend(friend):
├── 不能重复绑定
├── 不能自我绑定
└── 触发 FriendBound 事件
```

##### 查询函数

| 函数 | 说明 |
|------|------|
| `getReferral(user)` | 获取直接推荐人 |
| `getFriend(user)` | 获取绑定好友 |
| `hasLockedReferral(user)` | 是否已绑定推荐人 |
| `hasLockedFriend(user)` | 是否已绑定好友 |
| `getReferrals(user, maxDepth)` | 获取完整推荐链 |
| `getChildren(user)` | 获取直接下级列表 |
| `getChildrenCount(user)` | 直接下级数量 |
| `getChildrenPaged(user, offset, limit)` | 分页获取下级 |
| `getUserInfo(user)` | 完整关系信息 |
| `getReferralChainWithDepth(user, maxDepth)` | 带深度的推荐链 |
| `batchGetUserInfo(users)` | 批量查询用户信息 |

##### 管理函数

| 函数 | 权限 | 说明 |
|------|------|------|
| `setOperator(address)` | owner | 设置操作员 |
| `adminBindReferral(user, referrer)` | operator | 管理员绑定推荐人 |
| `adminBindFriend(user, friend)` | operator | 管理员绑定好友 |

## 五、项目功能总结

### 5.1 代币经济模型

#### 买入交易（3% 税）

```
用户买入 AE
├── 2% → 节点分红池
└── 1% → 社区分红池
```

#### 卖出交易（3% 固定税 + 可变利润税）

```
用户卖出 AE
├── 固定税 3%
│   ├── 1.5% → 营销基金
│   └── 1.5% → 销毁
└── 利润税（仅盈利部分 × 25%）
    ├── 15% → 流动性（买入AE + 添加LP，烧毁LP）
    ├── 15% → 周 Top15 奖励
    ├── 10% → 营销基金（买AE）
    └── 60% → 销毁（买AE后烧毁）
```

#### 冷却机制

- 买入后 10 秒内不可卖出

### 5.2 质押系统

#### 质押流程

```
用户质押 USDT
├── 50% USDT → 兑换 AE
├── AE + USDT → 添加流动性
├── LP Token → 烧毁
├── 记录质押信息
└── 每日复利计算收益
```

#### 赎回流程

```
质押到期，用户赎回
├── 计算复利总收益
├── 扣除已提取利息
├── 收益 AE → USDT
├── 手续费分配
│   ├── 5% → 教育基金
│   ├── ≤35% → 团队奖励（推荐链分配）
│   └── 1% → 赎回手续费
└── 剩余 → 用户
```

#### 提前提取利息

```
质押未到期，提取已产生利息
├── 计算可提取利息
├── 收益 AE → USDT
├── 同样的手续费结构
├── 本金继续生息
└── 记录已提取金额
```

### 5.3 推荐人体系

#### 推荐链结构

```
rootAddress（根节点）
├── A（V5 等级）
│   ├── B（V3 等级）
│   │   ├── D
│   │   └── E
│   └── C（V1 等级）
│       └── F
└── G
```

#### 团队奖励分配示例

假设用户 D 赎回质押，产生 1000 USDT 利息：

```
团队奖励池 = 1000 × 35% = 350 USDT

推荐链：D → B(V3,11%) → A(V5,19%) → root

差额分配：
├── B（V3）：350 × (11% - 0%) / 35% = 110 USDT
├── A（V5）：350 × (19% - 11%) / 35% = 80 USDT
└── root：350 - 110 - 80 = 160 USDT（剩余）
```

### 5.4 等级系统

用户等级由两个维度决定，取较低者：

1. **团队 KPI 等级**：所有下级质押总额
2. **个人质押等级**：自身活跃质押总额

这保证了高等级用户必须自身也有足够投入。

### 5.5 安全机制

| 机制 | 说明 |
|------|------|
| EOA 检查 | 主网禁止合约调用质押（防机器人） |
| 重入锁 | swap 操作使用 lockSwap 防重入 |
| 黑名单 | 可禁止特定地址交易 |
| 白名单 | 特定地址免税 |
| 滑点保护 | 动态滑点计算，最低 80% 输出保障 |
| 循环引用检测 | 推荐链绑定时检测循环 |
| 紧急提取 | 管理员紧急提取资金 |
| 冷却期 | 买卖间 10 秒冷却 |
