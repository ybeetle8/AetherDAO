# 推荐关系数据导出方案

## 目标

从 BSC 主网的 AetherReferral 合约 (`0x3810AE81750b61e8A73E1f96562e651f45d645EF`) 中导出全部推荐关系和好友关系数据，保存为 JSON 文件，作为后续迁移的数据源。

## 合约分析

### 需要导出的状态数据

| 数据 | 存储方式 | 读取方式 |
|------|---------|---------|
| 用户→推荐人 | `_referrals` mapping | `getReferral(user)` |
| 推荐人→下线列表 | `_children` mapping | `getChildren(user)` |
| 是否已绑定推荐人 | `_hasLockedReferral` mapping | `hasLockedReferral(user)` |
| 用户→好友 | `_friends` mapping | `getFriend(user)` |
| 是否已绑定好友 | `_hasLockedFriend` mapping | `hasLockedFriend(user)` |
| 根地址 | `rootAddress` | `rootAddress()` |

### 难点：如何获取所有用户地址

Solidity mapping 不可枚举，无法直接遍历。解决方案是通过扫描事件日志来收集所有参与过的地址：

- `ReferralBound(user, referrer, timestamp)` - 用户自行绑定推荐人
- `AdminReferralBound(user, referrer, admin, timestamp)` - 管理员绑定推荐人
- `FriendBound(user, friend, timestamp)` - 用户自行绑定好友
- `AdminFriendBound(user, friend, admin, timestamp)` - 管理员绑定好友

每个事件包含的 `user`、`referrer`、`friend` 地址全部收集，即可得到完整的用户地址集合。

## 脚本设计

### 执行流程

```
步骤 1：扫描链上事件
  ├── 分区块范围扫描 4 种事件（每次 5000 区块）
  ├── 收集所有独立地址
  └── 记录事件详情（用于审计）

步骤 2：批量查询用户关系数据
  ├── 使用 batchGetUserInfo() 批量查询（每批 100 个）
  ├── 获取每个用户的 referrer、friend、锁定状态
  └── 查询失败时降级为逐个查询

步骤 3：查询下线数据
  ├── 找出所有被引用为推荐人的地址
  └── 逐个调用 getChildren() 获取下线列表

步骤 4：构建输出数据并保存为 JSON
```

### 容错机制

- **区块范围限制**：BSC RPC 通常限制单次查询 5000 个区块，脚本按此分片扫描
- **分片失败重试**：大范围扫描失败时，自动缩小到 1/5 范围重试
- **批量查询降级**：`batchGetUserInfo` 失败时降级为逐个调用 `getReferral` / `getFriend` 等

### 关键字段说明

| 字段 | 用途 |
|------|------|
| `referralPairs` | **迁移核心数据** - 直接用于新合约的批量导入 |
| `friendPairs` | 好友关系迁移数据 |
| `users` | 完整的用户状态快照，用于验证 |
| `children` | 下线关系，用于交叉验证数据一致性 |
| `events` | 原始事件记录，用于审计追溯 |

## 使用方式

```bash
# 直接连接 BSC 主网执行
npx hardhat run scripts/exportReferralData.js --network bsc
```

输出文件保存在 `data/referral-data.json`。

## 配置参数

脚本头部可调整的参数：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `START_BLOCK` | 46000000 | 事件扫描起始区块，建议设为合约部署区块 |
| `BLOCK_RANGE` | 5000 | 每次事件查询的区块范围 |
| `BATCH_SIZE` | 100 | 批量查询每批地址数 |

如果 RPC 返回超时或限流，可适当减小 `BLOCK_RANGE`。

## 数据验证

导出完成后可通过以下方式验证数据完整性：

1. **`referralPairs` 数量** 应等于 `stats.usersWithReferral`
2. **`children` 中的所有子地址** 应能在 `referralPairs` 中找到对应记录
3. **事件总数** 应等于 `referralPairs` + `friendPairs` 的总数（排除重复绑定的情况）
