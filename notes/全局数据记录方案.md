# 全局数据记录方案

## 1. 需求概述

在合约中新增全局统计数据的链上记录，用于前端 Dashboard 展示。需要记录以下数据：

| 序号 | 数据项 | 说明 |
|------|--------|------|
| 1 | 全网质押总量 (TVL) | 当前所有用户质押本金总额 |
| 2 | 全网累计分红 | 历史上所有用户提取到的利息总额 |
| 3 | 全网累计销毁 | AE 代币累计销毁总量 |
| 4 | 全网教育基金 | 累计拨付给教育基金的 USDX 总额 |
| 5 | 质押参与人数 | 当前有质押记录的独立地址数 |

## 2. 现有状态分析

### 2.1 已有的数据

| 数据项 | 现有变量 | 所在合约 | 是否满足需求 |
|--------|----------|----------|-------------|
| 全网质押总量 | `totalSupply` | StakingBase | **已满足** — 这是当前所有活跃质押的本金总额 |
| 全网累计分红 | 无 | — | **需新增** |
| 全网累计销毁 | 无 | — | **需新增** — 销毁发生在 AE 合约 (sell tax 的 1.5% burn + LP burn) |
| 全网教育基金 | 无 | — | **需新增** — `_distributeEducationFund()` 中有转账但没有累计记录 |
| 质押参与人数 | 无 | — | **需新增** — 有 `balances` mapping 但没有计数器 |

### 2.2 数据产生位置分析

#### 全网累计分红（用户实际拿到的 USDX）

分红产生于两处：
- **`unstake()`** — 用户到期解锁后拿到的 `userPayout`（已扣除教育基金 5%、团队奖 35%、赎回费 5%）
- **`withdrawInterest()`** — 用户提前提取利息后拿到的 `userPayout`

> 注意：这里的"分红"指用户实际到手金额 (userPayout)，不是合约计算出的总利息 (interestEarned)。如果需要记录的是总利息（含各类费用），逻辑类似但累加的值不同。

#### 全网累计销毁

AE 销毁发生在 **AE 合约** (AEBase) 中：
- **卖出交易 (sell)**：1.5% 发送到 DEAD_ADDRESS（直接销毁）
- **利润税处理**：60% 的利润税用于添加流动性后 LP 发送到 address(0)（LP 销毁）

由于销毁发生在 AE 合约而非 Staking 合约，有两种方案：
- **方案 A**：在 AE 合约中新增累计变量（直接记录）
- **方案 B**：通过 `balanceOf(DEAD_ADDRESS)` 直接读取死亡地址余额（无需新增变量）

#### 全网教育基金

产生于 StakingBase 的 `_distributeEducationFund()` 函数，每次 unstake/withdrawInterest 时触发。

#### 质押参与人数

变更时机：
- **增加**：`stake()` 时，如果用户之前 `balances == 0`，则参与人数 +1
- **减少**：`unstake()` 时，如果用户 `balances` 变为 0，则参与人数 -1

## 3. 修改方案

### 3.1 StakingBase 合约 — 新增状态变量

```solidity
// =========================================================================
// GLOBAL STATISTICS
// =========================================================================

// 全网累计分红: 所有用户历史总到账 USDX (userPayout 之和)
uint256 public totalDividendsDistributed;

// 全网累计教育基金: 拨付给教育基金的 USDX 累计总额
uint256 public totalEducationFundDistributed;

// 当前质押参与人数 (有活跃质押的独立地址数)
uint256 public totalStakers;

// 用户是否为活跃质押者 (用于参与人数计数)
mapping(address => bool) private _isActiveStaker;
```

> **注**：`totalSupply` 已存在，无需新增 TVL 变量。

### 3.2 StakingBase 合约 — 修改 `_distributeEducationFund()`

在现有转账逻辑后，累加教育基金统计：

```solidity
function _distributeEducationFund(
    uint256 _interset
) private returns (uint256 fee) {
    unchecked {
        fee = (_interset * REFERRAL_REWARD_RATE) / PERCENTAGE_BASE;
    }
    IERC20(USDX).transfer(educationFundAddress, fee);

    // 新增: 累计教育基金统计
    totalEducationFundDistributed += fee;
}
```

### 3.3 StakingBase 合约 — 修改 `unstake()`

在 `unstake()` 函数末尾、USDX 转账后，累加分红统计：

```solidity
// 在 IERC20(USDX).transfer(msg.sender, userPayout); 之后新增:
totalDividendsDistributed += userPayout;
```

### 3.4 StakingBase 合约 — 修改 `withdrawInterest()`

在 `withdrawInterest()` 函数中、USDX 转账后，累加分红统计：

```solidity
// 在 IERC20(USDX).transfer(user, userPayout); 之后新增:
totalDividendsDistributed += userPayout;
```

### 3.5 StakingBase 合约 — 修改 `_mintStakeRecord()` 和 `_burn()`

**`_mintStakeRecord()`** — 质押时检查是否为新参与者：

```solidity
function _mintStakeRecord(
    address sender,
    uint160 _amount,
    uint8 _stakeIndex
) private {
    if (!isBindReferral(sender)) revert MustBindReferral();

    // 新增: 如果是新参与者，参与人数 +1
    if (!_isActiveStaker[sender]) {
        _isActiveStaker[sender] = true;
        totalStakers++;
    }

    // ... 后续逻辑不变 ...
}
```

**`_burn()`** — 解质押时检查是否完全退出：

```solidity
function _burn(
    uint256 index
) private returns (uint256 reward, uint256 amount) {
    // ... 现有逻辑 ...

    _update(sender, address(0), amount);

    // 新增: 如果用户所有本金都已取出，参与人数 -1
    if (balances[sender] == 0) {
        _isActiveStaker[sender] = false;
        totalStakers--;
    }

    unchecked {
        userIndex[sender] = userIndex[sender] + 1;
    }
}
```

### 3.6 AE 合约 — 销毁量记录

**推荐方案 B**：不新增状态变量，通过读取 DEAD_ADDRESS 余额实现。

```solidity
// 在 AEBase 或 AE 合约中新增 view 函数:
function getTotalBurned() external view returns (uint256) {
    return balanceOf(DEAD_ADDRESS);
}
```

**优势**：
- 零额外 gas 开销（不需要写 storage）
- 数据永远准确（直接读取实际余额）
- 无需修改任何交易逻辑
- 包含所有来源的销毁（sell tax、LP burn 等）

**备选方案 A**（如需精确分类统计各来源销毁量）：

```solidity
// 在 AEBase 中新增:
uint256 public totalSellBurned;      // 卖出税销毁
uint256 public totalLPBurned;        // LP 销毁对应的 AE 量
uint256 public totalBurned;          // 总销毁

// 在各销毁点累加
```

> 方案 A 会增加每笔 sell 交易的 gas（额外 ~5,000-20,000 gas），且需要修改多处逻辑。除非有按来源分类统计的需求，否则推荐方案 B。

### 3.7 新增 View 函数

在 StakingBase 中新增统一的全局统计查询接口：

```solidity
/// @notice 获取全局统计数据（供前端 Dashboard 使用）
/// @return tvl 全网质押总量 (当前活跃本金)
/// @return dividends 全网累计分红 (用户累计到账 USDX)
/// @return educationFund 全网累计教育基金
/// @return stakerCount 当前质押参与人数
function getGlobalStats() external view returns (
    uint256 tvl,
    uint256 dividends,
    uint256 educationFund,
    uint256 stakerCount
) {
    tvl = totalSupply;
    dividends = totalDividendsDistributed;
    educationFund = totalEducationFundDistributed;
    stakerCount = totalStakers;
}
```

在 AE 合约中：

```solidity
/// @notice 获取 AE 代币累计销毁总量
function getTotalBurned() external view returns (uint256) {
    return balanceOf(DEAD_ADDRESS);
}
```

### 3.8 新增 Events

```solidity
// StakingBase 中新增:
event GlobalDividendUpdated(uint256 userPayout, uint256 newTotalDividends);
event GlobalEducationFundUpdated(uint256 amount, uint256 newTotalEducationFund);
event StakerCountChanged(address indexed user, bool isJoin, uint256 newTotalStakers);
```

> Events 不是必须的，但有利于链下 indexer (如 The Graph) 追踪数据变化。可根据实际需要决定是否添加。

## 5. Gas 开销分析

| 操作 | 新增 Gas 开销 | 说明 |
|------|-------------|------|
| `stake()` | +~5,000-22,000 | 写 `totalStakers` (+20,000 首次)、写 `_isActiveStaker` |
| `unstake()` | +~5,000-7,000 | 写 `totalDividendsDistributed`、可能写 `totalStakers` |
| `withdrawInterest()` | +~5,000 | 写 `totalDividendsDistributed` |
| `_distributeEducationFund()` | +~5,000 | 写 `totalEducationFundDistributed` |
| `getTotalBurned()` (AE) | 0 额外 | 纯 view 调用，读已有余额 |
| `getGlobalStats()` | 0 额外 | 纯 view 调用 |

对比 stake 操作原本 ~500,000+ gas 的总开销，新增部分约 1-4%，影响可忽略。

## 6. Storage Layout 安全性

新增的状态变量全部追加在 StakingBase 现有变量之后，不会改变已有变量的 slot 位置：

```
现有最后一个变量:
  slot N:   dailyPeriodStart

新增变量 (追加):
  slot N+1: totalDividendsDistributed
  slot N+2: totalEducationFundDistributed
  slot N+3: totalStakers
  slot N+4: _isActiveStaker (mapping, 独立 slot)
```

**如果是升级合约（proxy 模式），这种追加方式是安全的。如果是重新部署，则无需担心 layout 问题。**

## 7. 决策点

在实施前需要确认以下几点：

### 7.1 "全网累计分红"的口径

| 选项 | 值 | 说明 |
|------|---|------|
| A. 用户到账金额 | `userPayout` | 扣除教育基金、团队奖、赎回费后的实际到账额 |
| B. 总利息金额 | `interestEarned` | 包含所有费用在内的总利息 |
| C. 总产出金额 | `usdxReceived` | swap 后收到的全部 USDX（含本金+利息） |

> **建议选 A**：最直观，代表用户实际收益。

### 7.2 "全网累计销毁"是否需要分类

| 选项 | 说明 |
|------|------|
| 简单模式 | 只用 `balanceOf(DEAD_ADDRESS)` 一个总数 |
| 详细模式 | 分类记录：sell 税销毁量 + LP 销毁量 + 其他 |

> **建议选简单模式**：gas 更省，数据准确，满足 Dashboard 展示需求。

### 7.3 是否需要新增 Events

Events 有助于链下 indexer 构建历史图表（如每日分红趋势），但会增加约 ~375 gas/event。如果前端只需要"当前快照"数据，可以不加 events。
