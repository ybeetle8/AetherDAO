## 二、状态变量

```solidity
// L169-170
uint256 public dailyStakedAmount;   // 当前周期内已质押总量
uint256 public dailyPeriodStart;    // 当前周期的起始时间戳
```

- `dailyStakedAmount`: 累计记录当前日周期内所有用户的质押总额
- `dailyPeriodStart`: 记录当前日周期是从哪个 UTC 06:00 开始的

## 三、完整调用流程

用户调用 `stake()` 时，每日限额的检查在所有其他逻辑之前执行:

```
stake(_amount, _stakeIndex)           // L268
  ├─ _validateStakeParameters()       // L269  先校验基础参数(最小/最大/用户上限)
  ├─ _checkAndUpdateDailyLimit()      // L272  ★ 每日限额检查与更新
  ├─ _swapAndAddLiquidity()           // L281  执行 swap + 加流动性
  └─ _mintStakeRecord()               // L283  铸造质押记录
```

### 3.1 `_checkAndUpdateDailyLimit()` 详解 (L1185-L1202)

```solidity
function _checkAndUpdateDailyLimit(uint256 _amount) private {
    uint256 currentPeriodStart = _getCurrentPeriodStart();

    // 1. 判断是否跨入新周期 → 自动重置
    if (dailyPeriodStart < currentPeriodStart) {
        dailyPeriodStart = currentPeriodStart;
        dailyStakedAmount = 0;              // 归零
    }

    // 2. 检查本次质押是否会超限
    require(
        dailyStakedAmount + _amount <= DAILY_NETWORK_STAKE_LIMIT,
        "Exceeds daily network stake limit"
    );

    // 3. 累加已质押量
    dailyStakedAmount += _amount;
}
```

**关键逻辑:**
1. 先调用 `_getCurrentPeriodStart()` 获取"当前日周期"的起始时间
2. 如果存储的 `dailyPeriodStart` 小于当前周期起始时间，说明已经跨天 → **自动重置为 0**
3. 检查 `已质押 + 本次质押 ≤ 50,000`，不满足则 revert
4. 通过检查后累加 `dailyStakedAmount`

### 3.2 `_getCurrentPeriodStart()` 详解 (L1173-L1182)

```solidity
function _getCurrentPeriodStart() internal view returns (uint256) {
    // 计算"今天 UTC 06:00"的时间戳
    uint256 todayResetTime = (block.timestamp / SECONDS_PER_DAY) * SECONDS_PER_DAY
                             + DAILY_RESET_HOUR_UTC * SECONDS_PER_HOUR;

    // 如果当前时间还没到今天的 06:00，则当前周期属于"昨天的 06:00"
    if (block.timestamp < todayResetTime) {
        return todayResetTime - SECONDS_PER_DAY;
    }
    // 否则当前周期属于"今天的 06:00"
    return todayResetTime;
}
```

**计算逻辑举例:**

假设当前 `block.timestamp` 对应 UTC 时间 2025-01-15 10:30:

1. `todayResetTime` = `2025-01-15 00:00 UTC` + `6 * 3600` = `2025-01-15 06:00 UTC`
2. `10:30 > 06:00` → 返回 `2025-01-15 06:00 UTC`
3. 当前周期: `2025-01-15 06:00 UTC` ~ `2025-01-16 06:00 UTC`

假设当前 `block.timestamp` 对应 UTC 时间 2025-01-15 03:00:

1. `todayResetTime` = `2025-01-15 06:00 UTC`
2. `03:00 < 06:00` → 返回 `2025-01-14 06:00 UTC`
3. 当前周期: `2025-01-14 06:00 UTC` ~ `2025-01-15 06:00 UTC`

## 四、重置机制

### 4.1 重置类型: 惰性重置 (Lazy Reset)

- **不是**定时任务或 cron job
- **不是**管理员手动触发
- 而是在下一次有人调用 `stake()` 时，自动检测是否跨天并重置

### 4.2 重置时间点

| 时区 | 重置时间 |
|------|----------|
| UTC | **06:00** |
| 北京时间 (UTC+8) | **14:00** |

### 4.3 重置条件

```
dailyPeriodStart < _getCurrentPeriodStart()
```

即: 存储的周期起点 < 当前应该的周期起点 → 说明跨天了 → 重置

### 4.4 重置后状态

- `dailyPeriodStart` 更新为当前周期起点
- `dailyStakedAmount` 归零为 0

## 五、查询函数

合约提供三个 view 函数用于前端查询:

### 5.1 剩余额度 `getDailyStakeRemaining()` (L692-L704)

```solidity
function getDailyStakeRemaining() external view returns (uint256 remaining) {
    uint256 currentPeriodStart = _getCurrentPeriodStart();
    if (dailyPeriodStart < currentPeriodStart) {
        return DAILY_NETWORK_STAKE_LIMIT;   // 新周期，满额 50,000
    }
    if (dailyStakedAmount >= DAILY_NETWORK_STAKE_LIMIT) {
        return 0;                           // 已用完
    }
    return DAILY_NETWORK_STAKE_LIMIT - dailyStakedAmount;
}
```

### 5.2 已使用额度 `getDailyStakeUsed()` (L706-L714)

```solidity
function getDailyStakeUsed() external view returns (uint256 used) {
    uint256 currentPeriodStart = _getCurrentPeriodStart();
    if (dailyPeriodStart < currentPeriodStart) {
        return 0;                           // 新周期，已用为 0
    }
    return dailyStakedAmount;
}
```

### 5.3 下次重置时间 `getNextDailyResetTime()` (L716-L719)

```solidity
function getNextDailyResetTime() external view returns (uint256 nextReset) {
    return _getCurrentPeriodStart() + SECONDS_PER_DAY;
}
```

## 六、与其他限制的关系

`stake()` 函数中存在多层限制，每日限额是其中之一:

```
stake() 的限制检查顺序:
│
├── _validateStakeParameters()         // L269
│   ├── 最小质押: _amount >= 100 USDX              (MIN_STAKE_AMOUNT, L64)
│   ├── 最大单笔: _amount <= maxStakeAmount()       (受池子容量限制)
│   ├── 档位合法: _stakeIndex <= 4                  (MAX_STAKE_INDEX, L68)
│   └── 用户总量: 用户已质押 + _amount <= 10,000 USDX  (MAX_USER_TOTAL_STAKE, L66)
│
├── _checkAndUpdateDailyLimit()        // L272
│   └── 全网日限额: dailyStakedAmount + _amount <= 50,000 USDX
│
└── 7天档位限制 (仅 stakeIndex==0)     // L275-278
    └── 每个用户只能用一次 7 天档位
```

### 池子容量限制 vs 每日限额

| 维度 | 池子容量限制 (1分钟) | 每日限额 |
|------|---------------------|----------|
| 时间窗口 | 1 分钟滑动窗口 | 24 小时固定周期 |
| 上限 | 池子 USDX 储备的 2% | 固定 50,000 USDX |
| 计算方式 | `maxStakeAmount()` (L1048) | `_checkAndUpdateDailyLimit()` (L1185) |
| 限制对象 | 单笔交易最大值 | 全网当日累计 |
| 重置方式 | 滑动窗口自动过期 | 惰性重置 (UTC 06:00) |

两个限制**独立运行、同时生效**。一笔质押必须同时满足两个条件才能成功。

## 八、关键注意点

1. **全网共享额度**: 50,000 USDX 是所有用户共享的，不是每个用户独立的
2. **惰性重置**: 如果某天 UTC 06:00 后没有人质押，计数器不会自动清零，但 view 函数会正确返回满额
3. **block.timestamp 依赖**: 周期划分依赖 `block.timestamp`，BSC 出块间隔约 3 秒，时间精度足够
4. **无管理员干预**: 重置完全自动，没有管理员手动重置的接口
5. **先检查后更新**: 采用 check-then-update 模式，先 require 再累加，防止超额
