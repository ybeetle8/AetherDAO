# 社区待领取收益功能调查报告

## 结论

**合约中不存在"社区待领取收益"的查询接口。** 社区收益（团队奖励）在触发时立即转账给用户，没有"待领取"状态，因此合约也没有提供对应的 view 函数供前端查询。

---

## 调查详情

### 1. 社区收益的产生机制

社区收益在以下两个场景中产生：

- **`unstake()`** — 用户赎回质押时（`StakingBase.sol:286-358`）
- **`withdrawInterest()`** — 用户提前提取利息时（`StakingBase.sol:368-460`）

这两个函数都会调用 `_distributeTeamReward()` 将利息的一部分（最高 35%）分配给推荐链上的上级。

### 2. 社区收益的分配方式：即时转账

关键代码在 `_distributeHybridRewards()`（`StakingBase.sol:1448-1526`）：

```solidity
// 第 1493 行：立即 transfer 给推荐人
IERC20(USDX).transfer(referralChain[i], memberReward);

// 第 1497 行：累加已领取记录
totalClaimedCommunityReward[referralChain[i]] += memberReward;
```

**社区收益在产生的同一笔交易中就直接转入了推荐人的钱包**，不存在"暂存在合约中等待用户来领取"的中间状态。

### 3. 合约中与社区收益相关的查询接口

| 函数 | 返回值 | 说明 |
|------|--------|------|
| `getUserRewardSummary(user)` | `(stakingReward, communityReward)` | 返回**已领取**的累计值 |
| `totalClaimedCommunityReward[user]` | `uint256` | public mapping，直接读取已领取累计值 |

这两个接口返回的都是**历史累计已到账金额**，不是"待领取"金额。

### 4. 与质押收益的对比

| 维度 | 质押收益（Staking Reward） | 社区收益（Community Reward） |
|------|--------------------------|---------------------------|
| 是否有待领取状态 | **有** — 利息在合约中持续增长，用户主动调用才能领取 | **没有** — 产生即到账 |
| 待领取查询函数 | `getAvailableInterest(user, stakeIndex)` | **不存在** |
| 已领取查询函数 | `totalClaimedStakingReward[user]` | `totalClaimedCommunityReward[user]` |
| 汇总查询 | `getUserRewardSummary()` → stakingReward | `getUserRewardSummary()` → communityReward |
| 触发方式 | 用户主动调用 `unstake()` 或 `withdrawInterest()` | 被动触发 — 下级提息/赎回时自动到账 |

### 5. LP 质押的对比参考

LP 质押合约（`LiquidityStakingBase.sol`）采用了不同的设计模式：

```solidity
// LP 质押有 pending 概念
mapping(address => uint256) public userPendingRewards;

// 有专门的查询函数
function getUserStakeInfo(address account) → pendingReward
```

LP 质押中奖励是按秒累积的，用户需要主动调用 `claimReward()` 来领取，所以存在"待领取"状态。但 **USDT 质押的社区收益不采用这种模式**。

## 社区收益的完整计算与发放流程

社区收益没有"待领取"状态，因为它不是独立触发的——它寄生在下级用户的 `unstake()` / `withdrawInterest()` 交易中，作为手续费的一部分被实时计算、实时转账。

### 触发入口

下级用户（假设叫 UserA）调用以下任意一个函数时，会触发社区收益分配：

```
UserA 调用 unstake(stakeIndex)
UserA 调用 withdrawInterest(stakeIndex)
```

### 完整流程（以 `withdrawInterest` 为例）

```
UserA 调用 withdrawInterest(stakeIndex)
│
│ ① 计算利息
│   totalCurrentValue = _calculateStakeReward(stakeRecord)
│   // 复利公式: 本金 × (1 + 日利率)^天数
│   totalInterest = totalCurrentValue - 本金
│   availableInterest = totalInterest - 已提取利息
│
│ ② 将利息从 AE 兑换为 USDX
│   _swapAEForReward(availableInterest)
│   // 从合约的 AE 储备中卖出 AE，换回 USDX
│   // 得到 usdxReceived（实际换到的 USDX 金额）
│
│ ③ 从 usdxReceived 中扣除教育基金（5%）
│   educationFund = usdxReceived × 5 / 100
│   // 直接 transfer 给 educationFundAddress
│
│ ④ 从 usdxReceived 中扣除团队奖励（最高 35%）    ← 社区收益在这里产生
│   teamFee = _distributeTeamReward(referralChain, usdxReceived)
│   │
│   │ ④-a 计算团队奖励池总额
│   │     teamRewardPool = usdxReceived × 35 / 100
│   │
│   │ ④-b 获取 UserA 的推荐链（向上最多 30 级）
│   │     referralChain = [直接推荐人, 推荐人的推荐人, ..., rootAddress]
│   │
│   │ ④-c 计算推荐链上每个人的等级
│   │     对每个上级调用 _getUserTier()：
│   │       tier = min(团队KPI等级, 个人质押等级)
│   │       // 团队KPI等级: 由 getTeamKpi() 决定
│   │       // 个人质押等级: 由 currentStakeValue() 决定
│   │
│   │ ④-d 按差额制分配（_distributeHybridRewards）
│   │     遍历推荐链，从近到远：
│   │     ┌─────────────────────────────────────────────────┐
│   │     │ cumulativeAllocatedRate = 0                      │
│   │     │                                                  │
│   │     │ for 推荐链中每个上级:                              │
│   │     │   tierRate = 该上级的等级对应比例 (如 V3=11%)       │
│   │     │   actualRate = tierRate - cumulativeAllocatedRate │
│   │     │                                                  │
│   │     │   if actualRate > 0:                             │
│   │     │     reward = usdxReceived × actualRate / 100     │
│   │     │     transfer(该上级, reward)  ← 立即到账           │
│   │     │     cumulativeAllocatedRate = tierRate            │
│   │     └─────────────────────────────────────────────────┘
│   │
│   │ ④-e 如果推荐链上没人吃满 35%，剩余部分转给 rootAddress
│   │     remaining = teamRewardPool - totalDistributed
│   │     transfer(rootAddress, remaining)
│   │
│   └─→ 返回 teamFee（总计扣除的团队奖励金额）
│
│ ⑤ 计算 UserA 实际到手
│   userPayout = usdxReceived - educationFund - teamFee
│   userPayout -= userPayout × 赎回费率 / 10000   // 赎回手续费
│   transfer(UserA, userPayout)
│
└─→ 完成
```

### 差额制分配举例

假设 UserA 提取利息，`usdxReceived = 1000 USDX`，推荐链如下：

| 推荐链位置 | 地址 | 等级 | 等级比例 |
|-----------|------|------|---------|
| 直接上级 | Bob | V1 | 3% |
| Bob 的上级 | Carol | V0 | 0% |
| Carol 的上级 | Dave | V5 | 19% |
| ... | ... | ... | ... |

分配过程：

1. **Bob (V1, 3%)**：actualRate = 3% - 0% = 3% → 获得 1000 × 3% = **30 USDX**，累计已分配比例 = 3%
2. **Carol (V0, 0%)**：等级为 0，跳过
3. **Dave (V5, 19%)**：actualRate = 19% - 3% = 16% → 获得 1000 × 16% = **160 USDX**，累计已分配比例 = 19%
4. **剩余**：35% - 19% = 16% → 1000 × 16% = **160 USDX** 转给 rootAddress

每一笔都是在这笔交易中**立即 `transfer` 到对应地址**，没有暂存。

### 为什么无法提前计算"待领取社区收益"

社区收益金额取决于以下变量，这些变量在下级实际操作之前都是不确定的：

| 不确定因素 | 说明 |
|-----------|------|
| 下级何时操作 | 利息是复利累积的，提取时间不同金额不同 |
| AE/USDX 兑换率 | 利息需要卖 AE 换 USDX，价格实时变动 |
| 推荐链上其他人的等级 | 其他上级的等级可能随时变化（质押/赎回改变个人等级、团队变化改变 KPI 等级），影响差额制分配 |
| 下级选择的操作 | `unstake` 和 `withdrawInterest` 的计算基数不同 |

因此合约中不存在也无法准确计算"社区待领取收益"。

## 质押收益累计值（totalClaimedStakingReward）的计算流程

`getUserRewardSummary()` 返回的 `stakingReward` 来自 `totalClaimedStakingReward[user]`，这个值在两个地方被累加，分别是 `unstake()` 和 `withdrawInterest()`。

### 累加时机与金额

```solidity
// StakingBase.sol:193 — 状态变量定义
mapping(address => uint256) public totalClaimedStakingReward;
```

**写入点只有两个：**

| 写入位置 | 行号 | 累加的值 |
|---------|------|---------|
| `unstake()` | 351 | `userPayout`（本金 + 净利息） |
| `withdrawInterest()` | 440 | `userPayout`（净利息，不含本金） |

### unstake 流程中的 userPayout 计算

```
unstake(stakeIndex)
│
│ calculatedReward = _calculateStakeReward()      // 复利: 本金×(1+日利率)^天数
│ _burn(stakeIndex)                                // 销毁 sAE 凭证
│ usdxReceived = _swapAEForReward(calculatedReward) // 卖 AE 换 USDX
│
│ interestEarned = usdxReceived - principalAmount   // 利息 = 总额 - 本金
│
│ educationFund = interestEarned × 5 / 100          // 教育基金: 利息的 5%
│ teamFee = interestEarned × ≤35 / 100              // 团队奖励: 利息的 ≤35%
│   ↑ 注意: 教育基金和团队奖励的计算基数是 interestEarned（纯利息）
│
│ userPayout = usdxReceived - educationFund - teamFee
│   ↑ 但 userPayout 的起点是 usdxReceived（包含本金）
│
│ userPayout -= userPayout × 500 / 10000             // 赎回手续费 5%
│
│ totalClaimedStakingReward[user] += userPayout      // ← 累加（含本金）
│ transfer(user, userPayout)
```

**关键点**：`unstake` 时累加的 `userPayout` **包含本金**，因为 `usdxReceived` 包含了本金部分，而教育基金和团队奖励只从利息中扣。

### withdrawInterest 流程中的 userPayout 计算

```
withdrawInterest(stakeIndex)
│
│ totalCurrentValue = _calculateStakeReward()
│ totalInterest = totalCurrentValue - principalAmount
│ availableInterest = totalInterest - withdrawnInterest[user][stakeIndex]
│
│ usdxReceived = _swapAEForReward(availableInterest)  // 只兑换利息部分
│   ↑ 这里没有本金，只换了可提取的利息
│
│ educationFund = usdxReceived × 5 / 100
│ teamFee = usdxReceived × ≤35 / 100
│
│ userPayout = usdxReceived - educationFund - teamFee
│
│ userPayout -= userPayout × 500 / 10000              // 赎回手续费 5%
│
│ totalClaimedStakingReward[user] += userPayout       // ← 累加（纯利息净额）
│ transfer(user, userPayout)
```

**关键点**：`withdrawInterest` 时累加的 `userPayout` **不含本金**，因为本金没有动，仍留在质押中。

### 数值举例

假设用户质押 1000 USDX，30 天到期，复利产生利息 300 USDX。

**场景 A：到期后直接 unstake**

```
usdxReceived     = 1300 USDX（本金 1000 + 利息 300）
interestEarned   = 300 USDX
educationFund    = 300 × 5%  = 15 USDX
teamFee          = 300 × 35% = 105 USDX（假设推荐链吃满）
userPayout       = 1300 - 15 - 105 = 1180 USDX
赎回手续费        = 1180 × 5% = 59 USDX
最终 userPayout   = 1180 - 59 = 1121 USDX

totalClaimedStakingReward += 1121   ← 包含本金
```

**场景 B：质押期间先 withdrawInterest，到期后再 unstake**

第 15 天提取利息（假设此时利息 = 140 USDX）：
```
usdxReceived     = 140 USDX（纯利息）
educationFund    = 140 × 5%  = 7 USDX
teamFee          = 140 × 35% = 49 USDX
userPayout       = 140 - 7 - 49 = 84 USDX
赎回手续费        = 84 × 5% = 4.2 USDX
最终 userPayout   = 79.8 USDX

totalClaimedStakingReward += 79.8   ← 只有利息
```

第 30 天赎回（剩余利息 = 300 - 140 = 160 USDX）：
```
usdxReceived     = 1160 USDX（本金 1000 + 剩余利息 160）
interestEarned   = 160 USDX
educationFund    = 160 × 5%  = 8 USDX
teamFee          = 160 × 35% = 56 USDX
userPayout       = 1160 - 8 - 56 = 1096 USDX
赎回手续费        = 1096 × 5% = 54.8 USDX
最终 userPayout   = 1041.2 USDX

totalClaimedStakingReward += 1041.2  ← 包含本金
```

两次累计：`totalClaimedStakingReward = 79.8 + 1041.2 = 1121 USDX`

### 前端调用方式

```javascript
// 方式一：通过汇总函数
const [stakingReward, communityReward] = await staking.getUserRewardSummary(userAddress);
// stakingReward = totalClaimedStakingReward[user]

// 方式二：直接读取 public mapping
const stakingReward = await staking.totalClaimedStakingReward(userAddress);
```

### 注意事项

| 项目 | 说明 |
|------|------|
| stakingReward 包含本金吗 | **包含** — unstake 时的 userPayout 包含本金 |
| stakingReward 是净额吗 | **是** — 已扣除教育基金、团队奖励、赎回手续费 |
| 何时更新 | 仅在 `unstake()` 或 `withdrawInterest()` 执行成功后 |
| 是否有对应的"待领取"值 | 质押利息的待领取可通过 `getAvailableInterest(user, stakeIndex)` 查，但这是**扣费前**的毛利息 |

## 前端影响分析

### 当前可用的数据

前端目前可以展示：

```javascript
// 已领取的社区收益累计值
const [stakingReward, communityReward] = await staking.getUserRewardSummary(userAddress);
// communityReward = 用户作为推荐人历史累计获得的团队奖励总额（已到账）
```

### 缺失的数据

前端**无法**展示：

- 社区待领取收益（因为不存在这个概念）
- 下级当前有多少未提取利息可能给自己带来多少团队奖励（无法预估）

### 如果需要"社区待领取收益"功能

由于社区收益的产生完全依赖于下级用户的 `unstake()` / `withdrawInterest()` 操作，在这些操作发生之前，无法确定具体金额（受 AE/USDT 价格、下级提取时机等因素影响）。

如果业务上确实需要一个"预估社区待收益"的功能，需要新增合约逻辑：

1. 遍历用户所有下级的活跃质押
2. 计算每个下级当前的未提取利息
3. 按差额制计算该用户在每笔利息中应得的团队奖励比例
4. 汇总得到预估值

这个计算非常复杂且 gas 消耗巨大，可能不适合在链上实现，更适合通过链下索引服务（如 subgraph）来计算。

## getUserRewardSummary 返回值精确分析

```solidity
function getUserRewardSummary(address user) external view returns (
    uint256 stakingReward,
    uint256 communityReward
) {
    stakingReward = totalClaimedStakingReward[user];    // ← 第 577 行
    communityReward = totalClaimedCommunityReward[user]; // ← 第 578 行
}
```

### stakingReward — 不是"质押利息总和"

**stakingReward 不是纯利息总和，而是用户从 unstake/withdrawInterest 实际收到的 USDX 净额累计。**

它累加的是 `userPayout`，这个值的含义因操作不同而不同：

| 操作 | userPayout 包含什么 | 代码位置 |
|------|-------------------|---------|
| `unstake()` | 本金 + 利息 - 教育基金(5%) - 团队奖励(≤35%) - 赎回费(5%) | 第 351 行 |
| `withdrawInterest()` | 利息 - 教育基金(5%) - 团队奖励(≤35%) - 赎回费(5%) | 第 440 行 |

**所以 stakingReward：**
- **包含本金**（unstake 时退还的本金也算在里面）
- **已扣除所有手续费**（是净到账金额）
- **不是**纯利息的总和
- 更准确的理解是：**用户从质押系统累计收到的所有 USDX 转账之和**

### communityReward — 是团队奖励总和

**communityReward 是用户作为推荐人获得的团队奖励净到账总和。** 这个值的语义比较准确。

它在三个地方被累加（都在 `_distributeTeamReward` 调用链中）：

| 场景 | 累加值 | 代码位置 |
|------|-------|---------|
| 推荐链为空，全额转给 rootAddress | `fee`（利息 × 35%） | 第 1387 行 |
| 差额制分配中，某个上级获得奖励 | `memberReward`（差额部分） | 第 1497 行 |
| 分配完后有剩余，兜底转给 rootAddress | `marketingAmount`（未分完的部分） | 第 1431 行 |

**所以 communityReward：**
- **不包含本金**（纯粹是从下级利息中获得的团队奖励）
- **是净到账金额**（转了多少就记多少，没有额外扣费）
- **只有当下级执行 unstake/withdrawInterest 时才会增加**
- 准确理解就是：**用户作为推荐人/团队领导人，从下级提息赎回手续费中分到的 USDX 总和**

### 对比总结

| 维度 | stakingReward | communityReward |
|------|--------------|----------------|
| 含义 | 用户从质押系统收到的 USDX 总和 | 用户作为推荐人收到的团队奖励总和 |
| 包含本金 | **是**（unstake 时包含） | **否** |
| 已扣手续费 | **是**（扣除了教育基金+团队奖励+赎回费） | **不适用**（本身就是手续费分配的一部分） |
| 是否等于"利息总和" | **不是**（混入了本金） | **不适用** |
| 是否等于"团队奖励总和" | **不适用** | **是** |
| 谁触发增长 | 用户自己（unstake/withdrawInterest） | 用户的下级（下级的 unstake/withdrawInterest） |
| 能否体现"赚了多少" | **不能直接体现** — 需要减去历史投入本金才是真正利润 | **可以** — 全部是净利润 |

### 前端展示建议

如果前端需要展示"质押利息总和"，仅靠 `stakingReward` 是不够的，因为它混入了本金。要获得纯利息累计，需要：

```
纯利息累计 = stakingReward - 用户历史投入本金总和
```

但合约中**没有**存储"用户历史投入本金总和"这个值。虽然每次 unstake 会记录 `principalAmount` 到 `WithdrawalRecord` 中，但需要遍历所有赎回记录求和，且不包括仍在质押中的本金。

可行的前端方案：
```javascript
// 获取所有赎回记录
const history = await staking.getWithdrawalHistory(userAddress);
// 累加所有赎回记录中的 principalAmount
let totalPrincipalReturned = 0n;
for (const record of history) {
    totalPrincipalReturned += record.principalAmount;
}
// 纯利息 = stakingReward - 已退还的本金
const [stakingReward] = await staking.getUserRewardSummary(userAddress);
const pureInterest = stakingReward - totalPrincipalReturned;
```

## 总结

| 项目 | 状态 |
|------|------|
| 社区收益是否即时到账 | 是，产生即转账 |
| 是否存在"待领取"状态 | 否 |
| 合约是否有待领取查询接口 | 否 |
| 前端是否能查询待领取社区收益 | 否 |
| `stakingReward` 是质押利息总和吗 | **不是** — 包含本金，是用户收到的 USDX 净额累计 |
| `communityReward` 是团队奖励总和吗 | **是** — 纯粹的团队奖励净到账累计 |
| 如何算出纯利息 | `stakingReward` - 赎回记录中 `principalAmount` 之和 |
