# 时间跳转脚本设计文档

## 1. 背景与需求

AetherDAO 质押系统有 5 个质押等级，锁仓时间从 7 天到 365 天不等：

| 等级 | 锁仓时间 | 日利率 |
|------|---------|--------|
| 0    | 7 天    | 0.6%   |
| 1    | 30 天   | 0.9%   |
| 2    | 90 天   | 1.1%   |
| 3    | 180 天  | 1.5%   |
| 4    | 365 天  | 2.0%   |

在本地测试环境中，等待真实时间流逝不现实。需要一个**时间跳转脚本**，利用 Hardhat 的 EVM 时间操作能力，快速推进区块链时间，以便测试质押到期、利息计算、赎回等场景。

## 2. 核心原理

Hardhat 本地节点提供以下 RPC 方法来操控 EVM 时间：

| RPC 方法 | 作用 |
|----------|------|
| `evm_increaseTime` | 将 EVM 时间向前推进指定秒数 |
| `evm_mine` | 强制出一个新区块（使时间变更生效） |
| `evm_snapshot` | 创建当前状态的快照，返回快照 ID |
| `evm_revert` | 回滚到指定快照 ID 的状态 |

**关键点**：`evm_increaseTime` 只改变下一个区块的时间戳，必须配合 `evm_mine` 才能生效。

## 3. 脚本设计

### 3.1 文件位置

```
scripts/timeTravel.js
```

### 3.2 使用方式

通过环境变量控制行为（Hardhat `run` 命令不支持 `--` 传递自定义参数）：

```bash
# 跳转天数
DAYS=7 npx hardhat run scripts/timeTravel.js --network localhost

# 跳转小时
HOURS=12 npx hardhat run scripts/timeTravel.js --network localhost

# 跳转秒数
SECONDS=3600 npx hardhat run scripts/timeTravel.js --network localhost

# 按质押等级跳转
TIER=1 npx hardhat run scripts/timeTravel.js --network localhost

# 查看当前时间
QUERY=1 npx hardhat run scripts/timeTravel.js --network localhost

# 创建快照
SNAPSHOT=1 npx hardhat run scripts/timeTravel.js --network localhost

# 回滚快照
REVERT=0x1 npx hardhat run scripts/timeTravel.js --network localhost
```

### 3.3 功能模块

#### A. 时间跳转

```javascript
async function advanceTime(seconds) {
  await hre.network.provider.send("evm_increaseTime", [seconds]);
  await hre.network.provider.send("evm_mine");
}
```

#### B. 时间查询

读取当前区块的 timestamp，转换为可读的日期时间格式显示。同时显示与 BSC fork 起始时间的偏移量。

#### C. 快照管理

创建快照前显示当前时间，保存快照 ID 到本地文件（`timetravel-snapshots.json`），方便后续回滚。

#### D. 质押状态查询（可选增强）

跳转时间后，自动查询质押合约中的状态变化：
- 读取 `ae-deployment.json` 获取合约地址
- 调用 `getUserStakeRecords()` 显示用户质押记录的到期状态
- 调用 `getDailyStakeRemaining()` 显示每日质押额度重置情况

### 3.4 输出格式

脚本执行后输出信息示例：


## 4. 注意事项

1. **仅限本地网络**：脚本只能在 Hardhat 本地节点（`localhost` / `hardhat`）上使用，BSC 主网和测试网不支持 `evm_increaseTime`。
2. **不可逆操作**：时间跳转后无法后退（除非使用快照回滚），建议操作前先创建快照。
3. **每日限额重置**：跳转时间后，`DAILY_NETWORK_STAKE_LIMIT` 会随之重置（UTC 06:00 为界）。
4. **复利计算**：时间跳转影响 `_calculateStakeReward()` 的 `compoundPeriods` 计算，可用于验证利息精度。
5. **累积跳转**：多次执行脚本会累积时间偏移，不是覆盖。例如先跳 7 天，再跳 30 天，总共偏移 37 天。
6. **节点重启**：重启 Hardhat 节点后时间重置为 fork 区块的时间，之前的跳转全部失效。

## 5. 典型使用场景

### 场景 1: 测试 30 天质押到期赎回

```bash
# 1. 部署合约
npx hardhat run scripts/deployAE.js --network localhost

# 2. 执行质押操作（通过测试脚本或手动操作）

# 3. 跳转 30 天
TIER=1 npx hardhat run scripts/timeTravel.js --network localhost

# 4. 测试赎回
npx hardhat run scripts/testAE.js --network localhost
```

### 场景 2: 验证复利计算精度

```bash
# 1. 质押 500 USDX 到 30 天池

# 2. 每天跳转 1 天，每次查询利息变化
DAYS=1 npx hardhat run scripts/timeTravel.js --network localhost
# 重复 30 次，观察复利增长曲线
```

### 场景 3: 测试每日限额重置

```bash
# 1. 质押达到每日限额 50,000 USDX

# 2. 跳转到下一个 UTC 06:00
HOURS=24 npx hardhat run scripts/timeTravel.js --network localhost

# 3. 验证限额已重置
QUERY=1 npx hardhat run scripts/timeTravel.js --network localhost
```

### 场景 4: 安全回滚测试

```bash
# 1. 创建快照
SNAPSHOT=1 npx hardhat run scripts/timeTravel.js --network localhost
# 输出: 快照 ID = 0x1

# 2. 执行各种操作和时间跳转...

# 3. 回滚到快照
REVERT=0x1 npx hardhat run scripts/timeTravel.js --network localhost
```

## 6. 实现要点

1. **环境变量解析**：通过 `process.env` 读取 `DAYS`、`HOURS`、`SECONDS`、`TIER`、`QUERY`、`SNAPSHOT`、`REVERT` 等参数。
2. **参数互斥**：同时指定多个操作时取优先级：`REVERT` > `SNAPSHOT` > `QUERY` > `TIER` > `DAYS` > `HOURS` > `SECONDS`。
3. **安全检查**：检测当前网络是否为本地节点，非本地网络拒绝执行。
4. **复用现有代码**：引用 `test/helpers/time.js` 中的核心函数或直接内联实现（脚本独立运行，不依赖 test 目录）。
5. **快照持久化**：将快照 ID 保存到 `timetravel-snapshots.json`，带时间戳和描述信息。
