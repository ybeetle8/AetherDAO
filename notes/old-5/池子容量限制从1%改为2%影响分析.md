# 池子容量限制从 1% 改为 2% 的影响分析

## 修改内容

将 `POOL_PERCENTAGE_DIVISOR` 从 `100`（1%）改为 `50`（2%），即：

```solidity
// 修改前
uint256 internal constant POOL_PERCENTAGE_DIVISOR = 100;  // 1% of pool

// 修改后
uint256 internal constant POOL_PERCENTAGE_DIVISOR = 50;   // 2% of pool
```

## 直接影响：maxStakeAmount 返回值翻倍

以当前池子约 60,000 USDX 为例：

| 项目 | 1%（当前） | 2%（修改后） |
|------|-----------|-------------|
| 池子百分比额度 | 600 | 1,200 |
| MAX_STAKE_LIMIT 硬上限 | 1,000 | 1,000 |
| **实际 maxStakeAmount** | **600** | **1,000** ← 达到硬上限 |

修改后当前池子规模下就能返回 1,000，达到预期。

### 不同池子规模对比

| 池子 USDX 储备 | 1% 时返回值 | 2% 时返回值 | 变化 |
|----------------|-----------|-----------|------|
| 30,000 | 300 | 600 | +100% |
| 40,000 | 400 | 800 | +100% |
| 50,000 | 500 | **1,000** | 达到硬上限 |
| 60,000 | 600 | **1,000** | 达到硬上限 |
| 80,000 | 800 | **1,000** | 达到硬上限 |
| 100,000 | **1,000** | **1,000** | 两者均达上限 |

**结论**：2% 方案下，池子只需 50,000 USDX 就能让 maxStakeAmount 达到 1,000 的硬上限，而 1% 需要 100,000 USDX。

## 风险分析

### 1. 价格冲击（Price Impact）— 中等风险

质押时会将一半 USDX swap 为 AE（见 `_swapAndAddLiquidity`）：

```
质押 1,000 USDX → 500 USDX 去 swap 买 AE → 500 USDX + AE 注入流动性
```

在 60,000 USDX 的池子中 swap 500 USDX：

| 场景 | swap 金额 | 占池子比例 | 预估价格冲击 |
|------|----------|-----------|-------------|
| 1% 上限（600 USDX 质押） | 300 USDX | 0.5% | ~0.5% |
| 2% 上限（1,000 USDX 质押） | 500 USDX | 0.83% | ~0.84% |
| 2% 上限（1,200 USDX 质押，池子仅30k时） | 600 USDX | 2.0% | ~2.0% |

**价格冲击增加有限**。在当前 60,000 USDX 池子中，单笔 swap 从 300→500 USDX，价格冲击从 ~0.5% 上升到 ~0.84%，属于可接受范围。

但注意：池子较小时（如 30,000 USDX），2% 允许单笔质押 600 USDX，swap 300 占池子 1%，冲击略有增加但仍在合理范围。

### 2. 1 分钟窗口内的累积风险 — 低风险

`getRecentNetworkInflow()` 检查最近 1 分钟的累积流入。改为 2% 后：

```
1分钟内最大累积质押 = 2% of pool
```

以 60,000 USDX 池子为例：
- 1% 方案：1 分钟内最多质押 600 USDX（可能是 1 笔 600 或多笔累计 600）
- 2% 方案：1 分钟内最多质押 1,200 USDX（可能是 1 笔 1,000 + 1 笔 200，或其他组合）

**这意味着 1 分钟内的最大总流入从池子的 1% 上升到 2%。** 这是主要的风险点——不仅单笔变大，短时间内的累积上限也翻倍了。

不过考虑到还有每日 50,000 USDX 的全网限制，1 分钟窗口的增加不会对全天总量造成质变。

### 3. 三明治攻击（Sandwich Attack）— 低风险

合约已有滑点保护机制：

```solidity
BASE_SLIPPAGE_TOLERANCE = 1500;        // 15% 基础滑点容忍
MAX_SLIPPAGE_TOLERANCE = 2000;         // 20% 最大滑点容忍
PRICE_IMPACT_THRESHOLD = 200;          // 2% 价格影响阈值
ADD_LIQUIDITY_SLIPPAGE_TOLERANCE = 500; // 5% 添加流动性滑点
```

单笔 swap 从 300→500 USDX，三明治攻击的利润空间增加有限，现有滑点保护足以应对。

### 4. 与其他限制的协同 — 无冲突

| 限制机制 | 值 | 与 2% 是否冲突 |
|---------|-----|---------------|
| MIN_STAKE_AMOUNT | 100 USDX | 无关 |
| MAX_STAKE_LIMIT | 1,000 USDX | 仍然是硬上限，2% 不会突破 |
| MAX_USER_TOTAL_STAKE | 10,000 USDX | 无关，这是用户累计上限 |
| DAILY_NETWORK_STAKE_LIMIT | 50,000 USDX/天 | 无关，每日总量不变 |
| NETWORK_CHECK_INTERVAL | 1 分钟 | 1 分钟窗口上限从 1%→2%，见上文分析 |
| onlyEOA | 仅 EOA 可质押 | 无关 |

**不存在结构性冲突。** MAX_STAKE_LIMIT 1,000 仍然是最终兜底，2% 只是让池子容量限制更宽松。

### 5. 对流动性池健康度的影响 — 可接受

质押流程是 swap + 添加流动性，所以质押实际上是在**增加**池子深度：

```
质押 1,000 USDX → swap 500 买 AE → 添加 (500 USDX + AE) 到流动性池
```

质押本身不是在"抽取"流动性，而是在"注入"流动性（虽然 LP token 发送到了 address(0) 永久锁定）。swap 环节会短暂消耗池子深度，但随后的 addLiquidity 会补充回来。所以 2% 的限制对池子健康度的影响是暂时的、自愈的。

## 极端场景推演

### 场景 A：小池子 + 高频质押（最不利情况）

假设池子 30,000 USDX，2% = 600 USDX：

```
T=0s：用户A 质押 600 → swap 300 (占池子1%) → 价格冲击 ~1%
T=61s：用户B 质押 600 → swap 300 → 价格冲击 ~1%（窗口已重置）
T=122s：用户C 质押 600 → ...
```

每分钟最多一笔 600 USDX 的质押，每笔价格冲击约 1%。**可接受**，且每次添加流动性后池子在变大，后续冲击会递减。

### 场景 B：当前池子 + 正常使用

池子 60,000 USDX，2% = 1,200 USDX，但被 MAX_STAKE_LIMIT=1000 限制：

```
T=0s：用户A 质押 1,000 → swap 500 (占池子0.83%) → 价格冲击 ~0.84%
（1分钟内剩余额度：1,200 - 1,000 = 200）
T=30s：用户B 可以质押 200（或等到下一分钟质押更多）
T=61s：窗口重置，用户B 可以质押 1,000
```

**完全可控**，体验良好。

## 总结与建议

| 评估维度 | 结论 |
|---------|------|
| **功能目标** | 达成。当前池子规模下 maxStakeAmount 可以返回 1,000 |
| **价格冲击** | 增加有限（0.5% → 0.84%），可接受 |
| **1分钟窗口累积** | 上限翻倍，但有每日总量兜底，风险可控 |
| **三明治攻击** | 现有滑点保护足够，无需额外措施 |
| **系统兼容性** | 与其他限制机制无冲突 |
| **池子健康** | 质押是注入流动性，影响是暂时的、自愈的 |

**总体评估：改为 2% 风险可控，影响不大。** 核心原因是 MAX_STAKE_LIMIT=1000 的硬上限仍然存在，2% 只是放宽了池子容量这一层约束，不会导致无限制的大额质押。在当前池子规模（~60,000 USDX）下，这是一个合理的调整。

唯一需要留意的是：如果未来池子缩小到很小（例如 10,000 USDX），2% = 200 USDX，此时单笔 swap 100 占池子 1%，冲击也在可接受范围。不过建议关注池子跌破 25,000 USDX 的情况（2% = 500，swap 250 占池子 1%）。
