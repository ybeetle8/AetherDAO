# AE 项目方无法撤回 PancakeSwap 流动性的原因分析

## 问题描述

项目方在 PancakeSwap 上手动添加了 AE/USDC 流动性，现在尝试撤回时交易失败，无法撤回。

---

## 原因

**撤流动性操作被合约的"预售期禁止买入"机制误拦截了。**

### 详细解释

AE 合约中有一个预售保护机制：在预售期间（部署后 30 天内），禁止任何人从 PancakeSwap 买入 AE。这个机制的目的是防止预售期间有人抢跑买入。

问题在于：**合约判断"买入"的逻辑过于宽泛，把"撤流动性"也当成了"买入"。**

### 为什么撤流动性会被当成买入？

当用户在 PancakeSwap 上撤流动性时，底层发生的事情是：

1. PancakeSwap 的 Pair 合约将 AE 代币从池子转给用户
2. 从 AE 合约的视角看：**代币从 Pair 地址转出，转到用户地址**

而合约判断"买入"的条件是（`_isBuyOperation` 函数，AEBase.sol 第 701-714 行）：

- 代币从 Pair 地址转出 ✓
- 接收者不是 Pair 本身 ✓
- 接收者不是 Router ✓
- 调用者（msg.sender）是 Pair ✓

**撤流动性完全满足这四个条件**，所以合约把它当成了一次"买入"操作。

然后进入 `_handleBuy` 函数（第 731-741 行），检测到预售期仍在进行中，直接 revert：

```solidity
if (presaleActive && block.timestamp < presaleStartTime + presaleDuration) {
    revert NotAllowedBuy();
}
```

---

## 当前状态

| 项目 | 值 |
|------|-----|
| 预售期时长 | 30 天（合约硬编码） |
| 预售开始时间 | 合约部署时 |
| 当前预售状态 | 激活中（presaleActive = true） |
| 预售期内能否撤流动性 | **不能**（被误判为买入而拦截） |

---

## 解决方案

### 方案一：关闭预售开关（立即生效）

合约 Owner 调用：

```
AE.setPresaleActive(false)
```

关闭预售后，"禁止买入"的限制解除，撤流动性操作将恢复正常。

### 方案二：等待预售期自然结束

预售期为部署后 30 天。到期后，即使 `presaleActive` 仍为 `true`，由于时间条件 `block.timestamp >= presaleStartTime + 30 days` 不再满足，限制自动失效，撤流动性将恢复。

---

## 重要确认

撤流动性能否成功，还取决于 **LP 代币是否在项目方钱包中**：

| LP 代币位置 | 能否撤回 |
|------------|---------|
| 在项目方钱包中 | 关闭预售后可以撤回 |
| 被发到零地址/死亡地址（burnLP） | 永久无法撤回 |

如果项目方是在 PancakeSwap UI 上手动添加的流动性，LP 代币默认会发到操作者自己的钱包，所以 LP 应该在项目方手中。可以在 BSCScan 上查看 Pair 合约的 LP 代币持有者列表来确认。

---

## 总结

| 问题 | 答案 |
|------|------|
| 为什么现在撤不了？ | 预售期的"禁止买入"机制把撤流动性误判为买入并拦截 |
| 是永久锁定吗？ | 不是，是预售期的临时限制 |
| 怎么解决？ | 关闭预售开关，或等 30 天预售期结束 |
| LP 代币还在吗？ | 手动添加的 LP 应该在项目方钱包中（需确认） |
