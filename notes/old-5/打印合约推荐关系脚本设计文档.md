# 打印合约推荐关系脚本设计文档

## 目标

编写脚本 `scripts/printReferralTree.js`，从本地 Staking 合约中读取当前推荐关系并以树形结构打印。

## 问题分析

### Staking 合约可用的推荐查询函数

| 函数 | 返回值 | 说明 |
|------|--------|------|
| `getRootAddress()` | `address` | 获取根地址 |
| `getReferral(address user)` | `address` | 获取用户的推荐人 |
| `isBindReferral(address user)` | `bool` | 查询用户是否已绑定推荐 |
| `getReferrals(address user, uint8 maxDepth)` | `address[]` | 获取用户的上级推荐链（向上） |
| `getReferralCount(address user)` | `uint256` | 获取用户的直接下线数量（注意：此函数不在 IStaking 接口中，但合约里有实现） |

### 核心难点：合约无法直接枚举下线地址

Staking 合约有 `_children` mapping，但**没有暴露 getChildren 函数**。`getReferralCount` 只返回数量，无法获取具体地址列表。因此不能直接从根节点 BFS 遍历整棵树。

### 解决方案：通过事件重建推荐树

绑定推荐关系时会触发事件：
- `ReferralBound(address indexed user, address indexed referrer, uint256 timestamp)`
- `AdminReferralBound(address indexed user, address indexed referrer, address indexed admin, uint256 timestamp)`

**方案：扫描合约的全部绑定事件，从中提取所有 (user, referrer) 关系对，再用合约的 `getReferral()` 逐一验证确认，最终构建树形结构打印。**

## 脚本设计

### 整体流程

```
步骤 1: 连接合约，获取根地址
步骤 2: 扫描 ReferralBound + AdminReferralBound 事件，收集所有地址
步骤 3: 对每个地址调用 getReferral() 获取当前链上推荐人（验证）
步骤 4: 构建 parent -> children 映射
步骤 5: 从根节点 BFS/DFS 打印树形结构
步骤 6: 输出统计信息
```

### 步骤详解

#### 步骤 1：连接合约

```javascript
const deployment = require("../ae-deployment.json");
const STAKING_ADDRESS = deployment.contracts.Staking;
const staking = await ethers.getContractAt("IStaking", STAKING_ADDRESS);
const rootAddress = await staking.getRootAddress();
```

#### 步骤 2：扫描事件收集地址

扫描合约从部署区块到最新区块的所有 `ReferralBound` 和 `AdminReferralBound` 事件：

```javascript
const referralFilter = staking.filters.ReferralBound();
const adminFilter = staking.filters.AdminReferralBound();

const [referralEvents, adminEvents] = await Promise.all([
  staking.queryFilter(referralFilter, 0, "latest"),
  staking.queryFilter(adminFilter, 0, "latest"),
]);
```

从事件中提取所有出现过的唯一地址（user + referrer 去重）。

#### 步骤 3：链上验证推荐关系

对每个收集到的地址调用 `getReferral(address)`，获取其当前链上实际的推荐人：

```javascript
for (const addr of allAddresses) {
  const isBound = await staking.isBindReferral(addr);
  if (isBound) {
    const referrer = await staking.getReferral(addr);
    // 记录 addr -> referrer
  }
}
```

这一步确保数据是**链上实时状态**，而非仅依赖历史事件。

#### 步骤 4：构建树形结构

```javascript
// parent -> [child1, child2, ...]
const childrenMap = new Map();

for (const [user, referrer] of referralMap) {
  if (!childrenMap.has(referrer)) childrenMap.set(referrer, []);
  childrenMap.get(referrer).push(user);
}
```

#### 步骤 5：树形打印

使用递归 DFS 打印，缩进表示层级：

```
ROOT: 0x2345...8901
├── 0xBB01...0001 (直推: 2)
│   ├── 0xCC01...0001 (直推: 2)
│   │   ├── 0xDD01...0001 (叶子)
│   │   └── 0xDD02...0002 (叶子)
│   └── 0xCC02...0002 (叶子)
├── 0xBB02...0002 (直推: 2)
│   ├── 0xCC03...0003 (直推: 1)
│   │   └── 0xDD03...0003 (叶子)
│   └── 0xCC04...0004 (叶子)
└── 0xBB03...0003 (直推: 1)
    └── 0xCC05...0005 (直推: 1)
        └── 0xDD04...0004 (叶子)
```

#### 步骤 6：输出统计

```
总用户数: 15
已绑定用户数: 14 (不含根地址)
最大深度: 4 层
各层分布: 第1层 3人, 第2层 5人, 第3层 4人, 第4层 0人
```

### getReferralCount 的使用

虽然 `getReferralCount` 不在 IStaking 接口中，但可以通过 ABI 直接调用。不过由于我们已经通过事件+`getReferral` 构建了完整的 childrenMap，可以不依赖它。仅在最终验证时作为可选的交叉校验手段。

如果需要使用，可以用合约完整 ABI 而非接口：

```javascript
const staking = await ethers.getContractAt(
  "contracts/AE-Staking/src/abstract/StakingBase.sol:StakingBase",
  STAKING_ADDRESS
);
```

## 用法

```bash
# 确保本地节点已启动并部署了合约（含已导入的推荐关系）
npx hardhat run scripts/printReferralTree.js --network localhost
```

## 注意事项

1. **本地节点限制**：localhost 环境下事件扫描范围取决于 fork 起始块和后续操作，通常事件量不大，性能无问题
2. **地址缩写**：打印时使用 `0x1234...5678` 格式缩写，保留前 6 + 后 4 位
3. **此脚本为只读操作**，不修改任何链上状态
