# [P0] 提息后解押少算一天复利问题分析

## 问题复现

1. 用户质押 1000 USDX，选择 7 天期
2. 1 天后调用 `withdrawInterest()` 提取利息
3. 再过 6 天后（到期）调用 `unstake()` 解押
4. **预期**：第二次应得 6 天的复利
5. **实际**：第二次只得到 5 天的复利

## 根因分析

问题出在 `_calculateStakeReward()` 中的**整数除法截断**（StakingBase.sol:1579）。

### 时间线推演

假设用户在 `T₀` 质押，在 `T₀ + 1天 + δ` 时提取利息（`δ` 是同一天内经过的额外秒数，哪怕只有1秒）：

```
T₀ = 质押时间 (stakeTime)
T₁ = T₀ + 86400 + δ    （提息时间，δ > 0，可能只是几秒）
T₂ = T₀ + 604800        （到期时间 = stakeTime + 7天）
```

### 第一次提息时（T₁）

```
compoundStart = T₀ (初始值)
stakingDuration = T₁ - T₀ = 86400 + δ
compoundPeriods = (86400 + δ) / 86400 = 1   ← 正确，算了1天
```

提息后：`compoundStartTime` 被重置为 `T₁ = T₀ + 86400 + δ`

### 第二次解押时（T₂ = T₀ + 604800）

```
compoundStart = T₁ = T₀ + 86400 + δ
maturityTime  = T₀ + 604800

block.timestamp >= maturityTime，进入到期分支：
stakingDuration = maturityTime - compoundStart
               = (T₀ + 604800) - (T₀ + 86400 + δ)
               = 518400 - δ
               = 6天 - δ 秒

compoundPeriods = (518400 - δ) / 86400
```

**当 δ > 0 时**（哪怕只有 1 秒）：

```
compoundPeriods = (518400 - δ) / 86400 = 5   ← 少了一天！
```

整数除法 `(6 × 86400 - δ) / 86400 = 5`，只要 `δ ≥ 1`，结果就是 5 而不是 6。

### 根本原因

`compoundStartTime` 精确到秒，但 `compoundPeriods` 按**整天**计算（除以 86400）。提息不可能恰好发生在整天边界上（`δ = 0`），所以必然会有零头秒数。这些零头秒数在整数除法时被截断，导致：

```
实际天数 = floor((maturityTime - compoundStartTime) / 1天)
        = floor(剩余天数 - δ/86400)
        = 剩余整天数 - 1    （只要 δ > 0）
```

**用户永远会少算 1 天复利。**

## 代码定位

```solidity
// StakingBase.sol:1559-1579

uint40 stakingDuration;
unchecked {
    stakingDuration = uint40(block.timestamp) - compoundStart;  // ← 精确到秒
}

// 到期上限
uint40 maturityTime = stakeRecord.stakeTime + uint40(getStakePeriod(stakeRecord.stakeIndex));
if (uint40(block.timestamp) > maturityTime) {
    stakingDuration = maturityTime > compoundStart
        ? maturityTime - compoundStart          // ← 6天 - δ 秒
        : 0;
}

// ...
uint256 compoundPeriods = stakingDuration / getCompoundTimeUnit();  // ← 整除截断！
```

## 影响范围

- 只要用户在质押期间调用过 `withdrawInterest()`，解押时**必定少算 1 天复利**
- 调用 `withdrawInterest()` 越多次，累计损失越大（每次提息都丢失一个零头）
- 影响所有档位（7天/30天/90天/180天/365天）

## 修复方案

### 方案 A：compoundStartTime 对齐到天边界（推荐）

在 `withdrawInterest()` 中重置 `compoundStartTime` 时，不用 `block.timestamp`，而是向下对齐到最近的复利周期边界：

```solidity
// 当前：
stakeRecord.compoundStartTime = uint40(block.timestamp);

// 修复后：
uint256 timeUnit = getCompoundTimeUnit();
uint40 compoundStart = stakeRecord.compoundStartTime != 0
    ? stakeRecord.compoundStartTime
    : stakeRecord.stakeTime;
uint256 elapsed = block.timestamp - compoundStart;
uint256 fullPeriods = elapsed / timeUnit;
stakeRecord.compoundStartTime = compoundStart + uint40(fullPeriods * timeUnit);
```

**原理**：如果用户在第 1.5 天提息，`compoundStartTime` 不设为 T₀+1.5天，而是设为 T₀+1天（整天边界）。这样剩余时间 = maturityTime - (T₀+1天) = 6天，整除后得到 6，不会丢失。

**效果**：

```
提息时刻 T₁ = T₀ + 86400 + δ
对齐后 compoundStart = T₀ + 86400 （δ 被去掉）

解押时：
stakingDuration = (T₀ + 604800) - (T₀ + 86400) = 518400 = 6天
compoundPeriods = 518400 / 86400 = 6  ✓
```

### 方案 B：使用已完成的复利周期数而非时间差

不基于时间差计算，改为记录"已消耗的复利周期数"，解押时用"总周期 - 已消耗周期"计算剩余。但这需要更大的结构体改动。

## 推荐

**方案 A**，只需修改 `withdrawInterest()` 中的一行赋值，改为对齐到复利周期边界。改动最小、语义清晰、完全消除整除截断问题。
