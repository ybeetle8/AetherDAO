# AetherDAO 资金分配详解（新版）

## 概述

本文档详细说明 AetherDAO 质押系统中的资金分配机制，包括质押收益、推荐奖励和团队奖励的计算与分配逻辑。

---

## 一、质押收益机制

### 1.1 质押周期与年化收益率（APY）

系统支持 5 种质押周期，每种周期对应不同的日复利利率：

| 质押周期 | 日复利利率 | 年化收益率（APY）估算 |
|---------|-----------|---------------------|
| 7天     | 0.6%      | ~9倍                |
| 30天    | 0.9%      | ~16倍               |
| 90天    | 1.1%      | ~33倍               |
| 180天   | 1.5%      | ~200倍              |
| 365天   | 2.0%      | ~1377倍             |

**重要说明：**
- 采用**日复利**计算方式
- 最终收益 = 本金 × (1 + 日利率)^天数
- 7天质押每个地址仅可使用一次

### 1.2 收益计算公式

```solidity
// 复利计算
compoundPeriods = stakingDuration / 1 day
finalAmount = principalAmount × (dailyRate ^ compoundPeriods)
```

## 二、推荐奖励机制

### 2.1 直推好友奖励

- **奖励比例：** 5%
- **奖励来源：** 从下级用户的质押收益（利息部分）中扣除
- **分配对象：** 直接推荐人（一级上级）

**计算逻辑：**
```
用户质押收益 = 赎回USDT金额 - 本金
好友奖励 = 用户质押收益 × 5%
```

**特殊情况：**
- 如果用户没有推荐人，该部分奖励归入营销地址（rootAddress）

## 三、团队奖励机制（核心）

### 3.1 等级体系

系统采用**双重条件**等级制度，用户需要同时满足**团队业绩**和**个人质押**两个条件，取较低等级作为最终等级。

#### 3.1.1 团队业绩要求（Team KPI）

| 等级 | 团队业绩要求 | 奖励比例 |
|-----|------------|---------|
| V1  | 3,000 USDT | 3%      |
| V2  | 10,000 USDT | 7%     |
| V3  | 30,000 USDT | 11%    |
| V4  | 100,000 USDT | 15%   |
| V5  | 300,000 USDT | 19%   |
| V6  | 1,000,000 USDT | 23% |
| V7  | 3,000,000 USDT | 27% |
| V8  | 10,000,000 USDT | 31% |
| V9  | 30,000,000 USDT | 35% |

**团队业绩计算：**
- 团队业绩 = 所有下级成员的累计质押金额总和
- 包括直推和间接推荐的所有层级（最多30层）

#### 3.1.2 个人质押要求（Personal Stake）

| 等级 | 个人质押要求 |
|-----|------------|
| V1  | 100 USDT   |
| V2  | 300 USDT   |
| V3  | 600 USDT   |
| V4  | 1,000 USDT |
| V5  | 3,000 USDT |
| V6  | 6,000 USDT |
| V7  | 10,000 USDT |
| V8  | 15,000 USDT |
| V9  | 20,000 USDT |

**个人质押计算：**
- 个人质押 = 用户当前所有有效质押订单的本金总和

#### 3.1.3 最终等级确定

```solidity
function _getUserTier(address user) returns (uint8 tier) {
    uint8 teamKpiTier = _getTierByTeamKpi(teamKPI);
    uint8 personalStakeTier = _getTierByPersonalStake(personalStake);

    // 取两者中的较低等级
    return min(teamKpiTier, personalStakeTier);
}
```

**示例：**
- 用户A：团队业绩 100,000 USDT（达到V4），个人质押 300 USDT（达到V2）
- 最终等级：V2（取较低者）
- 奖励比例：7%

### 3.2 团队奖励分配机制

#### 3.2.1 奖励池

- **总奖励池：** 用户质押收益的 35%
- **分配范围：** 向上追溯最多 30 层推荐关系

#### 3.2.2 严格差额分配法则

系统采用**严格差额分配**机制，确保高等级用户只获得等级差额部分的奖励。

**核心规则：**
1. 从用户的推荐链向上遍历（最多30层）
2. 每个等级只能被分配一次
3. 用户获得的奖励 = 自己的等级比例 - 已分配的累计比例
4. 如果自己的等级比例 ≤ 已分配比例，则不获得奖励

**计算公式：**
```solidity
actualRewardRate = tierRewardRate - cumulativeAllocatedRate
memberReward = userInterest × actualRewardRate / 100
```

#### 3.2.3 分配示例

**场景：** 用户E赎回质押，产生 1000 USDT 利息

推荐链：E ← D(V2) ← C(V4) ← B(V3) ← A(V5)

**分配过程：**

| 步骤 | 上级 | 等级 | 等级比例 | 已分配累计 | 实际获得比例 | 实际奖励 |
|-----|------|------|---------|-----------|------------|---------|
| 1   | D    | V2   | 7%      | 0%        | 7%         | 70 USDT |
| 2   | C    | V4   | 15%     | 7%        | 8%         | 80 USDT |
| 3   | B    | V3   | 11%     | 15%       | 0%         | 0 USDT  |
| 4   | A    | V5   | 19%     | 15%       | 4%         | 40 USDT |

**结果：**
- 总分配：190 USDT
- 剩余：350 - 190 = 160 USDT → 归入营销地址

**关键点：**
- B虽然是V3（11%），但因为下级C已经是V4（15%），所以B不获得奖励
- 每个等级只能被分配一次，即使推荐链中有多个相同等级的用户

## 四、资金流向总览

### 4.1 用户赎回时的资金分配

假设用户赎回获得 1000 USDT（本金 + 利息），其中利息为 200 USDT：

```
总收益：1000 USDT
├─ 本金：800 USDT
└─ 利息：200 USDT
   ├─ 直推好友奖励：200 × 5% = 10 USDT
   ├─ 团队奖励池：200 × 35% = 70 USDT
   │  ├─ 实际分配给上级：根据等级差额分配
   │  └─ 剩余部分：归入营销地址
   ├─ 赎回手续费：(1000 - 10 - 70) × 1% = 9.2 USDT
   └─ 用户实际到账：1000 - 10 - 70 - 9.2 = 910.8 USDT
```

### 4.2 费用明细

| 费用类型 | 比例 | 计算基数 | 接收方 |
|---------|------|---------|--------|
| 直推好友奖励 | 5% | 利息部分 | 直接推荐人 |
| 团队奖励 | 最高35% | 利息部分 | 推荐链上级 |
| 赎回手续费 | 1% | 用户实际到账金额 | feeRecipient |

## 八、安全机制

### 8.1 防刷机制

- 7天质押每个地址仅可使用一次
- 单次质押上限：1000 USDT
- 用户总质押上限：10000 USDT
- 仅允许EOA账户操作（防止合约攻击）

### 8.2 资金安全

- 所有奖励从利息中扣除，不影响本金
- 剩余奖励归入营销地址，不会丢失
- 严格的等级验证，防止超额分配

---

## 九、总结

新版本的资金分配机制更加精细和公平：

1. **双重门槛机制：** 既要求团队业绩，也要求个人质押，确保参与者真实投入
2. **更细化的等级：** 从7级扩展到9级，提供更多晋升空间
3. **降低门槛：** 前期等级门槛降低，更容易获得初始奖励
4. **严格差额分配：** 确保高等级用户只获得等级差额奖励，避免重复分配
5. **完善的费用体系：** 增加赎回手续费，完善经济模型

整体设计更加合理，既激励用户发展团队，又要求用户自身参与质押，形成良性循环。
