## 概述

当用户在 Uniswap 上卖出 AE 代币时，系统会根据用户的盈利情况自动扣除相应的费用，并将这些费用分配到不同的地址和池子中。整个过程完全自动化，无需人工干预。

**核心特点：**
- 交易时即时扣除费用（AE 代币形式）
- 根据盈利情况动态计算税费
- 支持推荐人奖励分成
- 费用累积后统一处理，提高 gas 效率

## 卖出交易费用结构

### 基础交易费用（从卖出金额中扣除）

卖出时会从用户的 AE 代币中扣除以下费用：

| 费用类型 | 费率 | 说明 | 代码位置 |
|---------|------|------|---------|
| **营销费用** | 1.5% | 用于项目营销推广 | `SELL_MARKETING_FEE = 150` |
| **流动性累积费用** | 1.5% | 用于 LP 质押奖励 | `SELL_LIQUIDITY_ACCUM_FEE = 150` |
| **总交易费用** | 3% | 营销 + 流动性 | - |

**计算公式：**
```solidity
// 从卖出的 AE 代币数量中扣除
营销费用 = 卖出数量 × 1.5%
流动性累积费用 = 卖出数量 × 1.5%
净卖出数量 = 卖出数量 - 营销费用 - 流动性累积费用
```

### 盈利相关费用（从 USDT 收益中扣除）

在基础交易费用之后，系统会根据用户的盈利情况，从换得的 USDT 中扣除额外费用：

| 情况 | 费率 | 说明 |
|-----|------|------|
| **有盈利** | 25% | 从盈利部分扣除（盈利税） |
| **无盈利** | 25% | 从总收益扣除（无盈利费） |

## 资金分配流程

### 第一阶段：交易时扣除（AE 代币）

```
用户发起卖出
    ↓
扣除 1.5% 营销费用（AE）→ 累积到 amountMarketingFee
    ↓
扣除 1.5% 流动性费用（AE）→ 累积到 amountLPFee
    ↓
净 AE 数量 → Uniswap 交换为 USDT
```

**代码实现：** `_handleSell()` 函数（[AEBase.sol:782-784](contracts/AE/src/abstract/AEBase.sol#L782-L784)）

```solidity
uint256 marketingFee = (amount * SELL_MARKETING_FEE) / BASIS_POINTS;  // 1.5%
uint256 liquidityAccumFee = (amount * SELL_LIQUIDITY_ACCUM_FEE) / BASIS_POINTS;  // 1.5%
uint256 netAmountAfterTradingFees = amount - marketingFee - liquidityAccumFee;
```

### 第二阶段：盈利判断与税费扣除（USDT）

系统会比较用户的投资成本和实际收益：

```
获得 USDT 收益
    ↓
比较：用户投资成本 vs 实际收益
    ↓
    ├─ 有盈利 → 扣除 25% 盈利税
    │           ↓
    │           ├─ 50% → 营销地址
    │           └─ 50% → 推荐人（如果合格）
    │                    否则 100% → 营销地址
    │
    └─ 无盈利 → 扣除 25% 无盈利费
                ↓
                100% → 营销地址
```

**代码实现：** `_handleSell()` 函数（[AEBase.sol:796-850](contracts/AE/src/abstract/AEBase.sol#L796-L850)）

## 盈利税机制

### 触发条件

当 `实际 USDT 收益 > 用户投资成本` 时触发盈利税。

### 计算方式

```solidity
// 1. 计算盈利金额
盈利金额 = 实际 USDT 收益 - 用户投资成本

// 2. 计算盈利税（25%）
盈利税 USDT = 盈利金额 × 25%

// 3. 将盈利税对应的 AE 代币换回 USDT
盈利税 AE = 根据当前价格计算需要的 AE 数量
```

**代码实现：**
```solidity
// AEBase.sol:796-810
uint256 userCurrentInvestment = userInvestment[from];
uint256 profitAmount = actualUSDTReceived > userCurrentInvestment
    ? actualUSDTReceived - userCurrentInvestment
    : 0;

uint256 profitTaxUSDT = 0;
uint256 profitTaxAE = 0;

if (profitAmount > 0) {
    profitTaxUSDT = (profitAmount * PROFIT_TAX_RATE) / BASIS_POINTS;  // 25%
    profitTaxAE = _estimateSwapInput(profitTaxUSDT);

    if (profitTaxAE > 0 && profitTaxAE <= netAmountAfterTradingFees) {
        netAmountAfterTradingFees -= profitTaxAE;
    }
}
```

### 盈利税分配

盈利税会根据推荐人情况进行分配：

#### 情况 1：有合格推荐人

```
盈利税 USDT (100%)
    ↓
    ├─ 50% → 营销地址
    └─ 50% → 推荐人
```

**推荐人合格条件：**
- 用户必须有推荐人
- 推荐人必须是"传道者"（Preacher）等级

#### 情况 2：无推荐人或推荐人不合格

```
盈利税 USDT (100%)
    ↓
    └─ 100% → 营销地址
```

**代码实现：** `_processProfitTax()` 函数（[AEBase.sol:1427-1468](contracts/AE/src/abstract/AEBase.sol#L1427-L1468)）

```solidity
function _processProfitTax(address user, uint256 taxAmount) private
    returns (address referrer, uint256 marketingShare, uint256 referrerShare)
{
    if (taxAmount == 0) return (address(0), 0, 0);

    // 将 AE 代币换成 USDT
    uint256 usdtAmount = _swapTokensForUSDT(taxAmount);
    if (usdtAmount == 0) return (address(0), 0, 0);

    referrer = _getUserReferrer(user);

    if (referrer != address(0)) {
        if (_isReferrerEligible(referrer)) {
            // 推荐人合格：50-50 分成
            marketingShare = usdtAmount / 2;
            referrerShare = usdtAmount - marketingShare;
        } else {
            // 推荐人不合格：全部给营销
            marketingShare = usdtAmount;
            referrerShare = 0;
            referrer = address(0);
        }
    } else {
        // 无推荐人：全部给营销
        marketingShare = usdtAmount;
        referrerShare = 0;
    }

    // 转账
    if (marketingShare > 0) {
        IERC20(USDT).transfer(marketingAddress, marketingShare);
    }
    if (referrerShare > 0) {
        IERC20(USDT).transfer(referrer, referrerShare);
    }

    return (referrer, marketingShare, referrerShare);
}
```

## 无盈利费用机制

### 触发条件

当 `实际 USDT 收益 ≤ 用户投资成本` 时触发无盈利费用。

### 计算方式

```solidity
// 无盈利费用 = 实际 USDT 收益 × 25%
无盈利费用 USDT = 实际 USDT 收益 × 25%

// 将无盈利费用对应的 AE 代币换回 USDT
无盈利费用 AE = 根据当前价格计算需要的 AE 数量
```

**代码实现：**
```solidity
// AEBase.sol:812-822
uint256 noProfitFeeUSDT = 0;
uint256 noProfitFeeAE = 0;

if (profitAmount == 0 && actualUSDTReceived > 0) {
    noProfitFeeUSDT = (actualUSDTReceived * NO_PROFIT_FEE) / BASIS_POINTS;  // 25%
    noProfitFeeAE = _estimateSwapInput(noProfitFeeUSDT);

    if (noProfitFeeAE > 0 && noProfitFeeAE <= netAmountAfterTradingFees) {
        netAmountAfterTradingFees -= noProfitFeeAE;
    }
}
```

### 无盈利费用分配

```
无盈利费用 USDT (100%)
    ↓
    └─ 100% → 营销地址
```

**注意：** 无盈利费用不会分给推荐人，全部进入营销地址。

## 推荐人奖励机制

### 推荐人资格

推荐人必须满足以下条件才能获得奖励：

1. **用户必须有推荐人**
   - 通过 `staking.getReferral(user)` 查询

2. **推荐人必须是"传道者"等级**
   - 通过 `staking.isPreacher(referrer)` 验证
   - 传道者需要满足特定的质押和团队业绩要求

### 奖励来源

推荐人只能从**盈利税**中获得奖励：

- ✅ 用户有盈利 → 推荐人可获得盈利税的 50%
- ❌ 用户无盈利 → 推荐人无奖励

### 奖励计算

```solidity
// 假设用户盈利 1000 USDT
盈利金额 = 1000 USDT
盈利税 = 1000 × 25% = 250 USDT

// 如果推荐人合格
营销地址获得 = 250 × 50% = 125 USDT
推荐人获得 = 250 × 50% = 125 USDT

// 如果推荐人不合格或无推荐人
营销地址获得 = 250 USDT
推荐人获得 = 0 USDT
```

## 累积费用处理

### 费用累积机制

为了节省 gas 费用，系统不会在每次交易时立即处理营销费用和流动性费用，而是先累积起来：

```solidity
// 状态变量
uint256 public amountMarketingFee;  // 累积的营销费用（AE 代币）
uint256 public amountLPFee;         // 累积的流动性费用（AE 代币）
uint256 public swapAtAmount = 10000 ether;  // 触发阈值
```

### 触发条件

当累积费用达到阈值时自动触发处理：

```solidity
if (amountMarketingFee + amountLPFee >= swapAtAmount) {
    _processFeeDistribution();
}
```

**代码位置：** `_tryProcessAccumulatedFees()` 函数（[AEBase.sol:1152-1172](contracts/AE/src/abstract/AEBase.sol#L1152-L1172)）

### 费用处理流程

```
累积费用达到阈值
    ↓
检查流动性是否充足
    ↓
    ├─ 充足 → 开始处理
    │         ↓
    │         ├─ 营销费用（AE）→ 换成 USDT → 营销地址
    │         │
    │         └─ 流动性费用（AE）→ 直接存入 LiquidityStaking
    │                              （作为 BLA 奖励）
    │
    └─ 不足 → 跳过处理，继续累积
```

**代码实现：** `_processFeeDistribution()` 函数（[AEBase.sol:1213-1256](contracts/AE/src/abstract/AEBase.sol#L1213-L1256)）

```solidity
function _processFeeDistribution() private lockSwap {
    uint256 totalMarketingFee = amountMarketingFee;
    uint256 totalLPFee = amountLPFee;

    if (totalMarketingFee + totalLPFee == 0) return;

    // 清零累积
    amountMarketingFee = 0;
    amountLPFee = 0;

    // 处理营销费用
    if (totalMarketingFee > 0) {
        uint256 marketingUSDT = _swapTokensForUSDT(totalMarketingFee);
        if (marketingUSDT > 0 && marketingAddress != address(0)) {
            IERC20(USDT).transfer(marketingAddress, marketingUSDT);
        }
    }

    // 处理流动性费用（直接存入 BLA 代币）
    if (totalLPFee > 0) {
        IERC20(address(this)).approve(address(liquidityStaking), totalLPFee);
        liquidityStaking.depositBLARewards(totalLPFee);
        emit LPRewardDeposited(totalLPFee);
    }
}
```

### 流动性检查

在处理费用前，系统会检查流动性池是否健康：

```solidity
function _canProcessFees() private view returns (bool) {
    // 1. 检查是否有费用
    uint256 totalFees = amountMarketingFee + amountLPFee;
    if (totalFees == 0) return false;

    // 2. 检查合约余额
    if (balanceOf(address(this)) < totalFees) return false;

    // 3. 检查流动性池储备
    (uint112 reserveUSDT, uint112 reserveXF) = uniswapV2Pair.getReserves();

    // 实际余额必须 >= 储备的 95%
    if (actualXFBalance < (reserveXF * 95) / 100) return false;
    if (actualUSDTBalance < (reserveUSDT * 95) / 100) return false;

    // 4. 检查交换数量不超过储备的 2%
    uint256 maxSwapAmount = (reserveXF * 2) / 100;
    if (totalFees > maxSwapAmount) return false;

    return true;
}
```

**代码位置：** [AEBase.sol:1174-1211](contracts/AE/src/abstract/AEBase.sol#L1174-L1211)

## 完整示例

### 示例 1：有盈利 + 有合格推荐人

**场景：**
- 用户投资成本：1000 USDT
- 卖出 AE 数量：10000 AE
- 当前价格：1 AE = 0.15 USDT
- 用户有合格推荐人

**计算过程：**

#### 第一步：扣除交易费用（AE）
```
营销费用 = 10000 × 1.5% = 150 AE
流动性费用 = 10000 × 1.5% = 150 AE
净卖出数量 = 10000 - 150 - 150 = 9700 AE
```

#### 第二步：换成 USDT
```
实际 USDT 收益 = 9700 × 0.15 = 1455 USDT
```

#### 第三步：计算盈利税
```
盈利金额 = 1455 - 1000 = 455 USDT
盈利税 = 455 × 25% = 113.75 USDT
盈利税对应 AE = 113.75 / 0.15 ≈ 758 AE
```

#### 第四步：扣除盈利税后的净卖出
```
最终净卖出 = 9700 - 758 = 8942 AE
最终 USDT 收益 = 8942 × 0.15 ≈ 1341.3 USDT
```

#### 第五步：盈利税分配
```
盈利税 USDT = 113.75 USDT
├─ 营销地址 = 113.75 × 50% = 56.875 USDT
└─ 推荐人 = 113.75 × 50% = 56.875 USDT
```

#### 最终资金分配汇总：

| 接收方 | 金额 | 来源 |
|-------|------|------|
| **用户** | 1341.3 USDT | 卖出收益 |
| **营销地址** | 56.875 USDT | 盈利税 50% |
| **推荐人** | 56.875 USDT | 盈利税 50% |
| **累积营销费用** | 150 AE | 交易费用（待处理） |
| **累积流动性费用** | 150 AE | 交易费用（待处理） |

### 示例 3：累积费用处理

**场景：**
- 累积营销费用：8000 AE
- 累积流动性费用：5000 AE
- 总累积：13000 AE（超过阈值 10000 AE）
- 当前价格：1 AE = 0.15 USDT

**处理流程：**

#### 第一步：检查是否达到阈值
```
总累积 = 8000 + 5000 = 13000 AE
阈值 = 10000 AE
13000 >= 10000 → 触发处理
```

#### 第二步：检查流动性
```
检查流动性池储备是否充足
检查交换数量是否在安全范围内（< 储备的 2%）
→ 通过检查，开始处理
```

#### 第三步：处理营销费用
```
营销费用 AE = 8000 AE
换成 USDT = 8000 × 0.15 = 1200 USDT
转账到营销地址 = 1200 USDT
```

#### 第四步：处理流动性费用
```
流动性费用 AE = 5000 AE
直接存入 LiquidityStaking 合约（作为 BLA 奖励）
LP 质押者将获得这些 AE 代币作为奖励
```

#### 第五步：清零累积
```
amountMarketingFee = 0
amountLPFee = 0
```

#### 资金分配汇总：

| 接收方 | 金额 | 说明 |
|-------|------|------|
| **营销地址** | 1200 USDT | 营销费用换成 USDT |
| **LiquidityStaking** | 5000 AE | 作为 LP 质押奖励 |

## 总结

### 卖出费用总览

| 费用类型 | 费率 | 扣除形式 | 分配方式 |
|---------|------|---------|---------|
| 营销费用 | 1.5% | AE 代币 | 累积后换 USDT → 营销地址 |
| 流动性费用 | 1.5% | AE 代币 | 累积后 → LiquidityStaking（BLA 奖励） |
| 盈利税 | 25% | AE 代币 | 换 USDT → 50% 营销 + 50% 推荐人 |
| 无盈利费 | 25% | AE 代币 | 换 USDT → 100% 营销地址 |

### 关键特点

1. **双重费用机制**
   - 交易费用：固定 3%（营销 1.5% + 流动性 1.5%）
   - 盈利费用：动态 25%（根据盈利情况）

2. **智能分配**
   - 有盈利：推荐人可获得盈利税的 50%
   - 无盈利：全部进入营销地址

3. **Gas 优化**
   - 费用累积机制，减少频繁交换
   - 流动性检查，避免影响价格

4. **透明可追溯**
   - 所有操作都有事件记录
   - 用户投资成本自动跟踪
