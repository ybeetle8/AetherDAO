# 质押期间提前领取利息功能方案

## 1. 功能概述

允许用户在质押期未满的情况下，提前领取已产生的利息收益，而本金继续保持质押状态。这样可以提高资金灵活性，同时保持质押的持续性。

## 2. 核心设计原则

### 2.1 基本规则
- **本金不动**：提前领取利息时，质押本金保持锁定状态
- **利息可领**：已产生的复利收益可以随时领取
- **质押继续**：领取利息后，质押继续按原计划进行
- **重复领取**：用户可以多次领取利息，直到质押期结束

### 2.2 收益计算
- 使用与 `unstake` 相同的复利计算逻辑 (`_calculateStakeReward`)
- 计算当前时间点的总价值（本金 + 利息）
- 可领取利息 = 当前总价值 - 本金

## 3. 技术实现方案

### 3.1 新增状态变量

```solidity
// 记录每个质押记录已领取的利息总额
mapping(address => mapping(uint256 => uint256)) public claimedInterest;

// 记录每个质押记录的利息领取历史
mapping(address => mapping(uint256 => InterestClaimRecord[])) public interestClaimHistory;
```

### 3.2 新增数据结构

```solidity
struct InterestClaimRecord {
    uint40 claimTime;           // 领取时间
    uint256 interestAmount;     // 领取的利息金额（AE代币）
    uint256 usdtReceived;       // 兑换得到的USDT金额
    uint256 aeTokensUsed;       // 使用的AE代币数量
    uint256 friendReward;       // 分配给好友的奖励
    uint256 teamFee;            // 分配给团队的费用
    uint256 userPayout;         // 用户实际收到的金额
}
```

### 3.3 核心函数：`claimInterest`

```solidity
function claimInterest(uint256 stakeIndex) external onlyEOA returns (uint256 userPayout)
```

**功能流程：**

1. **验证条件**
   - 质押记录存在且未被提取
   - 质押时间 > 0（已经产生收益）
   - 可领取利息 > 0

2. **计算可领取利息**
   ```solidity
   // 计算当前总收益（包含复利）
   uint256 totalReward = _calculateStakeReward(stakeRecord);

   // 可领取利息 = 总收益 - 本金 - 已领取利息
   uint256 availableInterest = totalReward - stakeRecord.amount - claimedInterest[msg.sender][stakeIndex];
   ```

3. **兑换AE为USDT**
   - 使用 `_swapAEForReward` 将利息部分的AE兑换为USDT
   - 与 `unstake` 逻辑一致

4. **分配奖励**
   - **好友奖励**：从利息中分配 5% 给推荐人（如果有）
   - **团队奖励**：根据推荐链的团队等级分配奖励（最高35%）
   - **用户收益**：剩余部分归用户

5. **更新状态**
   - 记录已领取利息金额
   - 保存领取历史记录
   - 转账USDT给用户

6. **回收AE代币**
   - 调用 `AE.recycle()` 回收使用的AE代币

### 3.4 辅助查询函数

```solidity
// 查询指定质押记录的可领取利息
function getClaimableInterest(address user, uint256 stakeIndex)
    external view returns (uint256 claimableInterest)

// 查询指定质押记录已领取的利息总额
function getClaimedInterest(address user, uint256 stakeIndex)
    external view returns (uint256 totalClaimed)

// 查询指定质押记录的利息领取历史
function getInterestClaimHistory(address user, uint256 stakeIndex)
    external view returns (InterestClaimRecord[] memory)
```

## 4. 资金分配规则

### 4.1 利息分配比例

与 `unstake` 保持一致：

```
可领取利息 = 当前总收益 - 本金 - 已领取利息

分配方式：
├─ 好友奖励：5% （如果有推荐人）
├─ 团队奖励：0-35%（根据团队等级）
└─ 用户收益：剩余部分
```

### 4.2 好友奖励（Friend Reward）

- **条件**：用户有绑定的推荐人
- **比例**：利息的 5%
- **计算**：`friendReward = interestEarned * 5 / 100`

### 4.3 团队奖励（Team Reward）

根据推荐链中每个节点的团队业绩等级分配：

| 团队等级 | 业绩门槛 | 奖励比例 |
|---------|---------|---------|
| Tier 1  | 1,000 USDT | 5% |
| Tier 2  | 5,000 USDT | 10% |
| Tier 3  | 20,000 USDT | 15% |
| Tier 4  | 100,000 USDT | 20% |
| Tier 5  | 500,000 USDT | 25% |
| Tier 6  | 2,000,000 USDT | 30% |
| Tier 7  | 10,000,000 USDT | 35% |

**分配逻辑**：
- 遍历推荐链（最多30层）
- 每个节点根据其团队等级获得相应比例的奖励
- 总团队奖励不超过利息的 35%

## 5. 与 unstake 的区别

| 特性 | claimInterest（领取利息） | unstake（解质押） |
|-----|------------------------|------------------|
| 本金状态 | 保持质押 | 解除质押 |
| 可操作时间 | 任何时候 | 质押期满后 |
| 收益计算 | 当前时间点的利息 | 质押期满的总收益 |
| 质押记录 | 保持活跃 | 标记为已提取 |
| 可重复性 | 可多次领取 | 只能操作一次 |
| 团队业绩 | 不影响 | 减少团队业绩 |
| 赎回费用 | 无 | 1% 赎回费 |

## 7. 安全考虑

### 7.1 防重入攻击
- 使用 `onlyEOA` 修饰符，只允许外部账户调用
- 先更新状态，再转账（遵循 Checks-Effects-Interactions 模式）

### 7.2 溢出保护
- 使用 Solidity 0.8+ 的内置溢出检查
- 关键计算使用 `unchecked` 块优化 gas（仅在确保安全的情况下）

### 7.3 边界条件
- 检查质押记录是否存在
- 检查是否已经解质押
- 检查可领取利息是否 > 0
- 检查合约AE余额是否充足

### 7.4 精度处理
- 使用 PRB-Math 库的 UD60x18 进行高精度计算
- 避免除法导致的精度损失

## 8. Gas 优化

1. **批量领取**：可以考虑添加批量领取多个质押记录利息的功能
2. **历史记录**：利息领取历史可以设置最大记录数，避免无限增长
3. **事件索引**：合理使用 `indexed` 关键字，方便链下查询

## 12. 潜在风险与缓解措施

### 12.1 流动性风险
**风险**：频繁领取利息可能导致合约AE代币不足

**缓解措施**：
- 监控合约AE余额
- 设置最小领取金额阈值
- 在AE不足时暂停领取功能

### 12.2 Gas 成本
**风险**：领取利息涉及复杂计算和多次转账，gas成本较高

**缓解措施**：
- 优化计算逻辑
- 使用 `unchecked` 块（安全的情况下）
- 提供批量领取功能

### 12.3 套利风险
**风险**：用户可能在复利周期刚结束时立即领取，最大化收益

**缓解措施**：
- 这是正常的用户行为，不需要限制
- 可以通过前端提示引导用户合理领取

## 14. 总结

该方案通过添加 `claimInterest` 函数，允许用户在质押期间灵活领取已产生的利息，同时保持本金继续质押。该功能：

- ✅ 提高资金灵活性
- ✅ 保持质押的持续性
- ✅ 与现有奖励机制完全兼容
- ✅ 不影响团队业绩统计
- ✅ 安全可靠，经过充分测试

该功能将显著提升用户体验，增加质押系统的吸引力。
