## 需求分析

### 核心需求
- 用户可以在质押到期前提取**已产生的利息**
- **本金保持锁定**，继续按原质押期限计息
- 可以**不限次数**提取利息
- 提取利息时的**分配规则与到期解质押相同**（好友5% + 团队35% + 赎回费1%）

### 与现有解质押的区别

| 特性 | 到期解质押 (unstake) | 提前提取利息 (withdrawInterest) |
|-----|---------------------|--------------------------------|
| 时间限制 | 必须到期 | 无时间限制 |
| 提取内容 | 本金 + 利息 | 仅利息 |
| 本金状态 | 销毁质押记录 | 保持质押，继续计息 |
| 提取次数 | 每个质押记录只能提取一次 | 不限次数 |
| 分配规则 | 好友5% + 团队35% + 赎回费1% | 相同 |
| sAE 销毁 | 销毁本金对应的 sAE | 不销毁 sAE |

## 功能设计

### 方案 A：简单累计提取（推荐）

#### 核心思路
- 记录用户每次提取利息的时间点
- 每次提取时，计算从**上次提取时间**到**当前时间**的新增利息
- 本金保持不变，继续按原利率计息

#### 数据结构
```solidity
// 在 Record 结构中添加字段
struct Record {
    uint40 stakeTime;           // 质押时间
    uint160 amount;             // 本金
    bool status;                // 是否已完全提取
    uint8 stakeIndex;           // 质押期限索引
    uint40 lastInterestWithdrawTime;  // 新增：上次提取利息时间
    uint256 totalInterestWithdrawn;   // 新增：累计已提取利息
}
```

#### 计算逻辑
```
当前总价值 = 本金 × (1 + 日利率)^已质押天数
已提取利息 = totalInterestWithdrawn
可提取利息 = 当前总价值 - 本金 - 已提取利息
```

#### 优点
- 逻辑简单清晰
- 不改变原有复利计算
- 用户可以随时提取任意次数

#### 缺点
- 需要修改 Record 结构（增加存储成本）
- 需要处理历史数据兼容性

---

### 方案 B：虚拟本金调整（不推荐）

#### 核心思路
- 每次提取利息后，将"已提取的利息"从虚拟本金中扣除
- 后续计息基于调整后的虚拟本金

#### 问题
- 破坏了原有的复利计算逻辑
- 用户的 sAE 余额与实际本金不匹配
- 复杂度高，容易出错

## 技术实现方案（方案 A）

### 1. 修改数据结构

```solidity
struct Record {
    uint40 stakeTime;
    uint160 amount;
    bool status;
    uint8 stakeIndex;
    uint40 lastInterestWithdrawTime;  // 新增
    uint256 totalInterestWithdrawn;   // 新增
}
```

**兼容性处理**：
- 历史记录的 `lastInterestWithdrawTime` 默认为 0
- 历史记录的 `totalInterestWithdrawn` 默认为 0
- 第一次提取利息时，如果 `lastInterestWithdrawTime == 0`，则设置为 `stakeTime`

### 2. 核心函数实现

```solidity
/**
 * @notice 提前提取质押利息（不影响本金）
 * @param stakeIndex 质押记录索引
 * @return interestWithdrawn 实际提取的利息金额
 */
function withdrawInterest(uint256 stakeIndex)
    external
    onlyEOA
    returns (uint256 interestWithdrawn)
{
    address user = msg.sender;
    Record storage stakeRecord = userStakeRecord[user][stakeIndex];

    // 1. 验证质押记录有效性
    require(!stakeRecord.status, "Stake already fully withdrawn");
    require(stakeIndex < userStakeRecord[user].length, "Invalid stake index");

    // 2. 计算当前总价值
    uint256 currentTotalValue = _calculateStakeReward(stakeRecord);
    uint256 principal = stakeRecord.amount;

    // 3. 计算可提取利息
    uint256 totalInterest = currentTotalValue > principal
        ? currentTotalValue - principal
        : 0;
    uint256 availableInterest = totalInterest > stakeRecord.totalInterestWithdrawn
        ? totalInterest - stakeRecord.totalInterestWithdrawn
        : 0;

    require(availableInterest > 0, "No interest available to withdraw");

    // 4. 兑换 AE 为 USDT
    (uint256 usdtReceived, uint256 aeTokensUsed) = _swapAEForReward(availableInterest);

    // 5. 分配资金（与解质押相同）
    address[] memory referralChain = getReferrals(user, maxD);
    uint256 friendReward = _distributeFriendReward(user, usdtReceived);
    uint256 teamFee = _distributeTeamReward(referralChain, usdtReceived);

    uint256 userPayout = usdtReceived - friendReward - teamFee;

    // 6. 收取赎回费
    uint256 redemptionFee = (userPayout * REDEMPTION_FEE_RATE) / BASIS_POINTS_DENOMINATOR;
    if (redemptionFee > 0 && feeRecipient != address(0)) {
        (, uint256 redemptionFeeAEUsed) = _swapAEForReward(redemptionFee);
        emit RedemptionFeeCollected(
            user, stakeIndex, redemptionFeeAEUsed,
            redemptionFee, feeRecipient, block.timestamp
        );
    }

    uint256 finalUserPayout = userPayout - redemptionFee;

    // 7. 更新质押记录
    stakeRecord.lastInterestWithdrawTime = uint40(block.timestamp);
    stakeRecord.totalInterestWithdrawn += availableInterest;

    // 8. 转账给用户
    IERC20(USDT).transfer(user, finalUserPayout);

    // 9. 回收 AE
    AE.recycle(aeTokensUsed);

    // 10. 记录提取历史
    _recordInterestWithdrawal(
        user, stakeIndex, availableInterest, usdtReceived,
        aeTokensUsed, friendReward, teamFee, finalUserPayout
    );

    emit InterestWithdrawn(user, stakeIndex, availableInterest, finalUserPayout, block.timestamp);

    return availableInterest;
}
```

### 3. 辅助查询函数

```solidity
/**
 * @notice 查询指定质押记录的可提取利息
 * @param user 用户地址
 * @param stakeIndex 质押记录索引
 * @return availableInterest 可提取利息金额
 */
function getAvailableInterest(address user, uint256 stakeIndex)
    external
    view
    returns (uint256 availableInterest)
{
    if (stakeIndex >= userStakeRecord[user].length) {
        return 0;
    }

    Record storage stakeRecord = userStakeRecord[user][stakeIndex];

    if (stakeRecord.status) {
        return 0;
    }

    uint256 currentTotalValue = _calculateStakeReward(stakeRecord);
    uint256 principal = stakeRecord.amount;

    uint256 totalInterest = currentTotalValue > principal
        ? currentTotalValue - principal
        : 0;

    availableInterest = totalInterest > stakeRecord.totalInterestWithdrawn
        ? totalInterest - stakeRecord.totalInterestWithdrawn
        : 0;
}

/**
 * @notice 查询用户所有质押记录的可提取利息
 * @param user 用户地址
 * @return stakeIndices 质押记录索引数组
 * @return availableInterests 对应的可提取利息数组
 */
function getAllAvailableInterests(address user)
    external
    view
    returns (
        uint256[] memory stakeIndices,
        uint256[] memory availableInterests
    )
{
    uint256 count = userStakeRecord[user].length;
    stakeIndices = new uint256[](count);
    availableInterests = new uint256[](count);

    for (uint256 i = 0; i < count; i++) {
        stakeIndices[i] = i;
        availableInterests[i] = this.getAvailableInterest(user, i);
    }
}
```

### 4. 提取历史记录

```solidity
/**

 */
struct InterestWithdrawalRecord {

function getInterestWithdrawalHistory(address user)
    external
    view
    returns (InterestWithdrawalRecord[] memory)

}
```

## 资金分配机制

### 分配流程（与解质押完全相同）

```
可提取利息 (availableInterest)
    ↓
兑换为 USDT (usdtReceived)
    ↓
分配：
├── 好友奖励: usdtReceived × 5%
├── 团队奖励: usdtReceived × 35%
│   └── 差额分配机制（V1-V9）
├── 用户收益: 剩余部分
└── 赎回费: 用户收益 × 1%

最终用户收到: 用户收益 × 99%
```

### 示例计算

**场景**：
- 用户质押 1000 USDT，选择 30 天期（0.9% 日复利）
- 15 天后提取利息
- 推荐链：V3(11%)

**计算**：
```
当前总价值 = 1000 × (1.009)^15 ≈ 1143 USDT
可提取利息 = 1143 - 1000 = 143 USDT

兑换为 USDT: 143 USDT
├── 好友奖励: 143 × 5% = 7.15 USDT
├── 团队奖励: 143 × 35% = 50.05 USDT
│   ├── V3 获得: 143 × 11% = 15.73 USDT
│   └── 项目方: 143 × 24% = 34.32 USDT
├── 用户收益: 143 - 7.15 - 50.05 = 85.8 USDT
└── 赎回费: 85.8 × 1% = 0.86 USDT

用户实际收到: 85.8 - 0.86 = 84.94 USDT
```

**后续**：
- 本金 1000 USDT 继续质押
- 从第 16 天开始继续计息
- 到期时可再次提取新增利息或全部解质押

## 关键问题与解决方案

### 问题 1：提取利息后，本金如何继续计息？

**解决方案**：
- 本金保持不变，继续按原利率复利计息
- 计算总价值时仍然基于原始质押时间
- 只是记录了"已提取的利息"，不影响后续计息

**示例**：
```
第 0 天：质押 1000 USDT
第 15 天：提取 143 USDT 利息
第 30 天：
  - 总价值 = 1000 × (1.009)^30 = 1309 USDT
  - 已提取 = 143 USDT
  - 可提取 = 1309 - 1000 - 143 = 166 USDT
```

### 问题 2：如何处理到期后的解质押？

**解决方案**：
- 到期后调用 `unstake()` 时，自动扣除已提取的利息
- 修改 `unstake()` 函数：

```solidity
function unstake(uint256 stakeIndex) external onlyEOA returns (uint256 totalReward) {
    (uint256 calculatedReward, uint256 principalAmount) = _burn(stakeIndex);

    // 获取已提取的利息
    Record storage stakeRecord = userStakeRecord[msg.sender][stakeIndex];
    uint256 alreadyWithdrawn = stakeRecord.totalInterestWithdrawn;

    // 计算剩余利息
    uint256 remainingInterest = calculatedReward > principalAmount + alreadyWithdrawn
        ? calculatedReward - principalAmount - alreadyWithdrawn
        : 0;

    // 只兑换剩余利息 + 本金
    uint256 amountToSwap = principalAmount + remainingInterest;
    (uint256 usdtReceived, uint256 aeTokensUsed) = _swapAEForReward(amountToSwap);

    // 后续分配逻辑保持不变...
}
```

### 问题 3：频繁提取会不会影响池子稳定性？

**风险**：
- 用户可能每天都提取利息，增加 AE 卖压
- 频繁兑换可能影响 AE 价格

**缓解措施**：
1. **最小提取金额限制**：
```solidity
uint256 constant MIN_INTEREST_WITHDRAWAL = 10 ether; // 最小提取 10 USDT
require(availableInterest >= MIN_INTEREST_WITHDRAWAL, "Interest too small");
```

2. **提取冷却时间**（可选）：
```solidity
uint256 constant INTEREST_WITHDRAWAL_COOLDOWN = 1 days;
require(
    block.timestamp >= stakeRecord.lastInterestWithdrawTime + INTEREST_WITHDRAWAL_COOLDOWN,
    "Cooldown period not met"
);
```

3. **提取手续费递增**（可选）：
```solidity
// 根据提取次数递增手续费
uint256 withdrawalCount = _userInterestWithdrawalHistory[user].length;
uint256 feeRate = REDEMPTION_FEE_RATE + (withdrawalCount * 10); // 每次增加 0.1%
feeRate = feeRate > 500 ? 500 : feeRate; // 最高 5%
```

### 问题 4：团队业绩如何计算？

**解决方案**：
- 提取利息**不影响**团队业绩
- 团队业绩只在质押和完全解质押时更新
- 理由：本金仍在质押中，团队业绩应保持

```solidity
// withdrawInterest() 中不调用 _updateTeamInvestmentValues()
// 只在 unstake() 完全解质押时才减少团队业绩
```

### 问题 5：sAE 余额如何处理？

**解决方案**：
- 提取利息**不销毁** sAE
- sAE 余额始终等于本金
- 只有完全解质押时才销毁 sAE

```solidity
// withdrawInterest() 中不调用 _update(user, address(0), amount)
// 保持 sAE 余额不变
```

## 风险评估

### 高风险

1. **AE 代币卖压增加**
   - 用户频繁提取利息会增加 AE 卖出量
   - 可能导致 AE 价格下跌
   - **缓解**：设置最小提取金额和冷却时间

2. **池子流动性压力**
   - 大量用户同时提取利息可能耗尽池子 USDT
   - **缓解**：复用现有的滑点保护机制

### 中风险

3. **Gas 成本增加**
   - 新增字段增加存储成本
   - 频繁提取增加链上交互
   - **影响**：用户需支付更多 gas

4. **合约复杂度增加**
   - 需要处理历史数据兼容性
   - 增加测试和审计成本
   - **缓解**：充分测试和代码审计

### 低风险

5. **用户体验问题**
   - 用户可能不理解"提取利息"和"解质押"的区别
   - **缓解**：前端清晰说明和引导

## 总结

### 推荐方案
- 采用**方案 A（简单累计提取）**
- 设置 **10 USDT 最小提取金额**
- 设置 **1 天冷却时间**（可配置）
- **固定 1% 赎回费**
- **不影响团队业绩**
- **不限提取次数**

### 优势
- 用户可以灵活提取利息，提高资金利用率
- 本金继续质押，保持团队业绩稳定
- 分配机制与解质押一致，逻辑清晰

### 需要注意
- 增加 AE 卖压，需要监控价格影响
- 需要充分测试和审计
- 前端需要清晰说明功能
