## 三、实现方案建议

### 3.1 简单直接的方案（推荐用于节点和跨链储备）

**适用于**: 节点、跨链储备

**实现方式**: 在部署脚本中直接转账

```javascript
// 在 deployAE.js 中添加
const nodeAddress = config.addresses.nodeAddress;
const crossChainAddress = config.addresses.crossChainAddress;

await ae.transfer(nodeAddress, ethers.parseEther("1000000"));
await ae.transfer(crossChainAddress, ethers.parseEther("1000000"));
```

**优点**:
- 实现简单，无需额外合约
- 代币立即可用
- 透明度高

**缺点**:
- 无锁仓保护
- 需要信任接收地址的管理者

---

### 3.2 市场营销代币的三种方案

#### 方案A: 直接转账（最简单）
```javascript
await ae.transfer(marketingAddress, ethers.parseEther("1000000"));
```
- **优点**: 简单直接
- **缺点**: 无控制，可能被滥用

#### 方案B: 分批释放（推荐）
创建一个简单的 `MarketingVault` 合约：
```solidity
contract MarketingVault {
    uint256 public constant MONTHLY_RELEASE = 100_000 ether; // 每月10万
    uint256 public lastReleaseTime;
    address public marketingAddress;

    function release() external {
        require(block.timestamp >= lastReleaseTime + 30 days);
        ae.transfer(marketingAddress, MONTHLY_RELEASE);
        lastReleaseTime = block.timestamp;
    }
}
```

#### 方案C: 多签控制（最安全）
使用 Gnosis Safe 多签钱包作为 marketingAddress

---

### 3.3 团队代币的三种方案

#### 方案A: 简单锁仓（推荐）
```solidity
contract TeamVault {
    uint256 public constant LOCK_PERIOD = 180 days; // 6个月锁仓
    uint256 public deployTime;
    address public teamAddress;

    function withdraw() external {
        require(block.timestamp >= deployTime + LOCK_PERIOD);
        ae.transfer(teamAddress, ae.balanceOf(address(this)));
    }
}
```

#### 方案B: 线性释放
```solidity
contract TeamVesting {
    uint256 public constant VESTING_DURATION = 365 days; // 1年线性释放
    uint256 public constant TOTAL_AMOUNT = 1_000_000 ether;
    uint256 public deployTime;
    uint256 public released;

    function release() external {
        uint256 elapsed = block.timestamp - deployTime;
        uint256 releasable = (TOTAL_AMOUNT * elapsed / VESTING_DURATION) - released;
        released += releasable;
        ae.transfer(teamAddress, releasable);
    }
}
```

#### 方案C: 分阶段释放
- 6个月后释放 25%
- 12个月后释放 25%
- 18个月后释放 25%
- 24个月后释放 25%

### 3.4 社区空投的三种方案

#### 方案A: 手动空投（最简单）
管理员持有 50万 AE，手动调用 `transfer` 分发

#### 方案B: 白名单空投
```solidity
contract AirdropVault {
    mapping(address => uint256) public allocations;
    mapping(address => bool) public claimed;

    function claim() external {
        require(!claimed[msg.sender]);
        require(allocations[msg.sender] > 0);
        claimed[msg.sender] = true;
        ae.transfer(msg.sender, allocations[msg.sender]);
    }
}
```

#### 方案C: Merkle Tree 空投（最省 gas）
使用 Merkle Proof 验证，用户自行 claim

## 七、风险提示

### 7.1 直接转账的风险
- ⚠️ 无锁仓保护，接收方可以立即抛售
- ⚠️ 如果私钥丢失，代币永久损失
- ⚠️ 如果地址填错，代币无法找回

### 7.2 建议的安全措施
1. **使用多签钱包**: 对于大额代币（节点、跨链、团队），建议使用 Gnosis Safe
2. **时间锁**: 至少对团队代币设置 6 个月锁仓期
3. **分批释放**: 市场营销和团队代币建议分批释放，避免一次性抛压
4. **透明度**: 所有地址应该公开，接受社区监督
