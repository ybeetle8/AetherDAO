## 概述

AetherDAO 的卖出机制包含两层税收体系：
- **普通交易税**：所有卖出交易都需支付的基础税费（3%）
- **盈利税**：仅在用户有盈利时额外收取的税费（盈利部分的 25%）

这种双层税收设计既保证了项目的可持续发展，又对盈利用户进行了合理的税收调节。

---

## 卖出税收结构

### 税收层级

```
卖出 100 AE 代币
    ↓
第一层：普通交易税（3%）
    ├─ 营销费：1.5%
    └─ 流动性累积费：1.5%
    ↓
第二层：盈利税（仅有盈利时）
    └─ 盈利部分的 25%
```

### 税率常量定义

位置：`contracts/AE/src/abstract/AEBase.sol:205-212`

```solidity
uint256 private constant BASIS_POINTS = 10000;              // 基点（100%）
uint256 private constant SELL_MARKETING_FEE = 150;          // 1.5% (150/10000)
uint256 private constant SELL_LIQUIDITY_ACCUM_FEE = 150;    // 1.5% (150/10000)
uint256 private constant PROFIT_TAX_RATE = 2500;            // 25% (2500/10000)
```

## 普通交易税详解

### 1. 营销费（1.5%）

#### 收取方式
- **计算公式**：`营销费 = 卖出金额 × 1.5%`
- **代币形式**：AE 代币
- **收取时机**：每次卖出交易时立即扣除

#### 资金去向
1. **累积阶段**
   - 扣除的 AE 代币转入合约地址
   - 累积到状态变量 `amountMarketingFee`
   - 代码位置：`AEBase.sol:820-823`
   ```solidity
   if (marketingFee > 0) {
       super._update(from, address(this), marketingFee);
       amountMarketingFee += marketingFee;
   }
   ```

2. **触发处理**
   - 当累积金额达到阈值时触发处理
   - 默认阈值：`swapAtAmount = 10000 ether`
   - 触发条件：`amountMarketingFee >= swapAtAmount`

3. **处理流程**
   - 将累积的 AE 代币 Swap 成 USDT
   - 使用 Uniswap Router 进行兑换
   - 转账到 `marketingAddress` 地址
   - 代码位置：`AEBase.sol:1213-1256`

#### 用途说明
营销费用于项目的市场推广、运营开支等，包括但不限于：
- 社区运营
- 市场推广
- 合作伙伴费用
- 项目开发支出

---

### 2. 流动性累积费（1.5%）

#### 收取方式
- **计算公式**：`流动性费 = 卖出金额 × 1.5%`
- **代币形式**：AE 代币
- **收取时机**：每次卖出交易时立即扣除

#### 资金去向
1. **累积阶段**
   - 扣除的 AE 代币转入合约地址
   - 累积到状态变量 `amountLPFee`
   - 代码位置：`AEBase.sol:824-827`
   ```solidity
   if (liquidityAccumFee > 0) {
       super._update(from, address(this), liquidityAccumFee);
       amountLPFee += liquidityAccumFee;
   }
   ```

2. **触发处理**
   - 当累积金额达到阈值时触发处理
   - 默认阈值：`swapAtAmount = 10000 ether`
   - 触发条件：`amountLPFee >= swapAtAmount`

3. **处理流程**
   - 直接作为 AE (BLA) 代币
   - 调用 `LiquidityStaking.depositBLARewards(amount)`
   - 分配给 LP 质押者作为奖励

#### 受益对象
- **LP 质押者**：在 LiquidityStaking 合约中质押 LP Token 的用户
- **奖励形式**：AE (BLA) 代币
- **领取方式**：通过 LiquidityStaking 合约的 `claimRewards()` 函数领取

## 盈利税详解

### 盈利判定机制

#### 1. 投资成本追踪
系统为每个用户维护一个投资成本记录：
- **状态变量**：`mapping(address => uint256) public userInvestment`
- **更新时机**：
  - 买入时：增加投资成本
  - 卖出时：按比例减少投资成本

#### 2. 盈利计算
代码位置：`AEBase.sol:799-809`

```solidity
// 估算卖出可获得的 USDT
uint256 estimatedUSDTFromSale = _estimateSwapOutput(netAmountAfterTradingFees);

// 获取用户当前投资成本
uint256 userCurrentInvestment = userInvestment[from];

// 判断是否有盈利
if (userCurrentInvestment > 0 && estimatedUSDTFromSale > userCurrentInvestment) {
    // 计算盈利金额
    profitAmount = estimatedUSDTFromSale - userCurrentInvestment;

    // 计算盈利税（25%）
    profitTaxUSDT = (profitAmount * PROFIT_TAX_RATE) / BASIS_POINTS;

    // 将盈利税转换为 AE 代币数量
    profitTaxInAE = (profitTaxUSDT * netAmountAfterTradingFees) / estimatedUSDTFromSale;
}
```

#### 3. 盈利示例

**场景 1：有盈利**
- 用户历史投资：1000 USDT
- 本次卖出估算收益：1500 USDT
- 盈利金额：1500 - 1000 = 500 USDT
- 盈利税：500 × 25% = 125 USDT
- 用户实际收到：1500 - 125 = 1375 USDT

**场景 2：无盈利**
- 用户历史投资：1000 USDT
- 本次卖出估算收益：800 USDT
- 盈利金额：0（亏损 200 USDT）
- 盈利税：0
- 用户实际收到：800 USDT

---

### 盈利税分配

盈利税收取后，按照固定比例分配到两个目标地址：

#### 分配比例
代码位置：`AEBase.sol:840-841`

```solidity
uint256 lsShare = (usdtAmountFromProfitTax * 10) / 25;  // 40%
uint256 nodeShare = usdtAmountFromProfitTax - lsShare;   // 60%
```

- **LiquidityStaking（40%）**：盈利税的 10/25
- **nodeDividendAddress（60%）**：盈利税的 15/25

---

#### 1. LiquidityStaking 分配（40%）

**处理流程**：
代码位置：`AEBase.sol:843-847`

```solidity
if (lsShare > 0) {
    IERC20(USDT).approve(address(liquidityStaking), lsShare);
    liquidityStaking.depositRewards(lsShare);
    emit LPRewardDeposited(lsShare);
}
```

**详细说明**：
- **金额**：盈利税的 40%
- **代币形式**：USDT
- **存入方式**：调用 `LiquidityStaking.depositRewards(lsShare)`
- **受益对象**：LP 质押者
- **奖励类型**：USDT 奖励（与流动性累积费的 AE 奖励不同）

**LP 质押者收益来源总结**：
1. 流动性累积费（1.5%）→ AE 代币奖励
2. 盈利税的 40% → USDT 奖励
3. 买入时的流动性费（2%）→ AE 代币奖励

---

#### 2. nodeDividendAddress 分配（60%）

**处理流程**：
代码位置：`AEBase.sol:849-854`

```solidity
if (nodeShare > 0) {
    address nodeAddr = nodeDividendAddress != address(0)
        ? nodeDividendAddress
        : marketingAddress;
    IERC20(USDT).transfer(nodeAddr, nodeShare);
}
```

**详细说明**：
- **金额**：盈利税的 60%
- **代币形式**：USDT
- **接收地址**：
  - 优先：`nodeDividendAddress`（如果已设置）
  - 备用：`marketingAddress`（如果 nodeDividendAddress 为空）
- **用途**：节点分红或项目运营

## 计算示例

### 示例 1：有盈利的卖出

**初始条件**：
- 用户持有：10,000 AE
- 用户历史投资成本：5,000 USDT
- 当前 AE 价格：0.6 USDT/AE
- 卖出数量：10,000 AE

**计算过程**：

#### 步骤 1：扣除普通交易税
```
营销费 = 10,000 × 1.5% = 150 AE
流动性费 = 10,000 × 1.5% = 150 AE
剩余 = 10,000 - 150 - 150 = 9,700 AE
```

#### 步骤 2：估算 USDT 收益
```
估算收益 = 9,700 × 0.6 = 5,820 USDT
```

#### 步骤 3：计算盈利税
```
盈利金额 = 5,820 - 5,000 = 820 USDT
盈利税 = 820 × 25% = 205 USDT
盈利税对应的 AE = 205 / 0.6 ≈ 341.67 AE
```

#### 步骤 4：实际卖出
```
实际卖出 AE = 9,700 - 341.67 = 9,358.33 AE
实际收到 USDT = 9,358.33 × 0.6 = 5,615 USDT
```

#### 步骤 5：盈利税分配
```
盈利税总额：205 USDT
├─ LiquidityStaking：205 × 40% = 82 USDT
└─ nodeDividendAddress：205 × 60% = 123 USDT
```

**最终结果**：
- 用户收到：5,615 USDT
- 营销费：150 AE（累积待处理）
- 流动性费：150 AE（累积待处理）
- LP 质押者获得：82 USDT
- 节点分红：123 USDT

**初始条件**：

**计算过程**：

## 技术实现细节

### 核心函数：_handleSell

位置：`contracts/AE/src/abstract/AEBase.sol:774-879`

```solidity
function _handleSell(
    address from,
    address to,
    uint256 amount
) private notBlacklisted(from) {
    // 1. 检查冷却期
    if (block.timestamp < lastBuyTime[from] + coldTime)
        revert InColdPeriod();

    // 2. 计算普通交易税
    uint256 marketingFee = (amount * SELL_MARKETING_FEE) / BASIS_POINTS;
    uint256 liquidityAccumFee = (amount * SELL_LIQUIDITY_ACCUM_FEE) / BASIS_POINTS;
    uint256 netAmountAfterTradingFees = amount - marketingFee - liquidityAccumFee;

    // 3. 估算 USDT 收益
    uint256 estimatedUSDTFromSale = _estimateSwapOutput(netAmountAfterTradingFees);

    // 4. 计算盈利税
    uint256 profitTaxUSDT = 0;
    uint256 profitTaxInAE = 0;
    uint256 userCurrentInvestment = userInvestment[from];

    if (userCurrentInvestment > 0 && estimatedUSDTFromSale > userCurrentInvestment) {
        uint256 profitAmount = estimatedUSDTFromSale - userCurrentInvestment;
        profitTaxUSDT = (profitAmount * PROFIT_TAX_RATE) / BASIS_POINTS;
        profitTaxInAE = (profitTaxUSDT * netAmountAfterTradingFees) / estimatedUSDTFromSale;
    }

    // 5. 扣除所有税费
    uint256 netAmount = amount - marketingFee - liquidityAccumFee - profitTaxInAE;

    // 6. 累积普通交易税
    if (marketingFee > 0) {
        super._update(from, address(this), marketingFee);
        amountMarketingFee += marketingFee;
    }
    if (liquidityAccumFee > 0) {
        super._update(from, address(this), liquidityAccumFee);
        amountLPFee += liquidityAccumFee;
    }

    // 7. 处理盈利税
    if (profitTaxInAE > 0) {
        super._update(from, address(this), profitTaxInAE);
        uint256 usdtAmountFromProfitTax = _swapTokensForUSDT(profitTaxInAE);

        if (usdtAmountFromProfitTax > 0) {
            // 分配给 LiquidityStaking (40%)
            uint256 lsShare = (usdtAmountFromProfitTax * 10) / 25;
            uint256 nodeShare = usdtAmountFromProfitTax - lsShare;

            if (lsShare > 0) {
                IERC20(USDT).approve(address(liquidityStaking), lsShare);
                liquidityStaking.depositRewards(lsShare);
            }

            // 分配给 nodeDividendAddress (60%)
            if (nodeShare > 0) {
                address nodeAddr = nodeDividendAddress != address(0)
                    ? nodeDividendAddress
                    : marketingAddress;
                IERC20(USDT).transfer(nodeAddr, nodeShare);
            }
        }
    }

    // 8. 执行实际转账
    super._update(from, to, netAmount);

    // 9. 更新用户投资成本
    _updateInvestmentAfterSell(from, actualUSDTReceived);
}
```

### 冷却期机制

**目的**：防止快速买卖套利

**实现**：
```solidity
uint256 public coldTime = 10 seconds;
mapping(address => uint256) public lastBuyTime;

// 卖出时检查
if (block.timestamp < lastBuyTime[from] + coldTime)
    revert InColdPeriod();
```

**说明**：
- 默认冷却期：10 秒
- 用户买入后必须等待 10 秒才能卖出
- 可通过管理员调整冷却时间

### 费用处理触发机制

位置：`contracts/AE/src/abstract/AEBase.sol:1213-1256`

**触发条件**：
```solidity
uint256 public swapAtAmount = 10000 ether;

// 在 _update 函数中检查
```

**处理流程**：
1. 检查累积金额是否达到阈值
2. 如果达到，触发 `_processFeeDistribution()`

### 投资成本更新

位置：`contracts/AE/src/abstract/AEBase.sol`

**买入时更新**：
```solidity
function _updateInvestmentAfterBuy(address user, uint256 usdtSpent) private {
    userInvestment[user] += usdtSpent;
}
```

**卖出时更新**：
```solidity
function _updateInvestmentAfterSell(address user, uint256 usdtReceived) private {
    uint256 currentInvestment = userInvestment[user];
    if (usdtReceived >= currentInvestment) {
        userInvestment[user] = 0;
    } else {
        userInvestment[user] = currentInvestment - usdtReceived;
    }
}
```

**说明**：
- 买入时：累加投资成本
- 卖出时：按比例减少投资成本
- 完全卖出后：投资成本归零

## 总结

### 资金最终去向汇总

| 费用类型 | 比例 | 代币形式 | 最终去向 | 受益对象 |
|---------|------|---------|---------|---------|
| 营销费 | 1.5% | AE → USDT | marketingAddress | 项目运营 |
| 流动性累积费 | 1.5% | AE | LiquidityStaking | LP 质押者 |
| 盈利税 - LS 部分 | 盈利×25%×40% | AE → USDT | LiquidityStaking | LP 质押者 |
| 盈利税 - 节点部分 | 盈利×25%×60% | AE → USDT | nodeDividendAddress | 节点/项目 |
| 用户收益 | 剩余 | USDT | 用户钱包 | 卖家 |

### 关键特性

1. **双层税收**：普通税 + 盈利税，合理调节市场
2. **盈利保护**：无盈利时不收取盈利税，保护亏损用户
3. **LP 激励**：多渠道奖励 LP 质押者（AE + USDT）
4. **自动处理**：费用累积到阈值后自动处理，节省 Gas
5. **透明可查**：所有交易通过事件记录，完全透明
