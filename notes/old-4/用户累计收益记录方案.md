# 用户累计收益记录方案

## 1. 需求概述

为每个地址新增两个**链上累计值**，只记录已领取（实际到账）的金额，未领取的不计入：

| 字段 | 含义 | 累加时机 |
|------|------|----------|
| **质押收益总数** | 用户通过 `unstake()` 和 `withdrawInterest()` 实际到账的 USDX 总额 | 每次 unstake / withdrawInterest 时，累加 `userPayout` |
| **社区收益总数** | 用户作为上级（推荐人链中的成员），通过团队奖励获得的 USDX 总额 | 每次 `_distributeHybridRewards()` 中 transfer 给该地址时，累加 `memberReward` |

## 2. 现状分析

### 2.1 质押收益发放路径

用户调用 `unstake()` 或 `withdrawInterest()` 时:

```
calculatedReward → swap AE→USDX → usdxReceived
  ├─ 5% educationFund → 教育基金地址
  ├─ 35% teamFee → 团队奖励（分配给上级链）
  └─ 剩余 userPayout
       ├─ 5% redemptionFee → feeRecipient
       └─ 最终 userPayout → 用户地址 ✅ 这就是"质押收益"
```

**当前状态**: 只有全局累计 `totalDividendsDistributed += userPayout`，没有逐用户记录。

### 2.2 社区收益发放路径

当下级用户触发 unstake / withdrawInterest 时:

```
_distributeTeamReward(referralChain, interest)
  └─ _distributeHybridRewards(referralChain, memberTiers, interest)
       └─ 遍历 referralChain，按差级制分配:
            IERC20(USDX).transfer(referralChain[i], memberReward) ✅ 这就是"社区收益"
```

**当前状态**: 仅通过 `StrictDifferentialRewardPaid` event 记录，没有链上累计值。

## 3. 解决方案

### 3.1 新增状态变量

在 `StakingBase.sol` 中新增两个 mapping：

```solidity
// =========================================================================
// PER-USER CUMULATIVE REWARD TRACKING
// =========================================================================

/// @notice 用户累计质押收益 (unstake / withdrawInterest 的 userPayout 之和)
mapping(address => uint256) public totalClaimedStakingReward;

/// @notice 用户累计社区收益 (作为推荐人获得的团队奖励之和)
mapping(address => uint256) public totalClaimedCommunityReward;
```

### 3.2 新增事件

在 `IStaking.sol` 中新增事件：

```solidity
/// @notice 用户质押收益累计值更新
/// @param user 用户地址
/// @param amount 本次到账金额
/// @param newTotal 更新后的累计总额
event UserStakingRewardUpdated(address indexed user, uint256 amount, uint256 newTotal);

/// @notice 用户社区收益累计值更新
/// @param user 用户地址
/// @param amount 本次到账金额
/// @param newTotal 更新后的累计总额
event UserCommunityRewardUpdated(address indexed user, uint256 amount, uint256 newTotal);
```

### 3.3 修改 `unstake()` 函数

在 `IERC20(USDX).transfer(msg.sender, userPayout)` 之后（约第 334 行），新增:

```solidity
// 累计用户质押收益
totalClaimedStakingReward[msg.sender] += userPayout;
emit UserStakingRewardUpdated(msg.sender, userPayout, totalClaimedStakingReward[msg.sender]);
```

### 3.4 修改 `withdrawInterest()` 函数

在 `IERC20(USDX).transfer(user, userPayout)` 之后（约第 419 行），新增:

```solidity
// 累计用户质押收益
totalClaimedStakingReward[user] += userPayout;
emit UserStakingRewardUpdated(user, userPayout, totalClaimedStakingReward[user]);
```

### 3.5 修改 `_distributeHybridRewards()` 函数

在 `IERC20(USDX).transfer(referralChain[i], memberReward)` 之后（约第 1449 行），新增:

```solidity
// 累计用户社区收益
totalClaimedCommunityReward[referralChain[i]] += memberReward;
emit UserCommunityRewardUpdated(referralChain[i], memberReward, totalClaimedCommunityReward[referralChain[i]]);
```

### 3.6 新增 `_distributeTeamReward()` 中 rootAddress 兜底情况

当 `referralChain.length == 0` 时，全部团队费转给 rootAddress（约第 1347 行），也需累加:

```solidity
IERC20(USDX).transfer(rootAddress, fee);
// rootAddress 作为兜底也累加社区收益
totalClaimedCommunityReward[rootAddress] += fee;
emit UserCommunityRewardUpdated(rootAddress, fee, totalClaimedCommunityReward[rootAddress]);
```

同理，`marketingAmount` 转给 rootAddress 的兜底部分（约第 1388 行）:

```solidity
IERC20(USDX).transfer(rootAddress, marketingAmount);
// rootAddress 兜底未分配部分也累加
totalClaimedCommunityReward[rootAddress] += marketingAmount;
emit UserCommunityRewardUpdated(rootAddress, marketingAmount, totalClaimedCommunityReward[rootAddress]);
```

### 3.7 新增查询接口

在 `IStaking.sol` 接口中新增:

```solidity
/// @notice 获取用户累计收益数据
/// @param user 用户地址
/// @return stakingReward 累计质押收益 (已领取)
/// @return communityReward 累计社区收益 (已领取)
function getUserRewardSummary(address user) external view returns (
    uint256 stakingReward,
    uint256 communityReward
);
```

在 `StakingBase.sol` 中实现:

```solidity
function getUserRewardSummary(address user) external view returns (
    uint256 stakingReward,
    uint256 communityReward
) {
    stakingReward = totalClaimedStakingReward[user];
    communityReward = totalClaimedCommunityReward[user];
}
```

## 4. 修改文件清单

| 文件 | 修改内容 |
|------|----------|
| `contracts/AE-Staking/src/interfaces/IStaking.sol` | 新增 2 个 event、`getUserRewardSummary` 函数声明 |
| `contracts/AE-Staking/src/abstract/StakingBase.sol` | 新增 2 个 mapping、修改 `unstake()` / `withdrawInterest()` / `_distributeHybridRewards()` / `_distributeTeamReward()`、实现 `getUserRewardSummary()` |

**不需要修改** `Staking.sol`（主网实现），所有逻辑都在 `StakingBase` 中。

## 5. Gas 开销分析

| 操作 | 额外开销 | 说明 |
|------|----------|------|
| `unstake()` | +1 SSTORE (~5,000 gas) + 1 event | 累加 `totalClaimedStakingReward` |
| `withdrawInterest()` | +1 SSTORE (~5,000 gas) + 1 event | 累加 `totalClaimedStakingReward` |
| `_distributeHybridRewards()` | +1 SSTORE/recipient (~5,000 gas each) + 1 event each | 累加 `totalClaimedCommunityReward` |
| `getUserRewardSummary()` | 0 (view) | 只读取 2 个 mapping |

每次操作额外增加约 5,000-10,000 gas，对于包含 swap 操作的交易（通常 200,000+ gas）影响很小。

## 6. 测试方案

在 `test/user-reward-summary/` 目录下编写测试。

### 测试用例

| 编号 | 测试项 | 说明 |
|------|--------|------|
| URS-1 | 初始值为零 | 未操作用户两项累计均为 0 |
| URS-2 | unstake 后质押收益累加 | unstake 后 `totalClaimedStakingReward` == userPayout |
| URS-3 | withdrawInterest 后质押收益累加 | withdrawInterest 后 `totalClaimedStakingReward` 增加 |
| URS-4 | 社区收益累加 | 下级 unstake 后，上级的 `totalClaimedCommunityReward` 增加 |
| URS-5 | 多次操作正确累加 | 多次 unstake 后质押收益持续累加 |
| URS-6 | `getUserRewardSummary` 返回一致 | view 函数返回值与直接查 mapping 一致 |
| URS-7 | 打印收益汇总 | 打印用户的质押收益总数和社区收益总数 |

### 测试关键打印

测试中需要明确打印以下值:

```javascript
const [stakingReward, communityReward] = await staking.getUserRewardSummary(user.address);
console.log(`用户 ${user.address}:`);
console.log(`  质押收益总数: ${formatEther(stakingReward)} USDX`);
console.log(`  社区收益总数: ${formatEther(communityReward)} USDX`);
```
