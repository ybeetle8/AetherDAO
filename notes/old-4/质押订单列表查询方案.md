# 质押订单列表查询方案

## 1. 需求概述

前端需要获取用户的**完整质押订单列表**，用于展示质押记录、计算收益、判断到期状态等。

## 2. 现有问题分析

### 2.1 当前合约已有的相关接口

| 函数 | 返回内容 | 问题 |
|------|----------|------|
| `userStakeRecord(address, uint256)` | 单条 Record (public mapping 自动生成) | 只能逐条查询，前端需循环 N 次 RPC 调用 |
| `stakeCount(address)` | 用户质押记录总数 | 只返回数量，不返回内容 |
| `getUserStakeWithdrawalStatus(address)` | 每笔质押的 index、能否提取、剩余时间 | 不含金额、质押时间、档位等关键信息 |
| `rewardOfSlot(address, uint8)` | 单笔质押的当前价值(含利息) | 只能逐条查询 |
| `canWithdrawStake(address, uint256)` | 单笔是否可提取 | 只能逐条查询 |

### 2.2 核心问题

**Solidity 的 public mapping 对数组类型的自动 getter，只支持按 index 查询单个元素，不能返回整个数组。**

```solidity
// 合约中的声明
mapping(address => IStaking.Record[]) public userStakeRecord;

// 自动生成的 getter 签名 — 只能查单条
function userStakeRecord(address user, uint256 index)
    external view returns (uint40 stakeTime, uint160 amount, bool status, uint8 stakeIndex);
```

前端想获取完整列表，目前只能：
1. 调 `stakeCount(addr)` 得到 N
2. 循环 N 次调用 `userStakeRecord(addr, 0)`, `userStakeRecord(addr, 1)`, ..., `userStakeRecord(addr, N-1)`

**问题**：
- N 次 RPC 请求，延迟高、体验差
- 公共 RPC 有限流，连续请求可能被拒
- 无法在一次调用中获得每笔的当前价值和到期信息

## 3. 解决方案

### 3.1 新增 `getUserStakeRecords` View 函数

在 `StakingBase.sol` 中新增一个批量查询函数，**一次 RPC 调用返回用户所有质押订单的完整信息**。

#### 新增返回结构体

在 `IStaking.sol` 中定义：

```solidity
/// @notice 前端展示用的质押订单完整信息
struct StakeOrderInfo {
    uint256 index;           // 质押记录索引
    uint40 stakeTime;        // 质押时间
    uint160 amount;          // 质押本金 (USDX)
    bool status;             // 是否已提取 (true = 已提取)
    uint8 stakeIndex;        // 质押档位 (0=7天, 1=30天, 2=90天, 3=180天, 4=365天)
    uint256 currentValue;    // 当前价值 (本金 + 利息)
    bool canWithdraw;        // 是否可以提取
    uint256 timeRemaining;   // 距到期剩余秒数 (0 = 已到期)
    uint256 earnedInterest;  // 已赚取利息 (currentValue - amount)
    uint256 withdrawnInterestAmount; // 已提取的利息金额
}
```

#### View 函数实现

在 `StakingBase.sol` 中实现：

```solidity
/// @notice 获取用户所有质押订单的完整信息
/// @param user 用户地址
/// @return orders 质押订单信息数组
function getUserStakeRecords(
    address user
) external view returns (IStaking.StakeOrderInfo[] memory orders) {
    IStaking.Record[] storage stakes = userStakeRecord[user];
    uint256 len = stakes.length;
    orders = new IStaking.StakeOrderInfo[](len);

    for (uint256 i = 0; i < len; i++) {
        IStaking.Record storage rec = stakes[i];

        uint256 currentVal = 0;
        uint256 interest = 0;
        bool canWd = false;
        uint256 remaining = 0;

        if (!rec.status) {
            // 未提取: 计算当前价值和利息
            currentVal = _calculateStakeReward(rec);
            interest = currentVal > rec.amount ? currentVal - rec.amount : 0;

            // 计算到期状态
            uint256 elapsed = block.timestamp - rec.stakeTime;
            uint256 required = getStakePeriod(rec.stakeIndex);
            canWd = elapsed >= required;
            remaining = canWd ? 0 : required - elapsed;
        }

        orders[i] = IStaking.StakeOrderInfo({
            index: i,
            stakeTime: rec.stakeTime,
            amount: rec.amount,
            status: rec.status,
            stakeIndex: rec.stakeIndex,
            currentValue: currentVal,
            canWithdraw: canWd,
            timeRemaining: remaining,
            earnedInterest: interest,
            withdrawnInterestAmount: withdrawnInterest[user][i]
        });
    }
}
```

### 3.2 接口声明

在 `IStaking.sol` 中新增：

```solidity
/// @notice 获取用户所有质押订单的完整信息
/// @param user 用户地址
/// @return orders 质押订单信息数组
function getUserStakeRecords(
    address user
) external view returns (StakeOrderInfo[] memory orders);
```

## 4. 前端调用示例

```javascript
// 一次调用获取全部质押订单
const orders = await staking.getUserStakeRecords(userAddress);

for (const order of orders) {
    console.log(`#${order.index} | 本金: ${formatEther(order.amount)} USDX`);
    console.log(`  档位: ${order.stakeIndex} | 质押时间: ${new Date(Number(order.stakeTime) * 1000)}`);
    console.log(`  当前价值: ${formatEther(order.currentValue)} USDX`);
    console.log(`  已赚利息: ${formatEther(order.earnedInterest)} USDX`);
    console.log(`  已提利息: ${formatEther(order.withdrawnInterestAmount)} USDX`);
    console.log(`  状态: ${order.status ? '已提取' : (order.canWithdraw ? '可提取' : `剩余 ${order.timeRemaining}s`)}`);
}
```

## 5. 修改文件清单

| 文件 | 修改内容 |
|------|----------|
| `contracts/AE-Staking/src/interfaces/IStaking.sol` | 新增 `StakeOrderInfo` 结构体、`getUserStakeRecords` 函数声明 |

**不需要修改** `Staking.sol` (mainnet 实现)，因为所有逻辑都在 `StakingBase` 中。

## 6. Gas 开销分析

- 这是一个 **view 函数**，不消耗 gas（只在链下执行）
- 时间复杂度 O(N)，N 为用户质押记录数
- 每条记录涉及一次 `_calculateStakeReward` 计算（PRB Math 复利计算）
- 对于典型用户（< 100 条记录），执行时间在毫秒级别

## 7. 对比旧方案

| 方案 | RPC 调用次数 | 数据完整性 | 延迟 |
|------|-------------|-----------|------|
| 逐条查询 (旧) | N+1 次 (`stakeCount` + N 次 `userStakeRecord`) | 缺少利息、到期等信息 | 高 |
| `getUserStakeRecords` (新) | **1 次** | 包含全部信息 | **低** |

| SOL-7 | 已提取利息金额正确 | withdrawInterest 后 `withdrawnInterestAmount` > 0 |
