# AE-Staking 时间加速测试方案

## 一、问题描述

AE-Staking 合约的质押期限包含 7/30/90/180/365 天，合约内部通过 `block.timestamp` 判断质押是否到期：

```solidity
if (block.timestamp - stakeTime < getStakePeriod(stakeIndex)) revert StakingPeriodNotMet();
```

复利计算也依赖时间差：

```solidity
stakingDuration = uint40(block.timestamp) - stakeStartTime;
compoundPeriods = stakingDuration / getCompoundTimeUnit(); // getCompoundTimeUnit() = 1 days
reward = principal × (dailyRate) ^ compoundPeriods
```

在本地测试网络上，不可能真正等待 365 天来验证到期赎回。需要一种方案来"加速时间"。

---

## 二、方案：Hardhat evm_increaseTime + evm_mine

Hardhat 本地节点提供了两个 RPC 方法来操控区块时间：

| 方法 | 作用 |
|------|------|
| `evm_increaseTime(seconds)` | 将节点内部时钟向前推进指定秒数 |
| `evm_mine` | 手动挖一个新区块（使新的时间戳生效） |

两者配合使用，可以让 `block.timestamp` 瞬间跳到未来任意时刻。

### 基本用法

```javascript
const { ethers, network } = require("hardhat");

// 向前推进 30 天
async function advanceTime(days) {
  const seconds = days * 24 * 60 * 60;
  await network.provider.send("evm_increaseTime", [seconds]);
  await network.provider.send("evm_mine");
}

// 使用示例
await advanceTime(30); // 推进 30 天
```

### 精确推进到指定时间点

```javascript
// 推进到某个质押的到期时间
async function advanceToTimestamp(targetTimestamp) {
  const currentBlock = await ethers.provider.getBlock("latest");
  const currentTime = currentBlock.timestamp;
  const diff = targetTimestamp - currentTime;
  if (diff > 0) {
    await network.provider.send("evm_increaseTime", [diff]);
    await network.provider.send("evm_mine");
  }
}
```

## 三、测试中的具体应用

### 3.1 验证到期赎回（以 365 天为例）

```javascript
// 1. 用户质押（stakeIndex = 4，即 365 天）
await staking.connect(user).stake(amount, 4);

// 2. 记录质押时间
const stakeRecord = await staking.getUserStakeRecord(user.address, 0);
const stakeTime = stakeRecord.stakeTime;

// 3. 验证未到期不能赎回
await expect(staking.connect(user).unstake(0)).to.be.revertedWithCustomError(
  staking, "StakingPeriodNotMet"
);

// 4. 时间推进 365 天
await advanceTime(365);

// 5. 现在可以赎回
await staking.connect(user).unstake(0); // 应成功
```

### 3.2 验证复利计算

```javascript
// 质押 1000 USDT，30 天期，日利率 1.009
await staking.connect(user).stake(parseEther("1000"), 1);

// 推进 30 天
await advanceTime(30);

// 赎回并验证收益
// 预期: 1000 × 1.009^30 ≈ 1309.56 USDT
const balanceBefore = await usdx.balanceOf(user.address);
await staking.connect(user).unstake(0);
const balanceAfter = await usdx.balanceOf(user.address);
```

### 3.3 验证提前提取利息（中途时间点）

```javascript
// 质押 90 天期
await staking.connect(user).stake(amount, 2);

// 推进 45 天（一半时间）
await advanceTime(45);

// 提取已产生的利息
await staking.connect(user).withdrawInterest(0);

// 再推进 45 天（到期）
await advanceTime(45);

// 赎回本金 + 剩余利息
await staking.connect(user).unstake(0);
```

## 四、注意事项

### 4.1 时间推进是全局的

`evm_increaseTime` 影响整个节点的时间。如果一个测试推进了 365 天，后续测试的 `block.timestamp` 也会在这个基础上继续。

**应对策略**：每个测试模块使用独立的用户账户和质押记录，不依赖绝对时间，只依赖相对时间差。

### 4.2 mining 配置的影响

当前 hardhat.config.js 中配置了自动挖矿：

```javascript
mining: {
  auto: true,
  interval: 3000  // 每3秒自动挖一个块
}
```

`auto: true` 意味着每笔交易自动出块，`evm_mine` 会额外出一个块。这不影响时间推进的正确性，因为 `evm_increaseTime` 直接修改的是节点内部时钟。

### 4.3 Hardhat 快照（可选优化）

如果需要在同一个部署环境下反复测试不同时间场景，可以使用快照：

```javascript
// 保存当前状态
const snapshotId = await network.provider.send("evm_snapshot");

// ... 执行测试（包括时间推进）...

// 恢复到快照时的状态（时间也会恢复）
await network.provider.send("evm_revert", [snapshotId]);
```

这样可以避免时间推进的累积效应，让每个测试场景从相同的起点开始。

### 4.4 推进天数 vs 推进秒数

合约中 `getStakePeriod` 返回的是秒数（`7 days` = 604800 秒）。`advanceTime(days)` 内部转换为秒数，与合约逻辑一致。

如果需要测试边界（比如"差 1 秒到期"），可以直接用秒数：

```javascript
// 推进到差 1 秒到期
const period = 30 * 24 * 60 * 60; // 30 天的秒数
await network.provider.send("evm_increaseTime", [period - 1]);
await network.provider.send("evm_mine");

// 此时赎回应失败
await expect(staking.connect(user).unstake(0)).to.be.reverted;

// 再推进 1 秒
await network.provider.send("evm_increaseTime", [1]);
await network.provider.send("evm_mine");

// 现在应成功
await staking.connect(user).unstake(0);
```

## 五、测试工具函数封装

建议在测试代码中封装以下工具函数，供所有模块复用：

```javascript
// test/helpers/time.js

async function advanceTime(days) {
  const seconds = days * 24 * 60 * 60;
  await network.provider.send("evm_increaseTime", [seconds]);
  await network.provider.send("evm_mine");
}

async function advanceTimeSeconds(seconds) {
  await network.provider.send("evm_increaseTime", [seconds]);
  await network.provider.send("evm_mine");
}

async function getBlockTimestamp() {
  const block = await ethers.provider.getBlock("latest");
  return block.timestamp;
}

async function takeSnapshot() {
  return await network.provider.send("evm_snapshot");
}

async function revertSnapshot(snapshotId) {
  await network.provider.send("evm_revert", [snapshotId]);
}

module.exports = {
  advanceTime,
  advanceTimeSeconds,
  getBlockTimestamp,
  takeSnapshot,
  revertSnapshot,
};
```

---

## 六、结论

使用 Hardhat 的 `evm_increaseTime` + `evm_mine` 是标准且可靠的时间加速方案，无需修改合约代码，完全在测试层面解决问题。所有 5 种期限（7/30/90/180/365 天）都可以在几秒内完成测试。
