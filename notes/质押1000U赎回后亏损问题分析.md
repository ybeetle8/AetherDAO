# 质押 1000U 赎回后亏损问题分析

## 问题描述

用户质押 1000 USDX，选择 7 天档位，到期赎回后钱包余额比质押前**少了约 25.62 USDX**。

预期：7 天复利 (日利率 0.6%)，利息约 42.76 USDX，赎回后应盈利。
实际：用户净亏损 25.62 USDX。

## 测试数据

| 项目 | 金额 (USDX) |
|------|-------------|
| 质押前余额 | 5000.00 |
| 质押金额 | 1000.00 |
| 质押后余额 | 4000.00 |
| 预计利息 (1000 × 1.006^7 - 1000) | 42.76 |
| 赎回后余额 | 4974.38 |
| **净亏损** | **-25.62** |

## 赎回提款记录详情

| 项目 | 金额 (USDX) |
|------|-------------|
| 本金 | 1000.00 |
| 计算奖励 (AE 价值) | 1042.76 |
| 换回 USDX (usdxReceived) | 1042.76 |
| 利息 (interestEarned) | 42.76 |
| 教育基金费 (5% × 利息) | 2.14 |
| 团队奖励费 (35% × 利息) | 14.97 |
| **赎回手续费 (5% × userPayout)** | **51.28** |
| 用户实收 (userPayout) | 974.38 |

## 根因分析

### 核心问题：赎回手续费(5%)是对「本金+净利息」整体收取的，而非仅对利息收取

查看 `StakingBase.sol` 第 312~320 行的 `unstake()` 函数：

```solidity
// 第312行：userPayout = 总换回金额 - 教育基金费 - 团队奖励费
uint256 userPayout = usdxReceived - educationFund - teamFee;

// 第315行：赎回手续费 = userPayout × 5%
uint256 expectedRedemptionFeeUSDX = (userPayout * REDEMPTION_FEE_RATE) /
    BASIS_POINTS_DENOMINATOR;

// 第320行：再从 userPayout 中扣除赎回手续费
userPayout -= expectedRedemptionFeeUSDX;
```

### 费用计算详细推导

```
usdxReceived = 1042.76  (AE → USDX 兑换所得，等于本金+利息)

第一层扣费（仅从利息 42.76 中扣）：
  educationFund = 42.76 × 5%  = 2.14
  teamFee       = 42.76 × 35% = 14.97
  小计 = 17.11

第二层扣费（从整体扣，问题在这里）：
  userPayout（扣费前）= 1042.76 - 2.14 - 14.97 = 1025.65
  redemptionFee = 1025.65 × 5% = 51.28    ← 这里的 1025.65 包含了 1000 本金!
  userPayout（最终）= 1025.65 - 51.28 = 974.38
```

### 费用的实际归属分解

将 51.28 的赎回手续费按比例分解到本金和利息：

| 费用来源 | 基数 | 赎回手续费 (5%) |
|---------|------|----------------|
| 本金部分 | 1000.00 | **50.00** |
| 净利息部分 (42.76 - 17.11) | 25.65 | 1.28 |
| 合计 | 1025.65 | 51.28 |

**本金被收取了 50 USDX 的赎回手续费**，这是用户亏损的直接原因。

## 用户实际收益率

```
投入：1000 USDX
收回：974.38 USDX
净亏损：25.62 USDX
实际收益率：-2.56%
```

对比各项费用占利息的比例：

| 费用项 | 金额 | 占利息比例 |
|--------|------|-----------|
| 教育基金 | 2.14 | 5% |
| 团队奖励 | 14.97 | 35% |
| 赎回手续费 | 51.28 | **119.9%** |
| **费用总计** | **68.39** | **159.9%** |

费用总额 (68.39) 超过了利息 (42.76) 的 1.6 倍，因此用户必然亏损。

## 问题代码定位

**文件**: `contracts/AE-Staking/src/abstract/StakingBase.sol`

**第 312~320 行** — `unstake()` 函数中的赎回手续费计算：

```solidity
uint256 userPayout = usdxReceived - educationFund - teamFee;  // 第312行

uint256 expectedRedemptionFeeUSDX = (userPayout * REDEMPTION_FEE_RATE) /  // 第315行
    BASIS_POINTS_DENOMINATOR;  // 第316行
```

`userPayout` 此时包含了全额本金，导致 5% 赎回手续费覆盖了本金。

## 对比：如果赎回手续费仅从利息中收取

```
利息 = 42.76
教育基金 = 42.76 × 5%  = 2.14
团队奖励 = 42.76 × 35% = 14.97
净利息 = 42.76 - 2.14 - 14.97 = 25.65
赎回手续费 = 25.65 × 5% = 1.28
用户实收利息 = 25.65 - 1.28 = 24.37
用户总收回 = 1000 + 24.37 = 1024.37  ← 盈利 24.37 USDX
```

## 结论

赎回手续费的计算基数有误。当前实现将 5% 赎回手续费应用于 `usdxReceived - educationFund - teamFee`（即本金+净利息），而非仅应用于利息部分。由于本金远大于利息（1000 vs 42.76），本金被收取的赎回手续费 (~50 USDX) 远超利息本身，导致用户必然亏损。

7 天档位由于利息最少（仅 4.27%），受此问题影响最严重，用户不可能盈利。其他更长档位也会受到影响，但利息更高可能勉强覆盖本金上的手续费。
