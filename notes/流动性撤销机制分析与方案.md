# 流动性撤销机制分析与方案

## 问题描述

用户反馈"不能撤销流动性"，需要等一定时间才行。本文分析合约源码中所有涉及流动性撤销的时间限制机制。

---

## 一、涉及的合约和流动性类型

系统中有 **两种流动性** 相关操作，对应不同的合约：

| 类型 | 合约 | 说明 |
|------|------|------|
| AE 质押 (Staking) | `StakingBase.sol` | 用户质押 USDX，合约自动将一半 swap 成 AE 后添加流动性，LP 发送到 `address(0)` 永久锁定 |
| LP 质押 (LiquidityStaking) | `LiquidityStakingBase.sol` | 用户自行将 LP Token 质押到合约中赚取奖励 |

---

## 二、时间限制机制详细分析

### 2.1 AE Staking 合约的时间锁 — `unstake()` / `_burn()`

**代码位置**: `StakingBase.sol` 第 1276-1309 行

```solidity
function _burn(uint256 index) private returns (uint256 reward, uint256 amount) {
    // ...
    if (block.timestamp - stakeTime < getStakePeriod(user_record.stakeIndex))
        revert StakingPeriodNotMet();
    // ...
}
```

**五个质押期限**（主网配置，`Staking.sol`）：

| stakeIndex | 期限 | 日利率 |
|------------|------|--------|
| 0 | **7 天** | 0.6% |
| 1 | **30 天** | 0.9% |
| 2 | **90 天** | 1.1% |
| 3 | **180 天** | 1.5% |
| 4 | **365 天** | 2.0% |

**关键结论**：用户质押时选择的档位决定了锁定期，未到期调用 `unstake()` 会 revert `StakingPeriodNotMet`。

**但是**，这里的"流动性"（LP Token）是发送到 `address(0)` 的，**用户本身就无法取回 LP**。用户取回的是通过 swap AE→USDX 得到的 USDX。所以这个时间限制是质押本金的锁定期，不是 LP 的撤销限制。

### 2.2 LP 质押合约的时间锁 — `unstake()`

**代码位置**: `LiquidityStakingBase.sol` 第 180-223 行

```solidity
function unstake(uint256 amount) external nonReentrant updateReward(msg.sender) {
    // ...
    if (block.timestamp < userStake.stakeTime + getMinStakeDuration()) {
        revert InsufficientStakeTime();
    }
    // ...
}
```

**主网配置**（`LiquidityStaking.sol` 第 30 行）：

```solidity
function getMinStakeDuration() internal pure override returns (uint256) {
    return 24 hours;  // 最短质押24小时
}
```

**关键结论**：用户在 LiquidityStaking 合约中质押 LP Token 后，**必须等待至少 24 小时** 才能调用 `unstake()` 取回 LP。在此之前调用会 revert `InsufficientStakeTime`。

### 2.3 AE Token 的冷却期 — `coldTime`

**代码位置**: `AEBase.sol` 第 786 行

```solidity
function _handleSell(address from, address to, uint256 amount) private {
    if (block.timestamp < lastBuyTime[from] + coldTime)
        revert InColdPeriod();
    // ...
}
```

**默认值**: `coldTime = 10 seconds`

这是买入后的卖出冷却期，与流动性撤销无直接关系，但如果用户通过 Router 操作 removeLiquidity（本质上包含一次 swap/transfer），可能触发此限制。

## 三、核心问题定位

**用户"不能撤销流动性"最可能的原因是：**

### 场景 A：LP 质押合约的 24 小时锁（最可能）

用户将 LP Token 质押到 `LiquidityStaking` 合约赚取奖励，质押后未满 24 小时尝试 unstake，被 `InsufficientStakeTime` 拒绝。

**验证方式**：调用 `canWithdrawStake(userAddress)` 查看返回值。

### 场景 B：AE Staking 的锁定期

用户质押 USDX 后在锁定期内（7~365天）尝试 unstake，被 `StakingPeriodNotMet` 拒绝。

**验证方式**：调用 `canWithdrawStake(userAddress, stakeIndex)` 查看返回值。

### 场景 C：LP Token 被发送到 address(0)

在 AE Staking 的 `_swapAndAddLiquidity()` 中（第 1641-1649 行）：

```solidity
ROUTER.addLiquidity(
    address(USDX),
    address(AE),
    remainingUsdx,
    aeTokensReceived,
    amountUsdxMin,
    amountAeMin,
    address(0),      // ← LP 接收方是 address(0)！
    block.timestamp
);
```

**LP Token 被发送到了零地址，等同于永久销毁。** 这意味着通过 Staking 合约添加的流动性本身就是**不可撤销的**——这是设计意图（协议拥有流动性 POL 模式），不是 bug。

## 四、方案建议

### 方案 1：前端提示优化（推荐）

**不修改合约**，在前端明确展示时间限制信息：

- **LiquidityStaking**：展示剩余锁定时间，合约已提供 `canWithdrawStake()` 函数，会返回 `(canWithdraw, stakedAmount, timeRemaining)`
- **AE Staking**：展示质押到期时间，合约已提供 `getUserStakeWithdrawalStatus()` 和 `getUserStakeRecords()`

### 方案 2：减少 LP 质押最短锁定期（如需调整）

当前 `getMinStakeDuration()` 硬编码为 `24 hours`。如需缩短：

- 修改 `LiquidityStaking.sol` 中的返回值
- 或改为 owner 可配置的 state variable

```solidity
// 改为可配置
uint256 public minStakeDuration = 24 hours;

function setMinStakeDuration(uint256 _duration) external onlyOwner {
    require(_duration >= 1 hours, "Too short"); // 防止闪电贷攻击
    minStakeDuration = _duration;
}
```

> **注意**：最低不建议低于 1 小时，否则可能被闪电贷攻击利用（存入 LP → 领取奖励 → 立即取出）。

### 方案 3：添加紧急撤回功能（保守方案）

在 LiquidityStaking 合约中添加一个紧急撤回函数，允许用户在锁定期内撤回 LP，但放弃所有奖励：

```solidity
function emergencyUnstake() external nonReentrant {
    StakeInfo storage userStake = stakes[msg.sender];
    if (userStake.amount == 0) revert NoStakeFound();

    uint256 amount = userStake.amount;
    userStake.amount = 0;
    rewardPool.totalStaked -= amount;
    _removeStaker(msg.sender);

    // 不发放奖励，直接返还 LP
    IERC20(lpToken).transfer(msg.sender, amount);
    emit Unstaked(msg.sender, amount, 0);
}
```

---

## 五、总结

| 限制 | 来源 | 时长 | 可否修改 |
|------|------|------|----------|
| LP 质押最短锁定期 | `LiquidityStaking.getMinStakeDuration()` | 24 小时 | 需升级合约 |
| AE 质押锁定期 | `StakingBase._burn()` → `getStakePeriod()` | 7~365 天 | 需升级合约 |
| Staking 添加的 LP | `_swapAndAddLiquidity()` → `address(0)` | 永久锁定 | 设计如此，不可变 |
| AE 卖出冷却期 | `AEBase.coldTime` | 10 秒 | Owner 可调整 |

**建议首先确认用户遇到的是哪个场景，再决定采取哪个方案。** 如果是场景 A（LP 质押 24 小时锁），前端提示即可解决用户困惑。
