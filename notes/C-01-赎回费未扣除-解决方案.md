# C-01: unstake 赎回费未从 userPayout 中扣除 — 解决方案

## 一、问题回顾

### 1.1 漏洞本质

在 `unstake` 和 `withdrawInterest` 两个函数中，赎回费（0.6%）的计算和收取存在逻辑错误：

- 赎回费基于 `userPayout` 计算，但**没有从 `userPayout` 中扣除**
- 赎回费通过额外调用 `_swapAEForReward` 从合约 AE 储备中支出
- 用户最终拿到的是**未扣除赎回费的全额**

### 1.2 受影响代码

**`unstake` 函数** (`StakingBase.sol:265-302`)：

```solidity
// 第265行：userPayout 计算完毕，未包含赎回费扣除
uint256 userPayout = usdxReceived - educationFund - teamFee;

// 第268-269行：赎回费基于 userPayout 计算
uint256 expectedRedemptionFeeUSDX = (userPayout * REDEMPTION_FEE_RATE) /
    BASIS_POINTS_DENOMINATOR;

// 第271-286行：赎回费从 AE 储备额外 swap 出来，但 userPayout 没有减少
if (expectedRedemptionFeeUSDX > 0 && feeRecipient != address(0)) {
    (, uint256 redemptionFeeAEUsed) = _swapAEForReward(expectedRedemptionFeeUSDX);
    // ... emit event
}

// 第302行：用户拿到未扣赎回费的 userPayout
IERC20(USDX).transfer(msg.sender, userPayout);
```

**`withdrawInterest` 函数** (`StakingBase.sol:358-382`) 存在完全相同的问题。

### 1.3 经济影响量化

假设用户 unstake 获得 10,000 USDX（扣除教育基金和团队费后）：

| 项目 | 当前（有 bug） | 预期（正确） | 差异 |
|------|---------------|-------------|------|
| userPayout | 10,000 USDX | 10,000 USDX | — |
| 赎回费 (0.6%) | 60 USDX | 60 USDX | — |
| 用户实际收到 | **10,000 USDX** | **9,940 USDX** | +60 USDX |
| 赎回费来源 | AE 储备额外支出 | 从 userPayout 扣除 | — |
| feeRecipient 收到 | **0 USDX**（M-07 bug） | **60 USDX** | -60 USDX |

每次操作合约额外损失 = userPayout × 0.6% 的 AE 等值。

## 二、关联问题

C-01 实际上与以下两个审计发现紧密关联，建议一并修复：

| 编号 | 问题 | 关联性 |
|------|------|--------|
| **C-01** | 赎回费未从 userPayout 扣除 | 本问题 |
| **M-06** | `AE.recycle` 未包含赎回费消耗的 AE | 赎回费 swap 的 AE 未被 recycle |
| **M-07** | 赎回费 USDX 未实际转给 feeRecipient | swap 出的 USDX 留在合约中 |

三个问题的根因相同：赎回费的整个处理流程设计有缺陷。

---

## 三、解决方案

### 3.1 核心思路

不再通过额外的 `_swapAEForReward` 来支付赎回费，而是直接从 `userPayout` 中扣除赎回费金额，然后将扣除的 USDX 转给 `feeRecipient`。

这样做的好处：
1. 赎回费从用户应得金额中扣除（符合设计意图）
2. 不额外消耗合约 AE 储备
3. feeRecipient 实际收到赎回费 USDX
4. 消除了赎回费 AE 未 recycle 的问题（因为不再需要额外 swap）

### 3.2 `unstake` 函数修复

**修复前**（当前代码）：

```solidity
uint256 userPayout = usdxReceived - educationFund - teamFee;

uint256 expectedRedemptionFeeUSDX = (userPayout * REDEMPTION_FEE_RATE) /
    BASIS_POINTS_DENOMINATOR;

if (expectedRedemptionFeeUSDX > 0 && feeRecipient != address(0)) {
    (, uint256 redemptionFeeAEUsed) = _swapAEForReward(expectedRedemptionFeeUSDX);
    emit RedemptionFeeCollected(
        msg.sender, stakeIndex, redemptionFeeAEUsed,
        expectedRedemptionFeeUSDX, feeRecipient, block.timestamp
    );
}

unchecked {
    _recordWithdrawal(...);
    IERC20(USDX).transfer(msg.sender, userPayout);
}

AE.recycle(aeTokensUsed);
```

**修复后**：

```solidity
uint256 userPayout = usdxReceived - educationFund - teamFee;

// 计算赎回费
uint256 redemptionFee = (userPayout * REDEMPTION_FEE_RATE) /
    BASIS_POINTS_DENOMINATOR;

// ✅ 关键修复：从 userPayout 中扣除赎回费
if (redemptionFee > 0 && feeRecipient != address(0)) {
    userPayout -= redemptionFee;

    // ✅ 修复 M-07：实际将赎回费转给 feeRecipient
    IERC20(USDX).transfer(feeRecipient, redemptionFee);

    emit RedemptionFeeCollected(
        msg.sender,
        stakeIndex,
        0,                // aeUsed = 0，不再从 AE 储备支出
        redemptionFee,
        feeRecipient,
        block.timestamp
    );
}

unchecked {
    _recordWithdrawal(
        msg.sender, stakeIndex, principalAmount,
        calculatedReward, usdxReceived, aeTokensUsed,
        educationFund, teamFee, userPayout, interestEarned
    );

    IERC20(USDX).transfer(msg.sender, userPayout);
}

// ✅ 修复 M-06：不再有额外的赎回费 AE 需要 recycle
AE.recycle(aeTokensUsed);
```

### 3.3 `withdrawInterest` 函数修复

**修复前**（当前代码）：

```solidity
uint256 userPayout = usdxReceived - educationFund - teamFee;

uint256 expectedRedemptionFeeUSDX = (userPayout * REDEMPTION_FEE_RATE) /
    BASIS_POINTS_DENOMINATOR;

if (expectedRedemptionFeeUSDX > 0 && feeRecipient != address(0)) {
    (, uint256 redemptionFeeAEUsed) = _swapAEForReward(expectedRedemptionFeeUSDX);
    emit RedemptionFeeCollected(
        user, stakeIndex, redemptionFeeAEUsed,
        expectedRedemptionFeeUSDX, feeRecipient, block.timestamp
    );
}

IERC20(USDX).transfer(user, userPayout);
AE.recycle(aeTokensUsed);
```

**修复后**：

```solidity
uint256 userPayout = usdxReceived - educationFund - teamFee;

// 计算赎回费
uint256 redemptionFee = (userPayout * REDEMPTION_FEE_RATE) /
    BASIS_POINTS_DENOMINATOR;

// ✅ 关键修复：从 userPayout 中扣除赎回费
if (redemptionFee > 0 && feeRecipient != address(0)) {
    userPayout -= redemptionFee;

    // ✅ 修复 M-07：实际将赎回费转给 feeRecipient
    IERC20(USDX).transfer(feeRecipient, redemptionFee);

    emit RedemptionFeeCollected(
        user,
        stakeIndex,
        0,                // aeUsed = 0，不再从 AE 储备支出
        redemptionFee,
        feeRecipient,
        block.timestamp
    );
}

// 转给用户（已扣除赎回费）
IERC20(USDX).transfer(user, userPayout);

// ✅ 修复 M-06：不再有额外的赎回费 AE 需要 recycle
AE.recycle(aeTokensUsed);
```

## 四、修改点汇总

| 文件 | 行号范围 | 修改内容 |
|------|---------|---------|
| `StakingBase.sol` | 265-306 | `unstake`：赎回费从 userPayout 扣除 + 转给 feeRecipient + 移除额外 swap |
| `StakingBase.sol` | 358-385 | `withdrawInterest`：同上 |

### 4.1 变更对比表

| 行为 | 修复前 | 修复后 |
|------|--------|--------|
| 赎回费来源 | 合约 AE 储备额外 swap | 从 userPayout 直接扣除 |
| 用户收到金额 | userPayout（未扣赎回费） | userPayout - redemptionFee |
| feeRecipient 收到 | 0（USDX 留在合约中） | redemptionFee 的 USDX |
| AE 储备消耗 | 额外消耗（赎回费等值 AE） | 无额外消耗 |
| 赎回费 AE 的 recycle | 遗漏（M-06 bug） | 不再需要（无额外 AE swap） |

## 五、事件兼容性说明

`RedemptionFeeCollected` 事件签名：

```solidity
event RedemptionFeeCollected(
    address indexed user,
    uint256 indexed stakeIndex,
    uint256 aeTokensUsed,       // 修复后此值为 0
    uint256 usdxFeeAmount,
    address indexed feeRecipient,
    uint256 timestamp
);
```

修复后 `aeTokensUsed` 参数将始终为 0，因为赎回费不再通过 AE swap 获取。如果前端或索引器依赖此字段，需要相应更新。

如果希望保持事件语义清晰，可以考虑新增一个事件或修改事件定义，移除 `aeTokensUsed` 字段：

```solidity
// 可选：简化事件
event RedemptionFeeCollected(
    address indexed user,
    uint256 indexed stakeIndex,
    uint256 usdxFeeAmount,
    address indexed feeRecipient,
    uint256 timestamp
);
```

## 六、资金流对比图

### 6.1 修复前的资金流（有 bug）

```
unstake 触发
    │
    ├─ _swapAEForReward(calculatedReward)
    │   └─ AE储备 ──swap──> usdxReceived (留在合约)
    │
    ├─ educationFund = 5% of interestEarned ──> educationFundAddress
    ├─ teamFee = 35% of interestEarned ──> 推荐链
    │
    ├─ userPayout = usdxReceived - educationFund - teamFee
    │
    ├─ redemptionFee = 0.6% of userPayout
    │   └─ _swapAEForReward(redemptionFee)  ❌ 额外消耗 AE 储备
    │       └─ AE储备 ──swap──> USDX (留在合约中, 未转给 feeRecipient) ❌
    │
    └─ IERC20(USDX).transfer(user, userPayout)  ❌ 未扣除赎回费
```

### 6.2 修复后的资金流（正确）

```
unstake 触发
    │
    ├─ _swapAEForReward(calculatedReward)
    │   └─ AE储备 ──swap──> usdxReceived (留在合约)
    │
    ├─ educationFund = 5% of interestEarned ──> educationFundAddress
    ├─ teamFee = 35% of interestEarned ──> 推荐链
    │
    ├─ userPayout = usdxReceived - educationFund - teamFee
    │
    ├─ redemptionFee = 0.6% of userPayout
    │   ├─ userPayout -= redemptionFee              ✅ 从用户金额扣除
    │   └─ IERC20(USDX).transfer(feeRecipient, redemptionFee)  ✅ 转给接收者
    │
    └─ IERC20(USDX).transfer(user, userPayout)     ✅ 已扣除赎回费
```

## 七、测试验证要点

### 7.1 基本功能测试

```
1. unstake 后用户收到的 USDX = usdxReceived - educationFund - teamFee - redemptionFee
2. feeRecipient 收到 redemptionFee 数量的 USDX
3. 合约 AE 余额变化 = 仅 calculatedReward 对应的 swap（无额外赎回费 swap）
4. withdrawInterest 同上
```

### 7.2 边界条件测试

```
1. feeRecipient == address(0) 时，不扣除赎回费，用户收到完整 userPayout
2. redemptionFee 计算结果为 0 时（极小金额 stake），跳过赎回费逻辑
3. 连续多次 withdrawInterest 后 unstake，赎回费均正确扣除
```

### 7.3 经济模型验证

```
1. 对比修复前后，合约 AE 储备消耗量（修复后应减少）
2. 验证 feeRecipient 累计收到的赎回费总额与预期一致
3. 大额 unstake 场景下赎回费计算精度
```
