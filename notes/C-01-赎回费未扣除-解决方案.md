# C-01: unstake 赎回费未从 userPayout 中扣除 — 解决方案

## 一、问题回顾

### 1.1 漏洞本质

在 `unstake` 和 `withdrawInterest` 两个函数中，赎回费（0.6%）的计算和收取存在逻辑错误：

- 赎回费基于 `userPayout` 计算，但**没有从 `userPayout` 中扣除**
- 赎回费通过额外调用 `_swapAEForReward` 从合约 AE 储备中支出
- 用户最终拿到的是**未扣除赎回费的全额**

### 1.2 受影响代码

**`unstake` 函数** (`StakingBase.sol:265-302`)：

```solidity
// 第265行：userPayout 计算完毕，未包含赎回费扣除
uint256 userPayout = usdxReceived - educationFund - teamFee;

// 第268-269行：赎回费基于 userPayout 计算
uint256 expectedRedemptionFeeUSDX = (userPayout * REDEMPTION_FEE_RATE) /
    BASIS_POINTS_DENOMINATOR;

// 第271-286行：赎回费从 AE 储备额外 swap 出来，但 userPayout 没有减少
if (expectedRedemptionFeeUSDX > 0 && feeRecipient != address(0)) {
    (, uint256 redemptionFeeAEUsed) = _swapAEForReward(expectedRedemptionFeeUSDX);
    // ... emit event
}

// 第302行：用户拿到未扣赎回费的 userPayout
IERC20(USDX).transfer(msg.sender, userPayout);
```

**`withdrawInterest` 函数** (`StakingBase.sol:358-382`) 存在完全相同的问题。

### 1.3 经济影响量化

假设用户 unstake 获得 10,000 USDX（扣除教育基金和团队费后）：

| 项目 | 当前（有 bug） | 预期（正确） | 差异 |
|------|---------------|-------------|------|
| userPayout | 10,000 USDX | 10,000 USDX | — |
| 赎回费 (0.6%) | 60 USDX | 60 USDX | — |
| 用户实际收到 | **10,000 USDX** | **9,940 USDX** | +60 USDX |
| 赎回费来源 | AE 储备额外支出 | 从 userPayout 扣除 | — |
| feeRecipient 收到 | **0 USDX**（M-07 bug） | **60 USDX** | -60 USDX |

每次操作合约额外损失 = userPayout × 0.6% 的 AE 等值。

## 二、关联问题

C-01 实际上与以下两个审计发现紧密关联，建议一并修复：

| 编号 | 问题 | 关联性 |
|------|------|--------|
| **C-01** | 赎回费未从 userPayout 扣除 | 本问题 |
| **M-06** | `AE.recycle` 未包含赎回费消耗的 AE | 赎回费 swap 的 AE 未被 recycle |
| **M-07** | 赎回费 USDX 未实际转给 feeRecipient | swap 出的 USDX 留在合约中 |

三个问题的根因相同：赎回费的整个处理流程设计有缺陷。
